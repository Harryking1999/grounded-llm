# 9.7 实验总结与初步进展

**阶段结论：已在积木任务中找到与研究问题直接对应的反例。** 模型可以正确报告棋盘，却在下一步重复移除空格；也可以执行合法动作、正确报告结果，却把原本可解的棋盘变成死局。因此，后续要检验的是：**显式状态模型能否帮助 LLM 将当前状态、动作后果与后续规划联系起来。** 当前完成的是任务筛选与反例验证，状态模型的增益尚未验证。

## 1. 我们要解决什么问题

我们希望模型在实际行动前，能在内部推演：**现在是什么状态 → 这个动作会改变什么 → 改变后还能否完成目标**；实际行动后，再利用真实反馈校准状态。显式状态模型的作用应体现在这条推演链上，而不只体现为多输出一份状态描述。

因此需要区分三种能力：**报告当前状态、预测动作后的状态、根据后果选择动作**。若模型状态报对仍选错动作，就需要进一步判断是没有检查动作前提、没有正确预测变化，还是没有识别未来的死局。只有定位失败环节，才能判断状态模型是否对症。

任务筛选据此要求：规则明确、状态和动作可核验，同时存在需要结合空间结构与动作后果才能避免的错误。**状态容易编码有利于实验实现；决策只需更新一个位置或少数开关，则不足以充分检验我们关心的能力。**

## 2. 为什么从其他尝试收敛到积木

| 已尝试或讨论的任务 | 筛选依据 | 当前取舍 |
| --- | --- | --- |
| 寻路：32 节点图、开关路径、DAG | 静态图的动态状态主要是“当前节点”；曾加入一至两位开关，但仍可用“位置＋开关列表”简洁表达。旧轮虽出现违规与绕路，尚不能据此定位复杂状态推演的缺陷。 | 保留已有结果作简单对照，退出近期主任务；Sol DAG 的表现见下表。 |
| 翻硬币 | 对此前讨论的简单版本，状态是正／反面，更新等价于翻转二值量或累计翻转次数的奇偶性。即使出错，也较难说明需要更丰富的状态模型。 | 讨论后不选作主任务，未开展本轮正式测试。 |
| 下棋：五子棋等 | 此前考虑的是逐回合“观察局面—落子—获得新局面”的 react 式交互；单看胜负，难区分状态推演、已有棋力与对手强弱。棋类还存在专门训练与规划研究，任务熟悉度会干扰解释。 | 暂缓；尚无本项目的匹配棋类实验结果。 |

这里的 react 指上述逐回合交互方式，不意味着下棋不需要规划。已有研究确实训练语言模型学习棋类状态转移与价值，并比较内部／外部搜索；但这不能证明本次 API 模型接受过五子棋专项训练，训练经历在此作为待控制因素。[棋类训练与规划先例](https://deepmind.google/research/publications/139455/)

积木同样能用二值棋盘完整表示。选择它的关键是：**给出或报对这些格子，仍不足以保证模型正确处理形状约束和未来可解性，而这样的失败已经被观察到。**

## 3. 本轮结果：任务失败与状态报告需要分开看

Sol 本轮直接接收文字规则与完整观测，一次输出完整计划；积木同时自报每步棋盘，无中途环境反馈或解题工具。三组各 16 题、每题 8 次。积木成功指全程合法并清空，DAG 成功另要求最短；pass@8 表示八次采样中至少成功一次的题数。正式设置见[实验配置](../experiments/sol_dag_blocks/configs/sol_medium.json)。

| 任务 | 单次采样成功 | pass@8 | 含非法动作的答案 | 合法前缀整棋盘报告正确 |
| --- | ---: | ---: | ---: | ---: |
| 8-block | 91/128（71.1%） | 16/16 | 10/128 | 777/802（96.9%） |
| 12-block | 69/128（53.9%） | 13/16 | 15/128 | 973/1008（96.5%） |
| DAG | 119/128（93.0%） | 16/16 | 9/128 | 不适用 |

DAG 本轮最短路为四至五步，九个失败均为非法动作，未观察到合法到达却非最短的答案。积木从 8 块到 12 块的样本成功率下降，但总体失败率本身不能定位原因。更直接的证据是：**六个非法积木答案此前具有非空且全部自报正确的合法前缀，随后仍选择非法动作。**

棋盘准确率只统计首次非法动作之前可执行的步骤，不涵盖空计划和非法后缀，也不等同于任务成功率；pass@8 只说明候选中有解，不代表模型能自行选中。以上数据来自[本轮结果与案例报告](../experiments/sol_dag_blocks/results/report.md)，逐题统计见[结果汇总](../experiments/sol_dag_blocks/results/summary.json)。

## 4. 两个反例已经把问题落到具体环节

### 反例一：动作合法、状态报对，仍将可解棋盘变成死局

`blocks12_10`，第 1 次采样、第 4 步。模型合法移除 `(4,4)、(5,4)、(5,5)`，却使 `(5,3)` 成为四周皆空的孤立格；该步自报棋盘完全正确。允许形状均为连通的三格或四格，后续只能移除、不能补格，因此这个单格再也无法移除。离线重放已验证：**该步之前仍有完整合法解，正是这一步首次把有解状态变成无解。**

![合法动作留下孤立格；右侧为从动作前状态出发的可行替代解](../experiments/sol_dag_blocks/results/figures/C4_legal_trap.png)

图从左到右展示动作前、动作后以及可清空的替代方案。会议所说的“悬空”在此准确指**不可覆盖的孤立格**，任务没有重力规则。这个案例反驳了“动作合法且状态报对，就足以保证后续规划可靠”；由于孤立格通过局部检查即可发现，它尚不能证明失败需要深层搜索才能避免。

### 反例二：已报告某格为空，下一步仍选择覆盖它的完整形状

`blocks8_00`，第 6 次采样。第 2 步已移除 `(4,6)`，模型随后自报棋盘也明确将其记为空；第 3 步仍选择横向三格 `(4,4)、(4,5)、(4,6)`。三格中只有两格仍被占用，违反“必须完整匹配并移除形状”的规则，裁判拒绝执行。

![正确报告棋盘后，下一步仍试图重复移除空格](../experiments/sol_dag_blocks/results/figures/C2_repeated_removal.png)

图中红叉标出被重复使用的空格。这对应会议所说的“未完整抠除”，可核验事实是**形状没有完整落在当前占用格上**，并非裁判实际执行了部分移除，也不能据此推断模型“偷懒”。它把问题定位到：正确的状态报告没有保证下一步满足动作前提。

两例坐标均从零开始，参考解仅供离线核验，未提供给模型。它们是对“状态报告正确足以保证可靠决策”的具体反例；是否能由显式状态模型修复，还需要干预对照。

## 5. 其他失败与下一步

12-block 的 `blocks12_05、09、13` 均为 0/8，24 次中有 **21 次空动作序列、3 次非法答案**。空计划说明没有交付解；它不等于 API 完全没有最终文本，也不等于没有思考。已有推理 token 用量，但内部推理文本不可见，暂不能区分搜索失败、停止策略或输出协议负担。另观察到 S/Z 四格在输出中的占比低于构造输入；合法分解不唯一，该现象不能直接说明模型识别不出复杂形状。[完整失败与形状统计](../experiments/sol_dag_blocks/results/report.md)

**目前已完成“明确问题—筛选任务—验证适用反例”。** 下一步先在固定棋盘上分别测试动作合法性、单步后继状态和死局判断，定位失败环节；再比较简单的显式记录／检查与拟议状态模型，匹配规则、信息、采样和推理预算。空计划另用输出协议对照诊断。若简单检查已能消除上述错误，应先确认这一更简单的解释，再判断学习状态模型能否带来额外增益。以上为后续研究建议，尚未启动。

> **30 秒口头版：** 我们研究显式状态模型能否帮助大模型推演动作后果。寻路和翻硬币状态过于简单；此前棋类方案侧重逐回合反应，又受训练经验和棋力干扰，因此聚焦积木。已有反例：模型棋盘报对仍选非法动作，或合法移除后留下无解孤立格。现在已找到符合研究场景的问题，下一步定位失败环节，再验证状态模型是否有效。
