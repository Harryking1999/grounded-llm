## 1. 项目问题、信息条件与指标

研究问题：显式状态地图能否改善 LLM 的状态关系判断、动作选择和完整任务完成，以及这种读取能力能否迁移到新目标、新底图、新人数和未训练任务类别。

地图 Q 是状态编码器输出的向量；attention 中的 Q 则指查询向量 Query，两者分别在地图距离和注意力计算中使用。当前主要方法分别编码当前状态、目标及全部合法动作后继，用固定距离和候选排序训练地图；LLM 通过可训练接口读取冻结地图。地图按任务、底图或人数独立训练。

本文的 SFT 指用标准回答做监督微调；ID 指任务规则和输入条件属于训练分布的留出题，OOD 指改变目标、底图、人数或任务类别的题。B 表示模型参数量的十亿单位；训练数据的50k表示50000条轨迹，检查点的50k表示50000次优化器更新。epoch／轮表示遍历一次训练集，动作步数表示环境中的实际执行次数。比例写作0–1或百分数时含义相同；“已评／计划”是评测覆盖数，“成功／题数”才是完成成绩。

| 条件 | 实际提供的信息／训练范围 |
|---|---|
| 当前地图贪心 | 环境提供真实当前状态与全部合法后继；按地图成本选动作；精确状态相等时停止 |
| 地图 LLM | 任务文字、真实状态、合法候选和环境反馈，加当前／目标／候选地图向量；输出排序、理由、动作或停止 |
| SFT 文字基线 | 有相同任务文字及逐轮环境更新，无真实地图；主干全参数训练 |
| 强文字 API 基线 | 一次输出完整计划，无工具、无中途执行反馈；预算通常包含思考与最终答案 |
| 精确教师 | 产生距离、可达性、参考解与裁判标签；推理时不替地图或 LLM 搜索选动作 |
| 目标坐标变换 | 积木异或、魔方群相对坐标和逆对称、8-Puzzle 对称及数字重命名使用已知任务结构 |

| 指标 | 定义与分母 |
|---|---|
| 到达／完成 | 曾达到精确目标；地图或一次完整计划按环境真实执行计分 |
| 正确完成／到达且停止 | 到达目标，并由 LLM 输出有效的正确停止标签 |
| 最优到达／最优完成 | 到达目标且动作成本等于精确最优／另要求正确停止；失败题仍在分母中 |
| RO／自主执行 | 使用模型自己的动作和历史连续执行，包含错误累积 |
| TF／参考状态 | 给定参考历史逐步作答；单步正确率不等于整题完成率 |
| safe／保持可达 | 动作后仍存在到目标的解；仅在动作前可解状态上统计 |
| 一步最优 | 所选动作满足精确最短成本关系，允许并列最优 |
| 跟图率 | 所选动作为地图预测成本最小的候选之一；过桥另加即时耗时 |
| NDCG | 输出候选排序与参考排序的吻合程度；位置增益和距离增益分别报告，各历史协议不混算 |
| 距离 MAE | 地图预测与精确成本的平均绝对误差；不可达标签与有限距离分开 |
| pass@k | 同一实例k次中至少一次成功的实例比例；pass@1为单次成功率，pass@8／@16分别用8／16次采样 |
| 预算分 | 按实际输出 token 扣除超限答案；“原执行”保留真实执行结果，不表示无限预算 |

所有比较保留其原题集、目标、交互方式、数据量和训练预算。地图组通常还增加排序监督，不能把组间差值直接归为地图单一因素。固定监测集参与过开发／选模；单种子、小样本和独立验收结果分别解释。


### 1.1 Qmap：状态编码、距离、候选排序

基本数据流为：物理状态编码 → 状态网络 → 128维Q；同一任务的当前、目标和每个合法后继共用一套权重，任务之间独立训练。距离读出比较后继Q和目标Q，选预测总成本最小的动作。Qmap训练与LLM训练分开，LLM阶段固定Qmap权重。MLP是逐状态的多层全连接网络，CNN是利用棋盘局部邻接的卷积网络，ReLU／GELU是非线性激活；独热编码以一个位置为1、其余为0表示离散身份。

| 层次 | 实际设计 |
|---|---|
| 基础状态网络 | 输入线性层 → ReLU → 隐藏线性层 → ReLU → 128维输出；默认sigmoid乘任务cap，使每维在0至cap之间；linear仅乘尺度，softsign为另一种有界输出；另比较CNN |
| 距离监督 | 状态对的预测距离与精确最短成本做Huber损失：小误差用平方、大误差用线性；不可达关系另赋有限代理标签，如积木19 |
| 排序监督 | 同一父状态、同一目标下，全部合法候选同时比较；精确总成本经softmax(-成本/温度)形成目标概率，与预测概率做交叉熵；温度控制概率集中程度 |
| 仅最优动作排序变体 | 在全部并列精确最优候选上均分目标概率；用于六人过桥等比较 |
| 转移差值变体 | 监督预测父成本减后继成本，匹配精确剩余成本变化；与原距离和排序共同训练 |
| 贪心选择 | argmin_a［即时动作成本c(s,a)＋D(Q(T(s,a)),Q(g))］；单位动作成本相同时等价于比较后继距离 |
| 终止 | 地图贪心按完整状态相等结束；LLM生成停止标签，单独计正确完成 |

上式s为当前状态，g为目标，a为合法动作，T(s,a)为环境产生的真实后继，c(s,a)为即时成本，D为固定的向量距离函数。单位成本任务每次加1；过桥加本次同行者的最大耗时。

基础读出记Δ=Q(s)−Q(g)，d为Q维数。当前代码中的距离包括：L∞=max|Δ|；有向最大差值=max(0,maxΔ)；有向和差=Σmax(Δ,0)/√d；名为L1的读出为Σ|Δ|/(2√d)；L2=√ΣΔ²。有向距离交换起终点后可改变；分组L1在组内求绝对差之和，再取最大组。以下L1成绩沿用该缩放定义。

目标坐标变换由目标g确定；当前、目标及所有后继都使用同一个变换，再计算Q。合法动作仍由原物理状态产生。这样，目标相对表示与动作规则保持对应。

| 任务／重要地图条件 | 输入与编码 | 隐藏宽度／输出 | 读出或结构 |
|---|---|---|---|
| 积木 | 100格占用；非空目标可统一变换为S⊕G，目标为零，全部后继一起变换 | 256／128维 | 有向和差；原cap13，不可达代理19；复用原权重 |

### 1.2 早期地图与接口架构

H为语言模型的隐藏宽度，D为该历史地图的向量维数；连续token指将状态向量投影为与文字token同宽的输入特征。

| 路线 | 表示与信息流 | 训练对象 |
|---|---|---|
| 固定图Q/V | 为节点存Q、为有向边动作存V；拟合Q(s′)≈Q(s)+V(a)，地图逐图训练 | 局部规则更新后继Q和V；对照完整梯度同时更新前态、后态及V |
| 积木共享动作V | 一张初始棋盘内按完整残余状态存Q；同形状／坐标动作共享V | 只用转移MSE；后续另实现δ=MLP［Q(s),动作embedding］ |
| 连续状态token | Q或完整棋盘 → Linear／两层MLP → LLM输入embedding；当前和目标各一个token | 冻结LLM，先训状态报告；图MLP为D→1024→H，中间GELU |
| 显式候选距离 | 每个候选提供‖Q(s)+V(a)−Q(g)‖₂标量，文字中逐步选动作 | 地图已训练，LLM不额外训练 |
| 早期地址K／状态V | 角色与候选编号embedding组成K；Q的线性投影组成V；LLM隐状态组成Query | 冻结主干或全参，分组比较 |
| 融合FFN | 拼接地图Q、角色、编号，经MLP形成共同特征，再分别投影K和V | 融合FFN和cross-attention；旧运行主干冻结 |
| 内容残差MLP | 对地图投影增加两层GELU残差MLP，角色／编号仍用于地址K | 用于10k诊断及后续MLP＋重编号条件 |
| 新contextual encoder | 先用4层双向Transformer处理地图槽位，再由LLM cross-attention读取 | A–H八组比较交互组织、K来源和主干训练范围 |

### 1.3 Self-attention：地图槽位如何交互

一个时间步有N个合法动作，地图输入为N+2个槽位：当前、目标、候选1…候选N。每槽128维Q投影到256维，拼接32维角色embedding和32维候选编号embedding，再线性投影为256维输入特征。embedding是可训练的身份向量；角色区分当前／目标／后继，编号将后继与文字动作菜单对应。当前与目标的候选编号为0，真实候选为1…N。

| 项目 | 共同encoder | 配对encoder |
|---|---|---|
| 输入分组 | ［当前,目标,候选1,…,候选N］ | 一个［当前,目标］，加N个［当前,目标,候选i］ |
| self-attention可见范围 | 同时间步全部有效槽位双向可见 | 每个二元组／三元组内双向可见 |
| 候选间交互 | 可直接比较其他候选 | 每个候选只直接接触当前与目标 |
| 保留输出 | 所有槽位输出 | 二元组保留当前／目标输出；每个三元组只保留该候选输出 |
| 参数共享 | 所有槽位用同一encoder | 全部二元组／三元组共享同一encoder |
| 每层有效槽位／注意力分数个数 | N+2／(N+2)² | 3N+2／9N+4；不含补齐位置和线性投影计算 |

每层先做LayerNorm特征归一化，再做4头self-attention并加回输入；随后再次归一化，经256→512→256的GELU前馈网络FFN，再加回输入。共4层，最后LayerNorm。这就是pre-LayerNorm与残差结构。为批处理补齐的padding空槽由mask屏蔽。地图encoder处理同一步快照，语言模型自己的self-attention仍只看已出现的文字历史。

### 1.4 Cross-attention：LLM如何读地图

记地图encoder输出为h_i，地址特征a_i=［角色embedding,编号embedding］，某语言层隐状态为x_t，LN表示LayerNorm，W表示可训练线性投影。两种模式的Query均为Wq·LN(x_t)。每头先计算softmax(Query·Kᵀ/√64)，得到各地图槽位的权重，再加权求和V；4头、每头64维，合并为256维读取向量read，最后由Wout投影回语言宽度H。K决定读取哪个槽，V提供读出的内容。

| 模式 | K来源 | V来源 | 实际读取依据 |
|---|---|---|---|
| 内容K/V | Wk·LN(h_i) | Wv·h_i | 语言Query与编码后地图内容匹配 |
| 地址K、内容V | Wk·LN(a_i) | Wv·h_i | 语言Query与角色／候选编号匹配，取出对应地图内容 |

每个地图快照只做一次encoder，结果供28个语言层共享；每个语言层拥有独立Q/K/V、输出投影和标量门控。读取结果以x′=x+tanh(gate)·Wout(read)加入残差，再进入该语言decoder层；gate从零初始化。旧稀疏接入实验将28处改为14处、7处或最后3处。

| 训练范围 | Qmap | 地图投影、地址embedding、encoder、cross-attention与门控 | 语言主干 |
|---|---|---|---|
| 全参组A–D | 冻结 | 训练 | 训练 |
| 冻结组E–H | 冻结 | 训练 | 冻结，梯度经过主干传回接口 |

每个文字token只读取所属时间步的地图快照；语言历史仍可见，未来地图不可见。候选重编号同步作用于动作菜单、向量和监督标签。训练时排序本身由模型预测并计算损失，后面的动作token可见前序标准排序；推理时先生成排序，再生成理由与动作。八组A–H的完整对应关系见第11节。

### 1.5 数据选取、监督和留出

BFS按边数逐层求单位成本最短路，Dijkstra用于过桥等非等权边；BDD以二元决策图压缩表示积木状态集合；DAG指没有有向环的状态图。下列数据池大小表示可供抽样的范围，实际训练曝光量另计。Qmap的关系留出与LLM的轨迹留出分别划分。Flan4／5／6是本项目的多任务训练组合名称，数字为训练任务大类数。

| 数据阶段 | 选取及标签生成 |
|---|---|
| Qmap基础数据 | BFS求单位成本距离，过桥用Dijkstra；保留全部合法动作，包括回边、死路和需要先让路的动作 |
| Qmap广域覆盖 | 按状态对、目标、精确距离层和场景抽样；一步边、完整候选分叉与路径关系共同进入监督 |
| 训练失败补充 | 从训练查询执行中取循环、不可达分叉、上游错误及最优后续；部分接续加入脆弱正确分叉保持池、完整走位至推动路径 |
| 留出保护 | 保护父状态到目标及所有候选到目标关系；未见输入、未见目标、未见布局和新图分别设题 |
| 积木精确图 | 连通分量完整BFS／BDD表示合法状态；差集最小覆盖提供任意状态对标签；训练实际抽样，另记曝光 |
| 魔方 | 枚举3674160个状态及六动作；按精确深度、目标族抽样；共同轴对称和逆对称条件分别记录 |
| 移车 | 1000独立车辆配置组；原题最短1–10／11–20／21–30／31以上各取250组；同配置分量保持在同一布局划分 |
| 棋子交换 | 每树3628800种排列的精确教师；独立保护关系、未见起点和两端未见 |
| 21／24点 | 全部210组互异四数来源；展开精确有理数DAG；按源元素数、目标类型和可达性配额取完整候选 |

| 新encoder数据 | 优先保留原5类起终点；新地图重新认证完整最短轨迹；补题匹配任务、小类、精确成本；A–H共享同一份新数据 |

| 监督与优化 | 重要设置 |
|---|---|
| 地图Q训练 | 关系Huber＋完整候选排序交叉熵；针对性变体仍按各自原预算比较 |

CE为交叉熵：提高标准输出token的预测概率。当前NDCG只比较合法后继，不含当前槽；位置增益为固定Qmap参考排序位置的倒数1/r，距离增益为(d_max−d)/(d_max−d_min)，d为候选地图成本，距离全相等时均记1。按输出位置使用1/log₂(i+1)折扣，再除以理想排序得分；@1看首位，@10看前10位，并列取平均、缺失计零。早期FFN使用过其他增益定义，单独保留原指标。

工程等价性比较：积木采样125批315.42→132.41秒，整数内核25批34.43→9.10秒，样本与随机进度一致；六人过桥同步／异步保存400更新109.92／73.62秒，权重与完整恢复状态一致。冻结主干组由双卡改为单卡时仍保持有效batch4。
