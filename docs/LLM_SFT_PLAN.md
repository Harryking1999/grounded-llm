# 1.5B 整题 CoT SFT 基线方案

本文件记录方案决议与待讨论的设计选项，不是正式运行合同。研究进度统一维护在[项目状态页](PROJECT_STATUS_AND_TODO.md)。当前授权范围是设计与逐项确认，尚未开始数据生成、训练或远端运行。

## 1. 问题与已确认范围

希望比较：面对寻路与积木任务，直接对小型 LLM 做任务监督微调，能否达到或超过“冻结 LLM＋认知地图＋可训练 cross-attention 接口”的任务表现。

2026-10-11 对话中已确认：

- 基座沿用 Qwen2.5-1.5B-Instruct；训练 LLM，去掉学习得到的地图和读取接口。具体参数更新范围尚待确认。
- 寻路与积木都做，不缩减为单个任务。
- 整题输入，一次生成 CoT 与完整计划；生成期间不接收环境逐步反馈。寻路的图结构属于题目信息，不属于被去掉的认知地图。
- 监督数据采用求解器生成，每道题采样多种合法、可到达目标的路径。不同路径的数量、长度和采样分布尚未确定。
- CoT 的具体内容保留为待选择、待讨论事项，不能默认采用状态轨迹或完整搜索过程中的任一种。

已有 cross-attention 条件也使用 SFT，只是训练接口、冻结 LLM。新方案还改变了交互方式及监督内容，因此首先是完整方案对照，不能将结果差异单独解释为地图收益或解冻 LLM 的收益。

## 2. 求解器与多路径数据

求解器根据真实规则枚举动作、计算状态转移并搜索解；它用于制作训练数据。测试时 LLM 独立生成整题答案，裁判在生成结束后验证计划，求解器不参与模型的在线行动选择。

寻路的不同解对应不同节点序列；积木的不同解可以对应不同移除顺序或形状组合。每条解都需要逐步合法，最终精确满足目标。搜索达到时间或节点预算上限只能记为未求解，不能标成无解。

以下仍是讨论项，不视为用户已确认：

- 仅采样最短解，还是包含有界长度的次优可达解；若包含，如何控制长度分布。
- 每道题的路径数量、物理动作序列去重及样本权重，避免容易采到多条解的题占据过大权重。
- 寻路是否限制为不重复节点的简单路径；积木如何区分仅交换独立动作顺序与不同分解方案。
- 采用何种搜索算法、随机化方式及计算预算；已有裁判和搜索实现能复用到什么程度。

## 3. CoT 监督内容：待选择讨论

**两种候选方案均未获选。不因状态轨迹较容易实现就自动采用，也不默认全部运行。**

| 候选 | 监督答案内容 | 能教给模型什么 | 代价与边界 |
|---|---|---|---|
| A：状态—动作轨迹 | 当前状态 → 动作 → 后继状态，最后汇总完整计划 | 沿一条成功解逐步维护状态、推演动作后果 | 容易从已验证路径生成；没有显式监督如何发现这条解、为何排除其他分支；中间状态会增加输出长度 |
| B：完整搜索过程 | 候选展开、分支探索、失败排除、回溯等实际搜索记录，最后输出完整计划 | 求解器如何找到解，包括未选中的探索分支 | 搜索记录可能远长于最终计划；需要定义记录粒度、搜索次序与长度处理，不能虚构搜索过程 |

待讨论的核心问题是：首轮主要让 LLM 学习成功解的状态推演，还是学习发现解的搜索程序。多路径采样与这一选择是两件事：同一道题有多条成功路径，并不意味着已经包含搜索过程监督。

无论选择哪种格式，推理时中间内容都由 LLM 自行生成。若记录状态、转移或分支判断，应由相应的真实环境或搜索记录支持；不能把仅核对终局视为已验证全部 CoT。

## 4. 后续逐项确认

1. CoT 采用第 3 节哪种格式，两个任务是否使用相同类型。
2. 多路径采样的长度范围、每题数量、去重和权重。
3. 数据与划分：建议复用已有物理任务及留出边界，先按物理任务划分，再生成多条解；不能将同题不同路径分入训练与测试。是否分别训练两个任务的模型也待确认。
4. 提示和终止类别：整题输入提供哪些信息，完整计划如何表达，初始即目标与无解题如何构造。
5. 训练方式与预算：全参数或参数高效微调、损失、学习率、长度上限、训练量和模型选择规则。不直接照搬接口训练超参数。
6. 评测与比较：建议主要报告合法完整到达率，另报最短性、非法动作、截断及中间状态错误；具体题集、生成预算与解码方式待确认。未微调的同基座整题条件可作为直接训练收益参照，是否加入另行确认。

原积木的失败上下文只监督“在这段历史之后，无合法动作且未达标”。它不能直接改写为原始整题无解：原题可能有解，只是该轨迹已走入死局。新条件的负例语义需要单独确定。

实现上优先复用现有 SFT 基础设施、环境规则和裁判，但整题样本、监督 mask 与评测输入需按新协议调整；不是仅修改参数冻结范围和地图开关。方案确认后再形成机器可读合同和实现。

## 5. 方法依据

- [Searchformer / Beyond A*: Better Planning with Transformers via Search Dynamics Bootstrapping](https://arxiv.org/html/2402.14083v2)，§3：用 A* 实际搜索记录与最终计划构造监督，在迷宫和 Sokoban 中比较只输出计划与搜索过程加计划。其模型从头训练，不是本项目 Qwen 微调效果的直接证据。
- [A Close Look At World Model Recovery in Supervised Fine-Tuned LLM Planners](https://arxiv.org/html/2606.03685v1)，§3.2、表 1：研究在动作之间插入中间状态的 State-CoT；在其 BlocksWorld 和 Logistics 条件下收益不稳定，不能预设显式输出状态一定改善规划。其 BlocksWorld 与本项目积木消除规则不同。
- [SCoTD](https://arxiv.org/html/2306.14050)与[DeepSeek-R1 蒸馏](https://arxiv.org/html/2501.12948v1)：教师模型生成推理示范后训练小模型的另一类路线。本轮已选择求解器，不将大模型生成 CoT 列为默认数据来源。
