# 研究简述：语义模型与状态认知

**核心问题：给已有语言能力的模型接入显式状态认知，能否改善状态理解、动作判断与规划？**

本页维护研究定义；进度见[项目状态页](PROJECT_STATUS_AND_TODO.md)，当前执行方案见 [Step 2 runbook](../experiments/cml_map_scaling/STEP2_RUNBOOK.md)，文献依据见 [Related Work](../RELATED_WORK.md)。

## 动机

已有纯语言基线出现状态报告错误，也出现报告正确却选择非法动作、合法动作导致死局和提前停止。它们提示状态读取、保持和使用可能是不同瓶颈，不能把所有失败都归为“忘记状态”。

GCML 提供了从动作转移学习地图、利用目标方向生成轨迹的参考。汉诺塔预印本则发现：模型在输入末尾已有可解码的状态表示，长生成中表示会退化，借助外部状态跟踪重新注入表征可以改善部分结果。这使“如何让状态持续可用”成为一个具体研究问题。

## 能力与信息条件

分别考察观测解析、当前状态估计与维护、动作条件下的转移预测、目标判断、未来规划和动作表达。某项改善是否传递到下一项，由实验回答。

状态既可以是环境真值，也可以是根据观测和历史估计的表示。文字输入可以完整编码状态；若观测本身不足以确定状态，应表达不确定性或获取信息，而不是将信息不足归因于推理失败。

更新当前状态与更新网络参数是两回事。冻结 LLM 参数仍允许梯度经过 LLM 传给状态接口；推理时是否在线学习参数另行设计。

## 当前图任务

每张固定图独立学习 Q/V：状态向量与动作位移共同拟合一步转移。转移准确不保证图距离或规划有效，因此 Step 1 分别检验转移、表示几何和简单动作读出。

Step 2 冻结地图和 Qwen3-4B-Instruct-2507，只训练输入层的 Linear／MLP 接口报告当前与目标节点。提供相同文字图结构，以准确文字状态作对照，训练后测一步动作选择与几何变化。多 token、打乱编号和少量动作监督留作后续解决方案。

程序拥有当前状态；动作执行后读取真实后继节点的 Q。首轮不使用 V 累加想象，也不评估 LLM 自主状态维护。固定图上未见起终点组合的表现，与未见节点、未见图拓扑的泛化分别定义。

## 积木与后续交互

积木使用完整二值棋盘和固定规则：`Q=I`，动作对应确定的状态差分。它用于检验冻结 LLM 能否使用状态接口，不学习积木动力学。保留的[试点设计](../experiments/state_interface_pilot/README.md)采用状态／关系报告适配，再评估规划；当前优先级低于图任务。

长期希望实现：

```text
真实观测 → 更新状态认知 → 想象候选动作及后果
         → 选择实际动作 → 环境执行 → 新观测
```

真实行动后的反馈与行动前的假想转移需要区分。若在尚未执行时调用精确环境转移、合法动作表或搜索器，应作为额外工具条件。文字状态对照获得同样的更新与反馈。

状态轨迹可以顺序推进，也可以扩展分支与回溯。输入层 state token 是当前接口；外部 memory／cross-attention、动态连续提示／LoRA 保留为后续候选，有具体读取瓶颈后再比较。

## 如何判断研究主张

- 用匹配的图、状态、提示、预算和反馈比较连续接口与文字状态。
- 同时报告状态／转移准确率、非法动作率、目标判断及任务成功率；保留负结果与截断样本。
- 状态可解码、几何关系存在、模型实际利用这些信息是三种证据；通过状态或目标干预检验使用情况。
- 若简单文字状态即可消除失败，应缩小显式地图的增益主张；若只在训练构型有效，不支持跨任务泛化。
- 冷门任务不等于预训练未见。更长思考、更大模型和额外搜索带来的收益，也不能直接归因于状态建模。

## 长期目标

探索共享模型如何跨任务表示和更新状态，如何利用新观测校准内部预测，以及较小 LLM 能否借助状态认知改善规划。积木与图任务分别成功仍只是单任务证据；跨任务共享、在线学习与多分支想象需要后续独立实验。
