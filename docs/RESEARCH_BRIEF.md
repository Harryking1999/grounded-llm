# 研究简述：LLM 能否读懂并利用状态地图

**核心问题：在相同任务监督下，接入显式状态地图能否改善动作判断与连续任务完成？**

当前决策见 [状态页](PROJECT_STATUS_AND_TODO.md)，现行对照见 [同数据多基线](../experiments/map_sft_baselines/DESIGN.md)。既有地图接口与独立 SFT 结果保留在各自实验目录。

## 假设与信息条件

地图提供当前状态、目标和各合法动作后继的关系，可训练 cross-attention 将这些关系交给 LLM。主干冻结与全参训练是两种需要比较的条件，不预先认定地图组应当更好。

环境每轮提供真实当前状态、全部合法候选和执行反馈。积木的候选后继也由环境算出，地图编码这些后继；因此本阶段直接检验关系读取与动作选择，尚未独立检验自主感知、状态维护、转移学习或内部搜索。

```text
当前状态、目标、真实历史、全部合法候选
  ├─文字输入 → LLM
  └─冻结 Q 的状态向量 → 可训练读取接口 → LLM
LLM 输出依据、地图排序（有图时）和动作
  → 环境执行并更新 → 下一轮
```

## 必须区分的证据

| 问题 | 所需比较 |
|---|---|
| 同一状态下判断是否改善 | 共用参考状态、候选编号与输入历史的自由作答 |
| 能否连续完成 | 使用模型自身历史执行的完整 rollout |
| 是否读取地图内容 | 同模型、同文本和地址的地图内容干预 |
| 地图方案是否有额外收益 | 共同数据、预算、架构与训练范围下的匹配基线 |

有地图时同时监督排序，相关差值衡量地图＋排序监督整体作用，不能单独归因于地图向量。内容干预证明使用与否，不替代匹配训练的增益比较。

## 什么会改变判断

- 匹配无地图组同样好，应缩小显式地图额外收益的主张。
- 参考状态表现好但自主 rollout 弱，需要定位自身轨迹上的首次错误和累积效应。
- 更少数据达到同等水平可以支持数据效率研究，但须计入地图训练数据与成本。
- 固定监测集已参与训练决策，其峰值不作为独立泛化证据。地图训练和接口训练的曝光范围分别核对；新初始棋盘也不保证中间状态未见。

历史任务、监督与参数范围不同的结果不能直接归因于架构。相关来源见 [Related Work](../RELATED_WORK.md)与 [GCML Tasks](GCML_TASKS.md)。

当前先按任务整理与训练。环境规则各不相同，但模型都需要识别目标和候选后继，读取它们与目标的距离关系，再把选择对应到正确动作。各任务采用自己的规则外壳、输入编码和地图，保持 Q 的 MLP、距离监督、候选排序和读取接口方法对齐；汉诺塔、魔方、寻路与积木的训练流程分别维护。

近期先统一文字、确定难度，比较地图全参、7B 全参、Qwen3-32B 与 GPT-6.1-sol high。地图组／CoT 组逐轮获得环境更新；用户已确定积木 SOTA／32B 采用一次完整剩余计划、无中途反馈的 JSON 条件，交互差异随结果注明。规则与输出文字见[集中总览](../TASK_TEXTS.md)。

当前任务筛选的最低要求是 32B 不能可靠完成。用户已接受最初的五任务配置，停止为难住 GPT 继续加难；GPT 保留为强基线，同时观察成功率与最优解率。32B 失败说明当前任务对该基线仍有难度，不构成地图必然有效的证据；额外收益仍需匹配比较。

单任务条件稳定后，再按蓝图探索多任务地图全参联合 SFT，评测已训练任务 OOD 与提供地图的未见任务迁移；当前优先级以[状态页](PROJECT_STATUS_AND_TODO.md)为准，历史会议内容保留原语境。
