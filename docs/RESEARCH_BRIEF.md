# 研究简述：语义模型与状态认知

状态：初步构想

更新时间：2026-09-02

## 问题与动机

LLM 已经具有相当的智能，但我们认为，基于 token 的语言能力无法代表人类总体的智慧。

当前观察和研究判断是：仅靠语言能力，LLM 不能正确、稳定地感知自己所处的状态。在语言推理过程中，它可能遗忘自己已经走到哪里，因而无法真实把握当前状态，并进一步影响正确推理和泛化。

需要设计具有可建模状态的反例任务来检验这一判断。下棋、搭积木等是目前提出的候选任务；具体任务和规则仍需继续设计。

## 核心设想

通过一个新网络引入状态知识，使模型能够知道自身所处的状态。老师提出的核心问题是：

> 有语义的模型加上状态认知，是不是比只有语义的模型更好？

例如，GPT 在思考时可能不知道自己已经走到哪里；加入这个模块后，一个很小的模型是否可能在相关问题上比 LLM 更聪明。

该网络需要在模型内部结合状态认知，因此与从外部检索信息的 RAG 不同。它还需要能够在聊天／交互过程中学习。

## 当前网络构想

模型需要编码观测、状态和动作，建立联合表征：把观测映射到一个空间中，也把动作的影响映射到同一个空间中。当前用 `Q` 和 `V` 表示这两个映射：

$$
Q o_{t+1}=Q o_t+V a_t
$$

其中，`o_t` 是时刻 `t` 的观测，`a_t` 是动作；`Q o_t` 表示观测在该空间中的表示，`V a_t` 表示动作在同一空间中造成的变化。

训练误差直接由等式的偏差给出：

$$
e_t=Q o_{t+1}-(Q o_t+V a_t)
$$

当前设想是用 `e_t` 直接更新网络。直观上，如果动作造成的位移预测少了一部分，就用这部分位移误差直接补回去。

## 状态表示与跨任务泛化

最难的问题预计是状态表示。目标不是为每个任务建立一个独立状态模型，而是只用一个共享模型，表示不同任务中的各种状态。

这些任务都希望能够被抽象成某种“地图”；不同任务的上下文和语言表述不同，但共享模型应学习可迁移的状态结构。为了达到这一目标，需要在多个任务上联合训练。

## 目标

- 检验加入状态认知后，模型是否比只有语义能力时更强；
- 让模型在多个具有可建模状态的问题上超过 GPT；
- 探索 **grounded language is better than token language**；
- 研究一个很小的状态网络能否使较小模型表现出超过纯语言 LLM 的智能；
- 使同一个状态模型能够跨任务表示和更新状态，并在交互过程中继续学习。

以上目前是研究目标和机制构想，不是已经得到的实验结论。

## 当前尚未定义清楚的问题

1. `Q`、`V` 的具体网络形式、维度和更新规则是什么？
2. “状态”在联合空间中如何表示，如何判断同一个模型确实学到了不同任务的状态？
3. 状态网络如何与 LLM 的内部计算结合？
4. 聊天／交互过程中的在线学习具体更新哪些参数？
5. 哪些反例任务能够清楚证明纯语言推理没有真实感知当前状态？
6. 如何从单任务实验推进到一个模型上的多任务联合训练与泛化？
