# 研究简述：LLM 能否读懂并利用状态地图

**核心问题：显式状态地图能否为LLM提供可复用的状态关系，使它更容易学会任务，并迁移到新目标、新任务？**

研究从已有任务上的效果出发，进一步检验通用读取能力。当前配置从[多任务实验入口](../experiments/map_sft_baselines/README.md#当前比较)进入，进度与安排只维护在[项目状态](PROJECT_STATUS_AND_TODO.md)；[旧积木设计](../experiments/map_sft_baselines/DESIGN.md)保留历史对照依据。

## 研究逻辑

1. **先让地图表达有用的关系。** 对当前状态、目标和合法后继进行编码，用距离和候选排序检验它们能否支持连续求解。各任务可以使用不同状态编码和独立Qmap，共用关系表示与读取方法。
2. **让LLM学会使用这些关系。** 联合训练将地图向量、任务文字和动作编号对应起来，观察任务成功率、学习速度以及到达后的停止判断。稀疏注意力比较的是地图接入方式与成本。
3. **通过多任务检验复用。** 扩大类别并加入类内子任务，让同一LLM接触不同规则和目标要求，再评估未训练目标及未训练类别。新类别可以提供该任务已训练好的地图；需要迁移的是LLM的读取和决策能力。

这三步构成同一主线：地图提供关系，LLM利用关系，多任务训练检验这种利用能否迁移。扩充兼顾不同难度；容易但结构不同、地图可靠的任务也有价值。本轮使用八类任务池：积木、二阶魔方、8-Puzzle、寻路、移车出库、棋子交换、过桥和21／24点；推箱子搁置。过桥提供带成本的调度，24点提供运算状态与分支选择。

本轮按“任务大类 → 类内小类 → 具体题目”组织。大类按共同规则和背景定义，小类改变目标、人数或底图。正式范围和留出清单由[配置](../experiments/map_sft_baselines/configs/flan_generalization_50k.json)维护：4类训练积木、魔方、寻路、过桥；5类加8-Puzzle；6类再加棋子交换。每档各50,000条物理轨迹，按大类均分，三种模型共享同批题目；各档从基座独立训练，不能把4→5→6解释为同一模型逐步续训。

每个训练大类保留一个类内小OOD，未训练的大类作为整类OOD。移车、21／24点始终整类留出；棋子交换在4／5类档整类留出，在6类档训练原树、留出另一树。积木训练8块清空、12块构造盘清空及8块非空目标，留出12块非空目标；反向放置推迟。新图和新人数可以提供独立训练的Qmap，这检验LLM读取迁移，不声称Qmap自身跨规则泛化。

脑区分工是研究动机，不是实验已证明的机制。待检验现象是：同批轨迹和相同既定训练时程下，1.5B＋冻结地图在类内及整类OOD上优于文字3B／7B，并与zero-shot DeepSeek V4 Flash比较。当前地图编码器主要为小型MLP，常用两层隐藏层，并非都只有一层；训练与参数开销须单列。原训练配置是全参数SFT，实验检验的是以后换任务地图时能否免去LLM重训，不能说当前LLM只训练了读取接口。

同物理轨迹数量不等于信息量、监督token或总计算量相等：地图组还有独立训练的Qmap和排序监督。比较结果首先归于这套整体条件，地图成本与读取机制另报告。ID验证用于原停止规则；类内及整类OOD只做终点评测，不参与早停或选模。

## 假设与信息条件

当前地图提供当前状态、目标和合法动作后继的关系，可训练cross-attention将它们交给LLM。各任务地图独立训练，同一个LLM读取。

环境每轮提供真实当前状态、全部合法候选后继和执行反馈。现阶段直接检验关系读取、目标判断、动作选择与连续完成；自主感知、状态维护和转移学习另需对应条件。

```text
任务规则、当前状态、目标、真实历史、合法候选 → LLM文字输入
当前状态、目标、合法后继 → 冻结Qmap → 地图读取接口
LLM输出排序（有图时）、依据与动作／停止
  → 环境执行并更新 → 下一轮
```

24点的状态是剩余有理数，完整动作包含操作数与运算符选择。它可作为通向运算任务的一个具体入口；推广到其他数学问题时，先明确状态需要保留什么、动作如何改变状态、目标如何判定。

## 研究问题与对应实验

| 要回答的问题 | 对应比较 |
|---|---|
| 地图本身是否可用 | 冻结Q的关系质量与同题完整贪心执行 |
| LLM是否真正使用地图 | 同模型、同文本和候选地址下的地图内容干预 |
| 已训练任务是否受益 | 匹配数据与预算的有图／无图对照，分别报告到达与正确停止 |
| 是否更快学会 | 连续完整评测节点的曲线，分开更新次数、实际耗时与地图训练成本 |
| 类内目标泛化如何 | 保留任务规则，留出目标要求或子任务，明确地图与LLM各自的曝光 |
| 新类别迁移如何 | LLM训练中留出完整任务类别，评估提供对应地图后的执行 |
| 多任务训练是否改善迁移 | 在相同留出题集上比较联合训练前后或匹配的单任务／多任务模型 |

因此，“比文字3B好”“训练内更快学会”“换目标仍会做”“能迁移到新类别”分别回答不同问题。已有训练内正信号与目标泛化缺口共同决定下一步如何组织任务。

## 什么会改变判断

- 匹配无地图组同样好，应缩小显式地图额外收益的主张。
- 地图关系可靠而LLM换目标后仍沿用旧目标策略，应检查目标读取、训练目标覆盖和停止判断；地图本身关系弱时先定位地图问题。
- 参考状态表现好但自主执行弱，应检查首次错误及轨迹累积效应。
- 增加任务类别后若在固定留出条件上改善，才支持多任务迁移收益。

## 比较条件

有地图时同时监督排序，现有组间差值衡量地图与排序监督整体作用；机制判断另用内容干预。不同模型规模、数据量、目标分布或更新预算的历史成绩保留各自身份。

地图组／SFT文字组逐轮获得环境更新；历史强文字基线一次输出完整计划、无中途反馈。对应结果注明交互差异，纯文字预算包含思考和答案。规则见[任务文字](../TASK_TEXTS.md)，数值见[基线报告](../experiments/task_text_baselines/results/report.md)。

固定监测集已用于选模和开发，最终泛化须保留独立验收；Qmap与LLM的曝光分别说明。相关研究入口见[Related Work](../RELATED_WORK.md)与[GCML Tasks](GCML_TASKS.md)。
