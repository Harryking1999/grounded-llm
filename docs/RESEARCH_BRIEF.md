# 研究简述：语义模型与状态认知

**核心问题：给已有语言能力的模型接入显式状态认知，能否改善状态理解、动作判断与规划？**

本页维护研究定义；进度与有序 TODO 见[项目状态页](PROJECT_STATUS_AND_TODO.md)，文献依据见 [Related Work](../RELATED_WORK.md)。

## 动机

RAP 对问题的概括是：

> The deficiency stems from the key fact that LLMs lack an internal world model to predict the world state (e.g., environment status, intermediate variable values) and simulate long-term outcomes of actions.

—— [Reasoning with Language Model is Planning with World Model](https://arxiv.org/pdf/2305.14992)

LLM 具有通用推理能力，但在复杂环境中可能难以稳定表示当前 world state、预测动作后的状态，并据此规划长程结果。已有纯语言基线出现状态报告错误，也出现报告正确却选择非法动作、合法动作导致死局和提前停止。它们提示状态读取、转移判断和规划可能是不同瓶颈，不能把所有失败都归为“忘记状态”。

GCML 提供了从动作转移学习地图、利用目标方向生成轨迹的参考。汉诺塔预印本则发现：模型在输入末尾已有可解码的状态表示，长生成中表示会退化，借助外部状态跟踪重新注入表征可以改善部分结果。当前研究把 cognitive map／roadmap 作为显式外部 world model，让它提供状态和动作后果，再检验 LLM 能否利用这些信息。

## 能力与信息条件

分别考察观测解析、当前状态估计与维护、动作条件下的转移预测、目标判断、未来规划和动作表达。某项改善是否传递到下一项，由实验回答。

状态既可以是环境真值，也可以是根据观测和历史估计的表示。文字输入可以完整编码状态；若观测本身不足以确定状态，应表达不确定性或获取信息，而不是将信息不足归因于推理失败。

更新当前状态与更新网络参数是两回事。当前显式接口不要求训练 LLM 解码一个连续 state token。

## 当前路线：寻路与积木

信息流是：环境／状态 → 学到的 cognitive map／roadmap → 显式提供当前状态、候选动作的预测后果及与目标的关系 → LLM planner。首版选择只向 LLM 暴露候选动作的 learned-map 距离；完整 Q 和较短 Q 向量是以后可比较的接口版本，不作为当前输入。

寻路的 Step 1 已为每张固定图独立学习 Q/V：状态向量与动作位移共同拟合一步转移。转移准确不保证图距离或规划有效，因此分别检验了转移、表示几何和简单动作读出。新接口可读取已有图 Q/V，为合法候选动作给出预测后的地图表示及其到目标 Q 的距离。这里的距离来自学到的 roadmap；图上的真实最短距离只用于评测或 oracle 上限，不能混作地图预测。

程序维护实际当前位置；动作执行后的真实反馈与执行前通过地图得到的预测后果分别记录。当前图的动作目录按有向边编码，已经包含真实终点；首版给所有条件相同的动作终点语义，只额外给地图条件 `||Q当前 + V动作 - Q目标||₂`。这个距离是 learned map 的预测，不是真实后继 Q 或最短路真值。同图未见起终点组合、未见节点与未见图拓扑的泛化分别定义。

连续生成试点采用**逐节点上下文干预**：控制器识别模型提交的新节点，暂停解码，执行动作，将实际状态与地图信息追加到已有上下文，再续写下一 token。历史推理始终保留，服务端以分段请求实现这条连续的生成轨迹。正常干预暂停与预算耗尽分别记录。具体协议、预算和诊断见[连续生成试点说明](../experiments/external_map_interface/results/path256_five_graphs.md#新实验设置连续生成过程中提供地图)。

积木规则中的完整状态是 10×10 二值棋盘，动作是 `shape_id、row、col` 指定的一次合法移除，目标为空棋盘。此前的像素接口取 `Q=I`，没有学出 goal-distance geometry。本轮先按单张初始棋盘建 Q 表，再换成读取棋盘的编码器；跨初始棋盘共享仍是待检验的问题。

当前积木方案按用户新讨论改为先训练 Q 的距离关系，再冻结 Q 单独拟合 V。首轮只训练 Q，使用原论文八种简单形状与固定初始棋盘，离线精确标注有向最短步数和已证明不可达的状态对；以距离 Huber 和近远排序 hinge 学习目标无关的 Q。普通欧氏距离与允许方向差异的固定距离读出采用匹配监督比较。坏合法动作仍是一步正样本，只有它的后继到不可达目标才应远。训练、loss 和评测的通俗说明见 [Q-map 方案](BLOCKS_QMAP_PLAN.md)，正式运行参数见[实验合同](../experiments/blocks_distance_map/configs/pilot.json)。

已先以查表 Q 检验已见状态的关系补全，再用棋盘编码器检验状态池外的残余棋盘。两张棋盘各自训练的结果较好，但首张编码器零样本用于第二张的逐步规划失败，因此不声称跨棋盘泛化。候选诊断使用环境合法动作与真实后继棋盘，独立于 V 和 LLM；真实距离仅用于离线监督或单列的 oracle 评测，不作为地图推理输入。共享 Q 的跨棋盘适用范围，与固定单棋盘 Q 后用 `V(a,o)` 拟合 `Q(o′)-Q(o)`，是可以分别验证的问题；跨棋盘成功不是单棋盘 V 实验的逻辑前提，目标不进入 V。本轮尚未训练 V。数值与局限见[积木 Q-map 报告](../experiments/blocks_distance_map/results/report.md)。

此前 `δ = MLP([Q(o), E(a)])` 联合更新 Q 与 MLP、仅拟合合法转移残差的实验保留为历史诊断；它使用十形状变体，不能当成本轮八形状的匹配对照。更早的固定共享 `V_a` 代码、配置与负结果同样保留。

积木地图的关键检验是：少量格子却已无解的 dead state，与剩余更多格子但仍可解的状态，在学到的目标关系中能否被区分。仅拟合一步转移不保证这一点，必须实际测量，不能用覆盖率下降代替可解性。此前[积木 Step 2](../experiments/state_interface_pilot/README.md) 的 token 读出结果作为 previous approach 保留。

## 后续交互与规划

长期希望实现：

```text
真实观测 → 更新状态认知 → 想象候选动作及后果
         → 选择实际动作 → 环境执行 → 新观测
```

真实行动后的反馈与行动前的假想转移需要区分。若在尚未执行时调用精确环境转移、合法动作表或搜索器，应记录相应信息条件；不同对照获得匹配的规则与反馈。

先验证地图、显式接口和基本逐步规划。若图规模增加后地图不够精确，再考虑让 planner 对多个候选路径向前采样；现在不引入复杂搜索系统。

## 如何判断研究主张

- 用匹配的任务、状态、规则、提示、预算和反馈比较原始模型、其 reasoning 版本与显式地图接口。
- 同时报告状态／转移准确率、非法动作率、目标判断及任务成功率；保留负结果与截断样本。
- 一步转移拟合、目标远近关系、模型实际利用地图信息是三种证据；通过状态或目标干预检验使用情况。
- 若简单文字状态即可消除失败，应缩小显式地图的增益主张；若只在训练构型有效，不支持跨初始棋盘泛化。
- 冷门任务不等于预训练未见。更长思考、更大模型和额外搜索带来的收益，也不能直接归因于状态建模。

## 长期目标

探索共享模型如何跨任务表示和更新状态，如何利用新观测校准内部预测，以及较小 LLM 能否借助状态认知改善规划。积木与图任务分别成功仍只是单任务证据；跨任务共享、在线学习与多分支想象需要后续独立实验。
