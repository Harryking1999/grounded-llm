# 研究简述：语义模型与状态认知

状态：纯语言基线已扩展至 Sol 与 Qwen；最新结果和有序工作统一见 [项目状态页](PROJECT_STATUS_AND_TODO.md)。状态增强机制与迁移主张仍待验证。

研究定义与讨论同步：2026-09-13。最新设计见 [实验设计讨论](../EXPERIMENT_TODO.md)，其中候选方案不等于实验事实或正式运行合同。

## 问题与动机

LLM 已经具有相当的智能，但我们认为，基于 token 的语言能力无法代表人类总体的智慧。

当前待检验的判断是：仅靠语言推理，LLM 可能不能正确、稳定地维护和使用任务状态。已有 Luna、Flash、Sol 与 Qwen 的批量基线暴露可定位的失败，也包含状态报告正确却动作违规的情况。失败是否由状态维护、转移预测或规划引起，仍需分别诊断。

近期讨论将任务拆为：积木用已知状态和规则检验 LLM 的状态使用能力；抽象图从轨迹学习地图，先检验目标方向信息，再检验 LLM 如何使用它。32 节点图是历史起步设置，现已有 path256 基线；新图方案首先关注合法到达，不沿用旧实验的最短路主指标。文字棋类、翻花绳、华容道和鲁班锁保留为后续候选。实际进度与后续计划统一记录在 [项目状态与有序 TODO](PROJECT_STATUS_AND_TODO.md)。

状态可以是环境真值，也可以是根据观测和历史估计的内部表示，须按条件区分。近期积木方案以完整初态和精确规则维护准确状态，因此提供了外部状态更新帮助；公平对照也应获得相同更新后的文字状态。抽象图方案中的学习表示不是独立真值，预测未知转移的准确性需要另测。

实验应区分两种情况：文字观测完整给出了任务状态，以及文字只提供局部观测、需要结合历史推断状态。没有图像输入并不等于信息不全；语言也可以完整编码棋盘或图结构。若所有可用历史仍不能确定状态，应允许表示不确定性或通过动作获取信息，不能把信息不足造成的失败归因于推理能力。

## 核心设想

通过认知地图／状态网络帮助模型构建对世界的认识，增强空间关系、当前状态和动作后果的认知，并在推理时先进行内部演算与想象，以支持实际动作选择。老师提出的核心问题是：

> 有语义的模型加上状态认知，是不是比只有语义的模型更好？

例如，GPT 在思考时可能不知道自己已经走到哪里；加入这个模块后，一个很小的模型是否可能在相关问题上比 LLM 更聪明。

该网络需要在模型内部结合状态认知，而非只从外部检索信息。它还希望能够在聊天／交互过程中继续学习；在线学习的更新时机与稳定性仍需定义。

## 训练与推理约束

**已确定的训练决策**：冻结 LLM 原有参数，仅训练状态网络及其与 LLM 之间的转换接口。近期积木方案提出只训练状态报告和状态关系报告，然后直接测规划；图方案提出地图学习与 LLM 适配分开验证。具体网络、注入层、损失实现和训练预算尚未形成正式合同。冻结参数不等于禁止梯度经过冻结模型传回接口；具体梯度路径取决于接入方式。

**已澄清的交互与推理机制**：实际动作执行后，模型可以获得真实反馈或新观测。认知地图结合这些观测和历史建立、校准对当前世界的内部认识；在下一次动作选择的推理过程中，模型先在内部演算候选动作及其后果，再选择实际执行的动作。基本循环为：

```text
真实观测 → 更新内部状态认知 → 推理中想象候选动作及后续状态
        → 选择实际动作 → 环境执行 → 真实反馈／新观测 → 下一轮
```

一次推理内部可以连续想象多个尚未执行的动作，也可以比较多条路径。实际执行可以只取计划中的一步或一段，再根据真实反馈修正认知、继续想象。想象的范围与执行步数尚待任务设计确定，不要求每次都预先想完整个任务或一次性输出最终完整解。

纯语言完整计划基线已完成多组批次，当前进入状态使用机制与接口的设计阶段，尚无状态网络训练结果。近期实现候选是在动作边界更新一条状态轨迹；这不等于网络只能做线性运算，也不禁止未来实现分支复制与回溯。短 CoT／结构化动作输出的选择依据应是协议可解析性，而不是“状态线性”的未经证明限制。

需要区分反馈的时机与用途：真实动作之后的环境反馈是正常交互；尚未执行的候选动作，其假想后果应由内部状态模型推演。若在这些虚拟步骤中查询精确环境转移或合法动作表，这提供了额外的推演辅助，应如实说明。不能仅因系统在真实执行后获得新观测，就认为其没有内部想象或状态认知能力。真实观测也不保证揭示完整世界状态。

更新当前内部状态表示与更新网络参数是两回事。推理时可以利用新观测校准状态；是否同时进行在线参数学习仍需另行定义，LLM 原有参数冻结的训练约束保持不变。

状态模型负责状态估计和动作条件下的转移预测；目标判断、未来搜索和动作选择需要分别定义。会议讨论让 LLM 承担参考框架中 `W` 的动作生成角色，但如何对应原机制的多分布加噪、如何生成多样路径仍未解决，不能视为已经完成等价替换。

**整体路径选择方案**：推理时采样多条想象路径，借助外部奖励工具选取候选解；采样、搜索与奖励排序的优化不属于核心研究贡献。会议明确要求在相同采样次数下比较基线与新模型的准确率；还需匹配评分工具、评分信息与推理预算，并区分候选集中存在正确路径和筛选后实际选中正确路径。单路径、无外部筛选与多路径工具辅助条件分别报告。奖励依据、未执行候选的评分能否查询精确环境、路径何时算“可以执行”、如何判定想象终止，均尚未定义。

环境代码可以执行真实动作、返回约定的新观测，并判定合法性、成功或失败。这是交互任务的环境／裁判功能；向推理中的未执行分支提供精确后继状态、合法动作表或搜索建议，则是另一种信息或工具条件。应分别记录，不能把一切环境反馈都归为额外工具帮助。外部工具选出候选解并不保证该解最优或能在真实环境成功，需要独立验证。

初测使用大模型 API，内部接入状态网络则需要确认所选模型及接口支持相应访问与训练。二者是不同的实现需求，不能默认一次文本 API 调用已经实现网络内部结合。环境真实状态可供裁判诊断；近期积木方案也提出用准确状态及差分作报告监督，但不能把任意学习编码器的输出本身称作独立真值。

## 参考工作的机制启发

这里的参考工作已明确为 [GCML 正式论文](https://www.nature.com/articles/s42256-026-01254-4)，原始任务和官方实现见 [GCML 任务说明](GCML_TASKS.md)。其中积木任务采用直接二值状态表示与任务特定合法性机制；发布代码还在候选轨迹生成中使用精确棋盘更新。需要核对的是这些规则计算承担了多少虚拟状态推演，而非以“真实执行后允许反馈”作为本项目与参考工作的区别。

参考工作提出了一种编码观测、状态认知和动作的方法：从观测形成状态认知，并把动作的影响映射到同一个空间中。参考工作用 `Q` 和 `V` 表示这两个映射：

$$
Q o_{t+1}=Q o_t+V a_t
$$

其中，`o_t` 是时刻 `t` 的观测，`a_t` 是动作；`Q o_t` 表示 AI 根据观测形成的内部状态认知，`V a_t` 表示动作在同一空间中造成的变化。`Q o_t` 不是一个可以直接读取的真实状态标签。

参考工作的训练误差直接由等式的偏差给出：

$$
e_t=Q o_{t+1}-(Q o_t+V a_t)
$$

参考工作用 `e_t` 直接更新网络。训练信号来自前后观测与动作之间是否一致，而不是来自真实状态标签。直观上，如果动作造成的位移预测少了一部分，就用这部分位移误差直接补回去。

本项目借鉴的是“从观测建立状态认知，并学习动作如何改变这一状态”的思路，不局限于参考工作的线性 `Q/V`、加法关系或直接误差更新。我们可以考虑使用反向传播，也可以根据具体场景、任务结构和实现难度采用其他网络与学习方法。

转移一致性不保证有用的目标距离。抽象图的“近”首先指所需合法动作少；学习表示之间的欧氏距离未必保留这一关系。原 GCML 还使用 `W` 从目标差形成动作偏好；能预测后继状态、能给动作排序、能成功规划是三项不同性质。即使某种动作编码下 Q 确定后可令 V 拟合各条边的差，也不能把表示几何称为已经获得的 ground truth。

## 状态表示与跨任务泛化

长期目标是用一个共享模型，根据不同任务的观测建立并更新状态认知。近期积木固定规则与抽象图学习地图是两个机制诊断，尚未构成共享模型，也不能单凭两项任务分别成功宣称跨任务迁移。

这些任务都希望能够被抽象成某种“地图”；不同任务的上下文和语言表述不同，但共享模型应学习可迁移的状态结构。计划通过多任务联合训练检验这一目标；多任务训练本身不能证明迁移，还需区分已见任务中的新实例与未见任务上的表现。

会议将翻花绳视为抽象图问题的具象化，确认采用状态与动作可数的抽象，并认可尝试用空间直角坐标系中的直线表征图形。需区分两层图：一层描述绳的构型或接触关系，另一层以完整构型为节点、以合法动作产生的转移为边。二者不能未经定义就视作同一张图。

可数不等于有限，也不保证容易枚举或搜索。连续坐标如何离散化、哪些构型视为同一状态、直线／线段及其连接信息是否保留交叉上下关系、穿绕和接触限制，都仍待验证。如果抽象把未来合法动作不同的两个物理构型映射成同一状态，就需要补充表示。该方案暂不进入复杂物理模拟实现。

会议提出向多模态和具身任务（如寻路、机械臂操作）扩展的可能性，并将“脑补未来状态”作为关注点。这是泛用性假设。关注虚拟推演可以明确问题，但不能仅按输入模态排除已有方法；仍需比较其是否维护状态、预测动作后果以及规划未来。

## 基线与可证伪的解释

历史筛选从 GCML 的积木和 32 节点图开始，随后扩展到新形状、开关图、DAG 与 path256，并完成获授权的开源 Qwen thinking 基线；早期“先只测闭源模型”已不是当前阶段约束。状态接口的基础模型尚未最终选定。英文用于统一规则、观测与输出格式，不能单凭使用英文断言没有语言偏差。冷门任务只能降低对任务熟悉度的直觉预期；在没有训练数据证据时，不能声称模型从未见过该任务。

### Luna 直接 API 小批基线（2026-09-04）

两项任务均通过兼容文本 API 直接调用 gpt-5.6-luna，推理强度为 medium，不创建 Codex task，也不提供浏览器、终端、文件、屏幕、仓库或其他 agent 工具。提示词只包含 GCML 任务规则、完整观测和可解析 JSON 输出合同；每条调用独立，原始 prompt、完整 API response、模型输出、summary 和外部裁判 verdict 保存在对应实验目录下的单一 `run.json`，正式合同与复现实验脚本也在对应 `experiments/gcml_direct_api_*` 目录。

**历史 Blocks setup 与结果**：使用 GCML tiling_order_10x10_8obj.h5 测试切片的 11 个不同棋盘，共 16 次调用；旧协议每条最多 8 个动作。逐次输出成功率为 12/16：一条在第 4 个动作越界非法，一条提前停止并留下可解残余，两条在合法动作后留下不可分解残余。宽松 JSON 提取后均可解析。旧模板要求 `final_status=solved`，不能把错误自报单独解释为终止判断能力。旧文档的 pass@16 标记已更正为逐次输出成功率。

**历史 path32 setup 与结果**：使用 GCML commit ff76859b71a2bc2056b50f5e052475351c007f76 中固定的 32-node 无向图。配置中的 8 组起终点包含重复，实际是 7 个不同起终点对，共 16 次调用；不限制路径长度，也没有要求最短。逐次输出中 16/16 到达目标、5/16 最短、16/16 自报终点正确。最短性是事后效率指标，不能据旧提示词把非最短答案判为未完成任务。

本轮 [`gcml_counterexamples`](../experiments/gcml_counterexamples/README.md) 扩大独立样本并测真正的 pass@8：每题八次独立采样中至少一次成功的实例比例，预算截断也保留为一次尝试。积木取消动作数上限，任何合法清空均算成功，构造块数与最小分解步数只作诊断；路径明确要求最短，并增加开关门条件。死局用于事后 case study，主要样本在模型调用前独立选定。最新结果统一见项目状态页与该研究摘要。

追加的 DeepSeek Flash 对照保留每题八次试验，包括预算截断；全部实例至少有一次成功，Luna 的三个 0/8 实例并非两个模型共同的稳定失败。Flash 的完整积木答案全部合法，但许多试验用完预算仍没有完整答案；少量路径答案表现为图边使用错误或非最短，已评估的开关状态报告全部正确。因此当前证据支持进一步检验固定推理预算下的可靠性、动作后果利用和效率，不支持把所有失败统称为状态遗忘，也不要求先证明每个前沿模型都无法解题才开展状态增强研究。两个接口的推理预算和实际 token 用量不同，不能把跨模型差异当作状态模块的因果证据。方法增益和共享迁移目标保持不变，具体结果与后续建议统一见权威状态页。

完整结果分别见 `experiments/gcml_direct_api_blocks/runs/clawnode_luna_20260904_16/run.json` 和 `experiments/gcml_direct_api_path32/runs/clawnode_luna_20260904_16/run.json`。Blocks 的 12/16 暴露了可定位的合法性与状态收尾问题；path32 的 16/16 说明当前 pair 套件对到达目标偏简单，后续优先增加组合状态，而不是立即把更长的 node-only 路径当作状态任务。

这只是定位用小批，不是泛化结论。结果将后续对照拆成规则/格式、当前状态维护、单步转移、目标判断和规划五个轴；在状态网络训练前，先用匹配提示和独立实例检验更简单解释。

文字下棋不作为近期主攻方向，保留为研究动机与后续验证方案：让两个接入状态网络的 GPT 对弈，以独立裁判执行规则，非法动作直接判负。会议对五子棋保留意见，也讨论过增加构型复杂度，希望选择模型较不熟悉的棋类，但尚未选定。规则复杂或训练需求高不自动说明更能定位状态缺陷。双边对弈受对手强弱影响，仍需匹配的无状态网络对照和固定局面的状态、转移测试。

会议提出“现有模型依赖大量数据拟合状态，规则改变后可能失效”的解释，并讨论了重读上下文作为潜在替代方法。规则变化后的失败与重读是否足够，都需要匹配实验；不能预先将基础模型概括为记忆，将状态网络概括为真正理解。

以下为依据项目研究纪律整理的实验解释建议，不是会议已逐项确定的方案，尚未形成正式运行合同：

- **先定位失败原因**：分别观察规则与观测解析、当前状态维护、单步转移、目标判断、未来规划和动作表达。任务失败本身不足以证明模型缺乏世界模型。
- **排除更简单的解释**：用最便宜的针对性对照判断问题是否来自含糊编码、规则误解、输出格式或推理预算；必要时加入显式文字状态记录的基线。若这些措施即可消除失败，应相应缩小状态网络的必要性主张。
- **检验状态机制**：在匹配信息、提示和预算的条件下比较冻结 LLM 加接口／状态网络与基础模型；如观察到增益，再用关闭、打乱或其他针对性对照判断增益是否依赖状态与转移信息。若只增加训练样本或搜索预算就能解释改善，不能归功于状态建模。
- **匹配交互条件**：主要比较允许模型在真实动作之后获得相同规则下的反馈，并记录推理中可访问的状态、工具和采样预算。一次性输出完整解、不给中途真实反馈可作为补充诊断，不将其设为认知地图方法必须满足的唯一任务形式。实际反馈不排除模型在每次动作前进行多步想象。
- **保留否定证据**：若纯语言基线稳定成功，则该任务当前不足以支持预期缺陷；若状态或转移改善但任务表现不变，应报告这一分离；若增益只在训练构型出现，不支持跨任务泛化。
- **控制筛选偏差**：保留初测中的成功案例，以独立实例进行后续比较。筛选出困难任务后的失败率不能代表模型的一般能力；如主张人类优于模型，需同信息条件的人类对照。

正式实验按任务报告成功率、非法动作率、适用的状态／转移准确率和不同呈现方式下的一致性，并记录训练与推理开销。若潜在表示没有可直接比较的标签，应通过明确的状态查询或可解码预测来检验，不以潜在向量损失单独代替能力证据。

## 目标

- 检验加入状态认知后，模型是否比只有语义能力时更强；
- 让模型在多个具有可建模状态的问题上超过 GPT；
- 探索 **grounded language is better than token language**；
- 研究一个很小的状态网络能否使较小模型表现出超过纯语言 LLM 的智能；
- 使同一个状态模型能够跨任务表示和更新状态，并在交互过程中继续学习。

以上目前是研究目标和机制构想，不是已经得到的实验结论。

## 当前尚未定义清楚的问题

1. 哪种状态网络和学习方法适合具体场景？参考工作的 `Q/V` 直接更新、反向传播及其他方案分别适用于什么情况？
2. 模型如何从观测形成状态认知，以及如何判断同一个模型确实学会了在不同任务中建模自身所处的状态？
3. 在冻结 LLM 原有参数的约束下，转换接口接入何处，状态网络如何参与内部计算和多步推演？
4. 聊天／交互过程中的在线学习何时触发，如何更新状态网络与接口并保持稳定？
5. 哪些任务和最小对照能将失败定位到状态维护、转移预测或规划，而非信息不足、编码含糊或任务不熟悉？
6. 如何从单任务实验推进到一个模型上的多任务联合训练，并用独立实例与未见任务区分记忆和迁移？
