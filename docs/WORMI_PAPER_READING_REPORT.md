# WorMI 精读报告：用多个领域模型辅助语言模型行动

**论文：** World Model Implanting for Test-time Adaptation of Embodied Agents，ICML 2025，Minjong Yoo 等。

[正式论文](https://proceedings.mlr.press/v267/yoo25a.html) · [公开代码](https://github.com/mjyoo2/WorMI/tree/96a2375ad7e96e75073f478bd37462f931dc39bc)

## 1. 动机：语言模型怎样使用不同环境中的行动经验

机器人收到“把苹果放进冰箱”的指令，需要结合当前环境决定下一步：苹果在哪里、是否已经拿起、冰箱是否打开。换一个场景，或换一种任务组合，原来学过的行动经验未必能直接适用。

作者关注的是：**怎样保留语言模型已有的能力，同时灵活调用不同领域的环境知识，减少适应新领域时的数据和训练需求。**

![Figure 1：不同方式如何把环境知识交给语言模型](figures/wormi/figure_1.png)

*Figure 1：方法的出发点。*

图中前三种方式分别是：直接让 LLM 生成动作；检索相关示例放入提示词；给 LLM 接入一个领域模型。它们各自依靠预训练知识、示例数据或特定模型提供的经验。

WorMI 的思路是把不同领域的知识分别学进多个小模型，执行时选出相关模型，将它们的内部表示接入主 LLM。模型库可以扩展，参与当前决策的模型也可以更换。于是，方法需要解决两个问题：**选哪些模型，以及怎样把选出的模型一起用好。**

## 2. 整体方法：先选模型，再融合知识

WorMI 包含三类组件：

- **主推理模型：** 默认使用 Llama-3.2-3B，负责最终生成动作。
- **领域世界模型：** 使用 Llama-3.2-1B，在不同领域的轨迹数据上分别训练，提供环境与行动经验。
- **组合模块：** 读取世界模型和主模型的中间层表示，融合信息并接回主模型。

这里的“表示”是模型处理输入后得到的向量。WorMI 在执行时读取世界模型的这些向量，再由主模型输出动作。

![Figure 2：原型检索与复合注意力组成的整体流程](figures/wormi/figure_2.png)

*Figure 2：左边选择参与模型，右边把它们接入主模型。*

**左边是原型检索。** 每个世界模型绑定一组代表其训练领域的向量，称为“原型”。当前观测也被转成原型，与模型库逐一比较，选出距离最近的模型。主设置从 6 个世界模型中选 3 个；图中的 Activate / Deactivate 表示参与或暂不参与。

**右边是复合注意力。** 主模型和选出的世界模型处理相同的指令与观测，产生中间层表示。组合模块先融合世界模型的信息，再将其接入主模型，输出下一步动作，例如 grab apple。环境执行动作，返回新观测，进入下一轮决策。图中的雪花表示模型冻结，火焰表示组合模块可以训练。

因此，完整流程是：

**当前观测 → 检索相关世界模型 → 融合中间层表示 → 主模型生成动作 → 环境反馈。**

下面先解释检索，再解释融合。

## 3. 原型检索：当前观测与哪些模型的训练领域接近

每个世界模型 $M_j$ 对应自己的训练数据 $\mathcal D_j$。作者从这些轨迹中提取对象状态，例如苹果的位置、冰箱的开关状态，再将它们编码成向量，形成领域的嵌入集合 $\mathcal E_j$。

直接比较整个集合成本较高，因此作者从中选少量代表向量，组成原型集合 $\mathbf p_j$。论文使用 **k-center**：选择 $k$ 个中心，使所有原始向量都尽可能靠近某个中心，特别控制最远点的距离。其目的在于用少量点覆盖领域内不同的对象状态。论文设置 $k=15$，对应的 VirtualHome 示例约有 10,200 个原始嵌入。

测试时，当前观测也经过对象状态提取、编码和原型构造，得到 $\mathbf p$。然后计算：

$$
d_j=\delta(\mathbf p_j,\mathbf p),
$$

其中 $\delta$ 是 Wasserstein 距离，用来衡量两组向量分布的差异。距离越小，认为当前状态与该模型的训练领域越接近，取距离最小的 $K$ 个模型参与后续计算，默认 $K=3$。

这一步提供的是**模型级的选择**。比如当前任务涉及卧室中的苹果和厨房中的冰箱，检索希望找到包含相关对象状态经验的模型。选中之后，各模型在具体输入位置上的作用大小，再由注意力决定。

原型来源与世界模型训练数据同源；当前原型来自执行时获得的观测。检索本身不需要目标域示范，也不进行梯度更新。按照论文算法，观测变化后可以重新选择参与模型。

实现上，公开代码的 ModelStore 使用 K-means 构造原型，与论文写的 k-center 不同；两者都提供聚类摘要，但优化目标不同。[依据：论文 §3.2；ModelStore](https://github.com/mjyoo2/WorMI/blob/96a2375ad7e96e75073f478bd37462f931dc39bc/wormi/model_store.py#L44)

## 4. 复合注意力：先沿模型维融合，再沿序列读取

检索得到了相关模型，但它们可能擅长不同对象或任务环节。WorMI 因此使用两层交叉注意力：**第一层融合多个世界模型，第二层让主模型读取融合后的信息。**

![Figure 3：复合注意力的两层结构](figures/wormi/figure_3.png)

*Figure 3：从下往上依次是表示投影、世界模型融合、主模型读取。*

### 4.1 投影：使不同模型的向量宽度一致

世界模型与主模型大小不同，中间表示的宽度也不同。首先将各世界模型表示 $H_j$ 投影成与主模型表示 $H_R$ 相同的宽度：

$$
Z_j=P_\theta(H_j).
$$

论文把这一步描述为线性投影，公开代码使用小型前馈网络。它为后续注意力提供尺寸一致的输入。

### 4.2 第一层：同一个 token 位置，应该怎样组合不同模型

主模型和世界模型处理相同的输入，token 位置能够对应。第一层注意力固定一个位置，比较不同世界模型在该位置的表示。

用“把苹果放进冰箱”举例，暂时把“苹果”和“冰箱”各看作一个 token。在“苹果”位置，主模型的表示作为 query，三个世界模型在同一位置的表示作为 key。query 与 key 的匹配程度决定权重，再按权重融合各模型表示：

$$
F_u=\sum_{j=1}^{K}\alpha_{u,j}Z_{j,u},
\qquad \sum_j\alpha_{u,j}=1.
$$

$u$ 表示 token 位置，$\alpha_{u,j}$ 表示该位置分配给模型 $j$ 的权重。query 是用于匹配的查询向量，key 是被匹配的索引向量。

下面的权重仅用于示意：

| 输入位置 | 模型 1 权重 | 模型 2 权重 | 模型 3 权重 |
|---|---:|---:|---:|
| 苹果 | 0.2 | 0.7 | 0.1 |
| 冰箱 | 0.8 | 0.1 | 0.1 |

两个位置可以采用不同的模型组合。每个位置完成融合后，仍得到一条与输入长度相同的序列 $F$。

代码中这一过程对应：

~~~
K 个世界模型表示：[B, K, L, D]
转置并合并 batch 与位置：
query → [B×L, 1, D]
key / value → [B×L, K, D]
~~~

$B$ 是批大小，$L$ 是输入长度，$D$ 是投影后的向量宽度。一次注意力只比较同一位置上的 $K$ 个模型。实现取多头平均后的注意力权重，对投影后的表示加权。[代码：WorldWiseAttentionImplantHook](https://github.com/mjyoo2/WorMI/blob/96a2375ad7e96e75073f478bd37462f931dc39bc/wormi/modules/hooks.py#L397)

### 4.3 第二层：主模型从融合序列中读取相关信息

第一层得到融合序列后，第二层沿 token 序列进行匹配，让主模型读取当前需要的信息。它的三个输入是：

| 输入 | 来源 | 作用 |
|---|---|---|
| Query | 主模型当前层表示 $H_R$ | 决定当前要匹配什么 |
| Key | 世界模型投影表示之和 $S=\sum_j Z_j$ | 决定读取哪些序列位置 |
| Value | 第一层产生的融合表示 $F$ | 提供被读取的内容 |

**Key 和 value 的来源不同**，这就是 Figure 3 左侧 Sum 路径与中间注意力路径的含义。

第一层已经决定每个位置如何组合各模型；第二层再决定主模型当前位置从序列的哪些位置读取内容。比如生成动作所依据的位置，可以读取前面有关苹果、冰箱及其状态的融合信息。

最后，将读取结果加回主模型中间表示：

$$
H'_R=H_R+C_\theta(H_1,\ldots,H_K,H_R).
$$

主模型继续经过后续层，生成动作。两个阶段分别处理“怎样组合模型”和“怎样读取序列”，构成作者所说的 world-to-world integration 与 world-to-reasoning alignment。

### 4.4 信息接入主模型的哪里

默认连接配置为：

| 世界模型输出层索引 | 主模型接入层索引 |
|---:|---:|
| 7 | 13 |
| 15 | 27 |

公开代码按从 0 开始的层索引注册 hook：先运行世界模型、取指定层表示，再在主模型对应层输出处加入组合结果。主模型和世界模型的原有权重冻结，连接处的组合模块可以更新。

“冻结”固定的是参数；接入的信息仍会改变主模型中间表示和最终动作。这也是 WorMI 能在保留原有模型的同时，调整知识使用方式的原因。

## 5. 训练与评测：模型学什么，未见领域怎样划分

### 5.1 先训练世界模型，再训练组合模块

每个世界模型在自己的领域轨迹上训练，样本包含：

$$
(I,s_t,a_t,s_{t+1}),
$$

分别为任务指令、当前状态、执行动作和下一状态。作者设置三个辅助任务：

| 训练任务 | 要求模型学会什么 |
|---|---|
| 状态转移预测 | 给定状态和动作，预测下一状态 |
| 动作可执行性 | 从当前状态判断哪些动作可执行 |
| 模仿示范动作 | 根据指令和当前状态预测示范动作 |

默认每个世界模型使用 Llama-3.2-1B，训练 2,000 个梯度步。领域数据来自对应 benchmark 的已见域轨迹。[依据：论文 §3.2、Table A.6](https://arxiv.org/html/2509.03956v1#S3.SS2)

随后冻结世界模型和主模型，只训练组合模块。作者采用元学习：反复选取不同的世界模型子集及其对应数据，从公共参数出发训练各组合，再把这些训练后的参数变化汇总，更新公共参数。训练目标是提高示范动作的生成概率。

这样训练，是为了让模块练习在模型组合变化时融合信息。论文设置 8 次外循环更新，每组内循环 30 个梯度步；内循环学习率为 $10^{-5}$，外循环更新系数为 0.1。

测试时分为两种情况：

- **Zero-shot：** 直接使用已训练的组合模块，读取当前观测、检索模型并生成动作。
- **Few-shot：** 提供目标域 1、5、10 个示范，更新组合模块；主模型与世界模型保持冻结。

### 5.2 两个 benchmark 的数据来源和划分

| 数据设置 | VirtualHome | ALFWorld |
|---|---|---|
| 收集的 episode 总量 | 1,023 | 3,554 |
| 任务划分 | 78 个具体任务：16 已见、62 未见 | 6 类任务：4 已见、2 未见 |
| 场景划分 | 20 个场景：6 已见、14 未见 | 4 类场景：3 已见、1 未见 |
| 输入 | 文本化的环境图三元组 | 文本观测与交互历史 |
| 动作 | 走动、拿取、打开、放置、放入、开关等高层命令 | 移动、拿取、放置、加热、冷却、清洁等文本命令 |

VirtualHome 中的任务主要属于开设备、开容器、放到表面、放入容器四类，变化包括对象、目标和房间配置。ALFWorld 包含放置、清洁后放置、加热后放置等六类任务，采用 CL-ALFRED 的划分设置。

以上 episode 数是收集总量，论文没有给出逐世界模型的训练轨迹数和完整分配清单。因此可以确认世界模型在关联领域数据上训练，但不能仅凭“6 个模型、6 个已见场景”认定它们严格一一对应。

Zero-shot 主表评测三种条件：已见任务与已见场景、已见任务与未见场景、未见任务与未见场景。这里的“未见”指被留出训练划分的任务或场景。

**论文的 zero-shot 是同一 benchmark 内留出领域上的零示范适应：已有源领域训练，测试时没有目标域示范更新。** 这是评价泛化结果时需要保留的范围。[依据：论文 §4、附录 B](https://arxiv.org/html/2509.03956v1#S4)

## 6. 实验：是否有效，以及各设计起了什么作用

### 6.1 主结果：在留出任务和场景上提高表现

作者比较四种方法：ZSP 直接使用预训练模型；LLM+FT 用领域数据微调；LLM-Planner 检索示例放入上下文；SayCanPay 结合 LLM、动作可执行性和成本模型。默认固定主模型使用 3B，可训练语言模型使用 1B。本文中的 SayCanPay 还使用环境提供的可执行性信息。

指标包括 **SR** 和 **PS**：SR 在 VirtualHome 表示任务完成比例，在 ALFWorld 按论文定义表示子目标完成比例；PS 是完成任务所需的平均环境步数。主表采用 5 个随机种子，报告 95% 置信区间。

最能体现留出域泛化的是“未见任务 + 未见场景”条件：

| 方法 | VirtualHome SR | VirtualHome PS | ALFWorld SR | ALFWorld PS |
|---|---:|---:|---:|---:|
| ZSP | 8.19% | 29.36 | 2.13% | 49.68 |
| LLM+FT | 42.82% | 20.79 | 29.40% | 46.84 |
| LLM-Planner | 21.45% | 27.73 | 12.31% | 46.33 |
| SayCanPay | 45.71% | 19.04 | 39.66% | 23.86 |
| **WorMI** | **66.12%** | **15.17** | **51.67%** | **20.18** |

WorMI 相对 SayCanPay，在 VirtualHome 提高 **20.41 个百分点**、减少 **3.87 步**；在 ALFWorld 提高 **12.01 个百分点**、减少 **3.68 步**。WorMI 的 SR 置信区间分别为 ±0.80 和 ±2.23 个百分点。

在已见任务与已见场景下，WorMI 的 SR 分别为 85.78% 和 62.51%；只换成未见场景时，分别为 80.26% 和 52.67%。方法在三种条件下均优于所比较方法，但任务和场景同时变化时仍有明显下降。[数字来源：Table 1](https://arxiv.org/html/2509.03956v1#S4.SS1)

Few-shot 测试中，WorMI 的结果为：

| 目标域示范数 | VirtualHome SR / PS | ALFWorld SR / PS |
|---|---:|---:|
| 1 | 74.90% / 12.18 | 51.50% / 21.46 |
| 5 | 78.04% / 11.85 | 58.69% / 13.14 |
| 10 | 79.61% / 11.68 | 64.46% / 11.79 |

增加示范后表现整体提高，说明组合模块可以利用少量目标域数据调整知识使用方式。其中 ALFWorld 的 1-shot 收益并不明显，5-shot、10-shot 的提升更清楚。[数字来源：Table 2](https://arxiv.org/html/2509.03956v1#S4.SS1)

![Figure 4：执行过程中三个世界模型的注意力变化](figures/wormi/figure_4.png)

*Figure 4：观察第一层注意力如何使用已参与的世界模型。*

纵轴是卧室、客厅、厨房来源的三个世界模型，横轴是执行步骤，颜色越深表示权重越高。横轴标出开电视、开柜子、把文件夹放到沙发、把面包放入微波炉几段任务。

开电视时，客厅模型的权重较高；处理微波炉相关任务时，厨房模型的权重较高。过程中权重随任务变化，说明组合模块会调整几个模型的相对作用。

这张图对应 Figure 3 的**第一层世界模型注意力**：展示的是选中模型之间怎样分配权重。实现按 token 位置计算权重，图则汇总到执行步骤；论文未详细说明汇总方式。热图提供了任务相关的使用现象，作用是否有效还要看下面的消融结果。

### 6.3 消融：模型选择和融合方式都影响结果

在 VirtualHome 未见任务与场景上，作者分别改变检索策略和融合方式：

| 改动 | SR | PS |
|---|---:|---:|
| 使用全部世界模型 | 48.63% | 18.93 |
| 随机选 3 个模型 | 62.04% | 16.96 |
| 选中模型后拼接表示 | 47.79% | 20.03 |
| 选中模型后求和表示 | 56.47% | 17.43 |
| **WorMI：原型检索 + 复合注意力** | **66.12%** | **15.17** |

原型检索比随机选择提高 4.08 个百分点；复合注意力比求和提高 9.65 个百分点，比拼接提高 18.33 个百分点。结果支持两项设计：选择相关模型有帮助，融合方式也会影响最终行动表现。[数字来源：Table 3](https://arxiv.org/html/2509.03956v1#S4.SS2)

参与模型数量的实验进一步显示，使用 1、2、3、4、6 个模型时，SR 分别为 42.75%、62.94%、66.12%、61.96%、48.23%。三个模型在该设置中最好；增加参与模型并不自动带来提升。

### 6.4 扩展实验：模型库可组合，复杂任务仍然困难

![Figure 5：加入与移除世界模型的影响](figures/wormi/figure_5.png)

*Figure 5：模型库的扩展与移除。*

上图逐步增加模型库中的世界模型，并有意只使用与目标域相关的模型，整体 SR 随领域覆盖增加而提高。下图移除各领域的相关模型后，SR 下降约 22–31 个百分点。这说明领域模型提供了有用信息，也展示了模型库可扩展和可移除的性质。

其他实验补充了两个结论。主模型从 1B 增至 3B、11B 时，WorMI 的 SR 从 49.65% 增至 66.12%、71.18%，表现仍依赖主语言模型的能力。长任务与多指令测试中，WorMI 优于基线，但完整 SR 分别只有 19.61%、20.26%；长期可靠执行仍然困难。

## 7. 评价：证明了领域知识组合的价值，泛化范围仍有限

WorMI 的贡献是把领域经验组织成可选择的模型，再通过两层注意力接入主 LLM。原型检索处理领域相关性，第一层注意力处理模型之间的信息组合，第二层处理主模型对融合序列的读取。主结果和消融支持这种组合方式在作者的任务设置中有效。

评价时需要保留三点限制：

1. **泛化发生在 benchmark 内。** 训练和测试共享模拟器与动作接口，测试留出任务、场景；论文没有验证跨模拟器或真实机器人的零示范泛化。
2. **收益来源尚未完全分解。** 世界模型同时接受转移、可执行性和动作模仿训练，论文没有分别量化三种目标的贡献。执行流程主要读取隐藏表示，也未展示基于预测未来状态的显式搜索。
3. **成本与复现信息仍有限。** WorMI 训练并运行多个世界模型，与基线的总参数量和训练量并不完全匹配；逐模型数据分配、完整评测清单和部分实现细节也未充分披露。

这篇论文最直接的结果是：**已见领域的多个模型可以通过检索和表示融合，帮助主 LLM 在留出的任务与场景中更好地行动；这种帮助有明确的实验增益，但复杂任务的绝对成功率和更广范围的泛化仍待提高。**
