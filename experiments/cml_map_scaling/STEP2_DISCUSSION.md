## 第一版架构与 Linear／MLP 对照

共同数据流为：当前／目标地图向量 → 适配器 → LLM 输入向量 → 与任务文字的嵌入拼接 → 冻结 LLM → 文字报告或动作。状态 token 是适配器直接生成的连续向量，不需要对应词表中的单词，也不把地图坐标打印成数字文本。

设地图维度为 `D`，LLM 的输入嵌入维度为 `H`，每个状态占 `k` 个连续 token。两种适配器均接收一个 `D` 维状态，输出 `k × H` 个数，再整理为 `k` 个输入向量。

| 条件 | 结构 | 选择原因 |
| --- | --- | --- |
| **Linear 基线** | `z = Wq + b`，再整理为 `k × H` | 最简单的可训练映射，检验一次线性变换是否已经足够 |
| **两层 MLP** | `z = W2 · activation(W1q + b1) + b2`，同样整理为 `k × H` | 在简单结构上增加非线性，检验更灵活的转换是否改善状态读取和后续使用 |

`D`、`H`、`k` 是三个不同的量：地图维度可选，`H` 由所用 LLM 决定，`k` 是接口容量选择。MLP 隐藏宽度与激活函数待定；Linear 是否使用偏置，以及两者是否共享相同输入／输出归一化，也将在具体实现配置中明确。

**当前／目标的适配器共享方式待确认。** 推荐在每个实验条件内部共享一套适配器，对当前状态和目标状态各调用一次，再用“当前状态／目标状态”的文字标签区分角色。同一节点在两种角色下得到相同的适配向量，便于在同一个表示空间中比较远近。另一候选是当前／目标分别使用两套参数，可作角色专门化，但需要额外处理两套输出之间的对齐。这里的“共享”指 Linear 条件内共享、MLP 条件内共享，两种对照本身仍分别训练。

**比较原则**：两者使用相同地图、输入信息、状态 token 数、数据划分、监督目标和评测预算；训练步数／样本量采用共同起点。分别记录参数量、训练时间、报告准确率与后续动作表现。MLP 通常同时改变非线性与参数量，因此首轮回答的是“两种实际接口哪个更好用”；若后续要单独归因非线性的作用，再设计相应对照。

工程入口已核对：Qwen3 的 `inputs_embeds` 接口支持直接输入形状为“批次 × 序列长度 × 嵌入维度”的浮点向量。[官方文档](https://huggingface.co/docs/transformers/model_doc/qwen3) 训练时，回答的损失经冻结 LLM 传回适配器；冻结 LLM 参数与允许梯度经过它是相容的。分段生成时的状态追加、位置与缓存处理将在实现方案中进一步明确。

已确认冻结 Q/V 和 LLM，训练适配器；当前／目标分别标识。当前的一步动作评测只需输出一次选择。后续多步推理可在确定动作后按 `q_next = q_current + v_action` 追加状态，这部分更新与缓存协议留到多步阶段讨论。积木已有每状态 1／2／4 个向量的讨论，图接口的数量需单独确定。

## 第一种与第三种架构的关系及其他候选

| 候选 | 与当前路线的关系 | 当前定位 |
| --- | --- | --- |
| 第一种：输入层状态 tokens | 状态向量经过适配器后成为输入序列的一部分 | 首版路线 |
| 第三种中的输入层动态连续提示 | 如果同样由当前状态生成输入层提示向量，则与第一种属于同一路线 | 不重复设为另一组架构实验；追加还是替换需写清楚 |
| 第二种：外部 memory + cross-attention | 状态保存在序列外，由新增的内部读取模块访问 | 后续候选，需要明确插入层与状态更新方式 |
| 第三种中的动态 LoRA | 状态影响内部低秩计算分支，而非仅生成输入向量 | 后续候选，需要额外设计参数生成、训练和历史缓存的使用方式 |

“第一种与第三种接近”具体指输入层连续提示；逐层注意力前缀或动态 LoRA 仍有不同的实现。首轮采用简单适配器，便于先观察状态是否被读懂。更复杂的接口可在发现具体不足后讨论。

## 训练任务：先学地图，再学状态报告

**阶段一：地图学习，已由 Step 1 完成。** 由图环境生成 `(o_t, a_t, o_{t+1})` 三元组，训练 `Q o_{t+1} ≈ Q o_t + V a_t`，并独立测量地图远近性质。重跑已经得到可用 Q/V 与对应距离结构结果，Step 2 直接加载选定地图。

在当前“一条有向边对应一个动作 ID”的设置中，固定 Q 后，该动作向量可取对应后继与前态的表示差。因此三元组可以直接提供转移训练信号。文档将环境节点、动作和后继关系称为 ground truth，将 Q/V 称为由这些真值训练得到的表示；表示坐标本身有多种选择。若以后多个状态共享同一动作编码，则另行检查这些转移是否能用同一个位移表示。

**阶段二：状态报告，本轮确认的适配训练。** 冻结地图与 LLM，分别训练 Linear 和两层 MLP，让 LLM 看当前／目标状态的连续表示，按 prompt 输出对应节点身份。此前提出的相邻关系、动作后果和最短距离监督不进入本轮训练。

下面给出待确认的样本格式；其中方括号是连续向量的位置示意：

```text
输入：当前状态：[adapter(s)]；目标状态：[adapter(s*)]。
      请报告当前所在节点，只输出节点编号。
答案：17

输入：当前状态：[adapter(s)]；目标状态：[adapter(s*)]。
      请报告目标节点，只输出节点编号。
答案：42
```

编号由生成样本时的节点索引提供。连续地图条件的输入文字不提前包含待报告的节点编号，避免直接抄答案。建议当前／目标两类提问均衡采样，只有答案 token 计算交叉熵损失；损失经过冻结 LLM 传回接口。节点编号格式、模板数量、采样比例和训练预算待具体确认。

该方案直接检验：仅做状态报告适配后，是否还能保留距离结构，并把地图用于未训练的一步动作选择。报告准确率是接口学会读取状态的基础诊断。

## 两项主要评测及建议判定

| 用户确定的任务 | 建议实现 | 回答的问题 |
| --- | --- | --- |
| 远近性质保持 | 在同一图、同一批节点对上，比较图最短距离与原始 Q 表示距离、适配后表示距离的秩相关 | 原地图与适配后的表示是否保留整体远近关系 |
| 一步动作选择 | 给定当前状态和目标，输出一个下一节点；检查是否合法，且是否缩短到目标的图距离 | 只训练报告后，LLM 是否会用地图选择更接近目标的一步 |

**远近评测已确认主测适配器输出。** 比较原始 `q_i` 和适配后 `z_i = adapter(q_i)` 各自与图最短距离的关系，回答实际输入 LLM 的地图是否保留远近结构。若每状态输出多个 token，建议按固定顺序展平为一个向量，并在所有节点上使用相同角色标识后计算距离。建议使用与 Step 1 一致的欧氏距离及 Spearman 秩相关，补充适配器训练前后的变化。多 token 的处理和具体指标待确认。LLM 内部 hidden state 保留为可选补充，需要另行指定层、读取位置与固定上下文；不作为本轮已确认的主测对象。

**一步动作建议判定。** 对当前节点 `u`、目标 `g`、输出节点 `v`，成功条件为 `v` 与 `u` 相邻，且 `d(v,g) < d(u,g)`；`d` 由图最短路计算，只供裁判使用。当前无权图中，这等价于走出一条最短路径的第一步。多个邻居满足条件时都算正确，不要求匹配唯一标签。报告格式有效率、合法率，以及在全部样本上“合法且接近目标”的比例。建议主测试集排除 `u=g`；目标已达的停止判断另列。

**一步动作的输入已确认采用第一种。** 适配器分别转换当前状态和目标状态，LLM 根据这两个表示及通用任务说明生成下一节点编号。系统不提供当前节点的邻居列表、候选状态表示、动作向量、全图邻接表或方向分数；也不在生成时用真实合法邻居过滤输出。通用任务说明可解释“一步只能沿图中一条边移动”，节点编号格式与取值范围待具体确定。

输入示意：

```text
当前状态：[adapter(s)]
目标状态：[adapter(s*)]
一次移动只能沿图中的一条边到达相邻节点。
请选择一个合法且更接近目标的下一节点，输出其编号。
```

分工明确为：适配器提供表示，LLM 生成判断，环境裁判在生成后核对输出节点是否存在、是否相邻、是否接近目标。相邻性由裁判检查，不由裁判提前筛选。该设置同时测试合法性判断和方向选择，需分别记录合法率与“合法且接近目标”的成功率。只有状态报告训练能否支持这两项能力，是本轮要观察的结果。

其他输入方案保留为后续诊断候选，不纳入本轮首版：

| 一步动作输入方案 | 给模型的信息 | 能重点观察什么 |
| --- | --- | --- |
| **仅当前与目标，已确认** | 当前、目标的适配向量，要求输出下一节点 | LLM 自行判断合法性与方向 |
| 加合法候选 ID，后续候选 | 上述输入，加真实邻居的节点编号列表 | 已知合法范围时，模型能否联系编号与地图关系 |
| 加合法候选 ID 与表示，后续候选 | 当前、目标的适配向量，加各真实邻居的编号及适配向量 | 已知合法范围及候选表示时，模型能否作方向选择 |

提供候选时，最终排序仍由 LLM 完成，但系统额外给出了合法范围或候选状态。用户本轮选择让 LLM 同时承担这些判断，因此首版保留两个状态输入，报告训练也沿用当前／目标两类状态槽位。

## 最小对照与数据划分

已确认的适配器比较为 Linear 与两层 MLP，两者均只获得当前与目标的表示及相同任务说明。另建议在同一固定图上加入文字状态接口，输入当前／目标节点身份与相同规则，不额外提供邻居或全图结构；这比较的是学习到的连续表示与纯节点文字输入。未训练的随机节点编码也是候选对照，可帮助观察学到的转移／距离结构是否比单纯节点身份更有用；这两类额外对照的具体训练方式和首轮纳入范围待讨论。

建议所有节点参与状态报告训练，保留未用于适配训练的当前／目标组合用于报告与一步动作评测。训练与测试均可出现单个节点，但节点对不重叠；这检验同图的新组合。一步动作答案、最短距离和完整路径不进入状态报告训练。所有单节点身份均可在训练中出现，因此报告识别首先是接口可读性检查，不称为未见节点泛化。

首版动作输出为下一节点编号，不向 LLM 输入候选动作或候选节点。BFS 距离和真实邻接表只用于生成后的评测；无效编号、非法移动及合法但未接近目标分别记录，不把输出自动纠正为合法节点。

在内部规划状态连续累加时，最近节点检索先只作诊断，不默认为每步纠正状态。若采用真实观测后重新编码，则明确是另一个更新时机。两种方式都可研究，首轮应选定一种以便解释结果。
