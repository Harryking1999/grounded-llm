# Step 2 调研与讨论：让冻结 LLM 使用认知地图

定位：基于当前图实验的讨论稿；下面的接入选择和实验安排是建议，尚未启动适配训练。当前进度仍统一见[项目状态页](../../docs/PROJECT_STATUS_AND_TODO.md)。

## 从现有结果出发

Step 1 已得到能准确执行一步加法转移、状态彼此可区分的 Q/V。不同维度和更新方法都可用，因此 Step 2 可以直接研究：**将状态向量接入冻结 LLM 后，模型能否读懂状态，并把这种理解用于动作选择？**

建议先沿用局部更新的 1000 维地图衔接已有结果，以 128 维作为紧凑方案候选。本轮 2048 维的距离相关收益较小，暂不需要围绕维度继续展开。这里的推荐只针对首轮图接口试点。

## 初步文献线索

| 参考 | 已核对的相关内容 | 对当前实验的启发 |
| --- | --- | --- |
| [PaLM-E](https://arxiv.org/abs/2303.03378) | 把连续状态估计、视觉和文字编码交错输入语言模型 | 将当前状态和目标状态投影为连续输入向量，是可借鉴的接入方式 |
| [BLIP-2](https://arxiv.org/abs/2301.12597) | 冻结图像编码器与 LLM，通过可训练的 Querying Transformer 分两阶段连接两端 | 冻结两端、训练中间接口有先例；可先尝试简单投影，再根据效果判断是否需要查询模块 |

这是针对接口思路的初步调研，已核对两篇论文的摘要；具体层结构和训练细节留到接入方案确定后精读。这些工作支持尝试连续接口，本项目中“报告适配能否迁移到图规划”仍由自己的实验回答。

## 建议的第一版接法

先冻结已训练 Q/V 和 LLM，只训练小型 MLP 适配器，将 `q_current`、`q_goal` 映射到 LLM 的输入嵌入空间。当前／目标分别标识；生成一个确定动作后，按 `q_next = q_current + v_action` 追加下一状态，再继续同一序列。训练损失从冻结 LLM 反传到适配器，LLM 参数本身不更新。

输入层状态 tokens 最便于沿用现有[状态接口试点](../state_interface_pilot/README.md)的思路。cross-attention memory 可作为后续选项；当前没有必要同时实现多条接口路线。积木已经讨论过每状态 1／2／4 个向量，但图接口的数量仍待讨论，不自动继承为正式配置。

## 适配训练究竟教什么

建议先用“向量 → 节点 ID”的状态报告验证接口接通，再决定状态关系报告的内容。图中节点没有自然语义，节点 ID 报告主要解决向量与名称的对应；让 LLM 使用转移和目标关系，需要更明确的关系任务。

| 内容 | 首轮建议 | 作用 |
| --- | --- | --- |
| 状态报告 | 从当前／目标向量报告对应节点 ID | 检查接口是否可读 |
| 状态关系报告 | 候选为同一节点判断、是否直接相邻；标签来自已探索图 | 建立状态间关系的语言表达；具体组合待讨论 |
| 动作后果与一步选择 | 报告适配之后单独评测 | 观察读懂状态能否迁移到动作相关问题 |
| 多步路径 | 留到后续 rollout 检验 | 观察是否能组合使用地图 |

首轮建议保留“不训练专家路线”的原思路。若希望把动作后果或图最短距离加入监督，应先明确这是额外教给模型的信息，以及对应的训练对照。

## 最小对照与数据划分

先在同一固定图上比较连续地图接口与文字状态接口，两者获得相同的节点／目标、候选信息、报告样本和动作预算。可增加一个未训练的随机节点编码对照，帮助观察学到的转移／距离结构是否比单纯节点身份更有用。

所有节点可以参与状态报告训练；状态关系训练和最终评测按节点对分开，最终路径不进入训练。这样先检验同图的新组合，不强行引入跨图泛化。报告识别、一步动作、最终到达分别记录。

图接口还需确定动作信息的输入方式：只给动作 ID，还是同时给候选动作向量／候选节点向量。建议明确写出每个候选携带的信息，并在文字对照中给出对应信息。若提供真实合法候选，两边都提供；BFS 距离只用于裁判。

在内部规划状态连续累加时，最近节点检索先只作诊断，不默认为每步纠正状态。若采用真实观测后重新编码，则明确是另一个更新时机。两种方式都可研究，首轮应选定一种以便解释结果。

## 接下来讨论的三个选择

1. 首轮是否冻结 Q/V，只训练接口？建议先这样做，方便直接观察地图是否被 LLM 使用；联合微调留作有依据的后续尝试。
2. 图状态关系报告具体教什么？建议从节点身份与直接关系开始，讨论是否需要动作后果监督。
3. 先从哪张图和哪个接口起步？建议单张小图确认报告可学习，再转到已有较大图；首轮沿用 Qwen3-8B 非 thinking 和追加状态输入的已有思路，具体规模与向量数在实施前确定。

完成讨论后再形成可运行配置，先做一个能看到报告损失与识别准确率变化的小型训练试点。
