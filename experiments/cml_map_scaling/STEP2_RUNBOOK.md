# Previous approach：Step 2 地图到连续 token 的接口方案

本文封存此前的 roadmap／Q → Adapter → LLM 连续 state token 路线，保留原设计和配置供复现；不再作为当前执行方案，也不在本目录加入新的显式 roadmap 接口。当前方向见[研究简述](../../docs/RESEARCH_BRIEF.md)和[项目状态页](../../docs/PROJECT_STATUS_AND_TODO.md)。

**目标：只用状态报告训练接口，再检验它能否支持一步动作选择。** 首轮比较 Linear 与 MLP；多 token、打乱编号和少量动作监督均留作后续解决方案。

以下是当时的实施规格；原始想法与会议批注保留在 [STEP2_DISCUSSION.md](STEP2_DISCUSSION.md)。参数和精确 prompt 统一放在 [configs/step2.json](configs/step2.json)。图 Step 2 runner 尚未实现。

## 1. 模型与信息流

首轮使用 **[Qwen/Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)**。这是仅支持非 thinking 的 Instruct 模型，使用原生聊天模板，无需设置 `enable_thinking=False`。模型和 tokenizer 的 revision 已锁定在配置中。

地图使用 Step 1 的 `local1000 / official32` 最终 Q/V。每个节点的向量经共享 Adapter 转为一个连续 token，放入 LLM 的**输入嵌入层**。

```text
程序保存当前节点 u 和目标节点 g
              ↓
读取 q_u、q_g → 共享 Adapter → 当前／目标两个状态 token
              ↓
与文字邻接表、问题一起输入冻结的 Qwen Instruct
              ↓
输出一个节点编号 → 外部裁判判分
```

| 模块 | 本轮设置 |
| --- | --- |
| Q/V 地图 | 冻结；Q 提供节点向量，V 本轮不参与状态推进 |
| Linear | 地图维度 → LLM 嵌入维度，带偏置 |
| MLP | 地图维度 → 隐藏层 → GELU → LLM 嵌入维度，带偏置 |
| LLM | 冻结全部参数，BF16；梯度仍经过 LLM 回传给 Adapter |
| 状态管理 | 程序持有真实节点；模型的报告只用于评测 |

所有节点、当前和目标角色共用同一套 Adapter。输入统一除以冻结 Q 的全元素 RMS，不逐节点归一化；Adapter 使用 FP32 参数，输出转为模型精度。状态向量直接插入序列，不打印为数字文本。

每题只生成一次答案。报告题与动作题独立调用，动作题不会得到模型先前的报告或裁判反馈。后续多步执行时，程序检查动作 `(u,v)` 合法后令 `u=v`，重新读取 `q_v`；本轮先完成独立单步评测。

## 2. 跑哪些条件

| 条件 | 训练内容 | 要回答的问题 |
| --- | --- | --- |
| `linear_report` | Linear＋状态报告 | 最简单接口能否读出状态、支持动作？ |
| `mlp_report` | MLP＋状态报告 | 非线性接口是否更有效？ |
| `text_control` | 不训练；直接提供正确的当前／目标节点 ID | 相同图信息下，文字状态的表现如何？ |

Linear 和 MLP 分别从各自初始化开始，只训练当前／目标两类状态报告，使用相同划分、报告样本顺序和训练预算。**一步动作选择只在训练后评测，不参与训练或选模。**

全部条件都提供同一份完整文字邻接表。文字对照只把两个连续状态槽换成正确节点 ID，其余模板与生成设置相同。

## 3. 数据与 Prompt

**“全量报告”指覆盖所有节点，并完整使用训练划分中的报告样本。** 验证和测试保留未见的节点组合。

以无序节点对划分数据，同一对的两个方向放在同一集合；每个方向生成当前／目标两类报告。按配置得到：

| 划分 | 无序节点对 | 报告样本 | 动作评测题 |
| --- | ---: | ---: | ---: |
| 训练 | 396 | 1,584 | — |
| 验证 | 50 | 200 | — |
| 测试 | 50 | 200 | 100 |

划分方法：枚举字典序 `u<g` 的节点对，用配置指定的 NumPy RNG 和 seed 打乱，再依次切分。保存实际划分，检查训练覆盖全部节点、各集合无交集。报告样本按“节点对 → 两个方向 → 当前／目标”展开后逐 epoch 洗牌。

报告题与训练后的动作评测共用以下结构；精确英文模板由配置直接读取：

```text
图规则与完整邻接表
Current node: [Adapter(q_u)]
Goal node: [Adapter(q_g)]

训练／验证问题：报告当前节点，或报告目标节点
训练后评测另问：选择一步后更接近目标的节点
回答：只输出节点编号
```

邻接表按节点及邻居编号升序排列。不提供最短距离、正确候选或参考路径。训练和验证使用固定模板；测试再用一份预先固定的改写模板，交换当前／目标段落顺序并改写问句，观察呈现变化后的表现。

## 4. 怎么训练

### 4.1 输入和正确答案

每条样本只问一个问题：报告当前节点时，正确答案为 `u`；报告目标节点时，正确答案为 `g`。将正确编号按 tokenizer 编码，再追加原生回答结束标记，得到答案序列 `y`。

训练采用 teacher forcing：预测答案的下一个 token 时，前面提供的是**正确答案 token**。评测则让模型自己完整生成编号。

### 4.2 哪些位置计算 loss

| 序列部分 | 训练标签 |
| --- | --- |
| system、邻接表、问题、当前／目标状态槽、assistant 回答前缀 | `-100`，不计入 loss |
| 正确节点编号的全部 token | 对应的真实 token ID，逐个计算交叉熵 |
| 回答结束标记 | 原生结束 token ID，计算交叉熵 |
| 为对齐批量添加的 padding | `-100`，不计入 loss |

使用因果语言模型的下一 token 对齐：位置 `t-1` 的输出预测位置 `t` 的标签，对齐只做一次。**答案前最后一个位置的输出负责预测答案第一个 token**；它虽然位于输入部分，仍会对这个答案 token 产生损失。

### 4.3 loss 的准确计算

首轮只有报告损失：**`L = L_report`**。它就是答案序列的 SFT 交叉熵，不回归节点编号的数值差，也没有动作或几何辅助项。

$L_{\mathrm{report}}(\theta)=-\frac{1}{B}\sum_{i=1}^{B}\frac{1}{T_i}\sum_{j=1}^{T_i}\log p_{\phi}(y_{i,j}\mid x_i(\theta),y_{i,<j}).$

- `B`：本次优化器更新使用的报告样本数；当前／目标报告在数据中等量。
- `T_i`：第 `i` 条正确答案的 token 数，**包含结束标记**，不包含 prompt 和 padding。
- `x_i(θ)`：文字 prompt 与 Adapter 生成的状态 token；`θ` 是待训练的 Adapter 参数。
- `φ`：冻结的 LLM 参数；`p_φ` 是它给正确答案 token 分配的概率，`log` 为自然对数。

计算顺序是：**逐 token 求负对数概率 → 每条答案内部平均 → 批量中各条答案平均。** 这样每条样本等权，不会因为某个编号被分成更多 token 就自动获得更大权重。实现时保留逐 token 损失、应用标签遮罩，再完成这两次平均。

例如，假设某个编号被切成 `a、b` 两个 token，完整监督序列就是 `[a, b, 结束标记]`。依次预测 `a`、给定正确 `a` 后预测 `b`、给定正确 `a,b` 后预测结束；若三个正确 token 的概率为 `0.8、0.5、0.9`，该样本损失为 `−(ln 0.8 + ln 0.5 + ln 0.9) / 3 ≈ 0.341`。实际切分以 tokenizer 为准。

### 4.4 反传与选模

梯度路径为：**报告 loss → 冻结 LLM 的计算 → 状态 token → Adapter 参数**。LLM 和 Q/V 不更新；LLM 保持 eval 模式，但前向须保留通向 Adapter 的梯度，不能整体用 `no_grad` 或 detach 状态 token。

一个优化器步骤只处理报告批量。微批次按显存设置；若本次有效批量有 `B` 条样本，某微批有 `b` 条，将其样本平均 loss 乘以 `b/B` 后累积梯度，最后统一裁剪并更新 Adapter。最后不足一批时，`B` 使用实际样本数。学习率、批量和轮数见配置。

每轮验证，按以下顺序选 checkpoint：**报告自由生成准确率最高 → 报告损失最低 → 轮次最早**。保存初始、选中、固定最终轮权重。动作测试和几何指标不参与选模；选中与最终轮结果均汇报。

## 5. 怎么评测

动作评测对 `(u,g)` 接受所有合法且接近目标的下一节点：$S(u,g)=\{v:(u,v)\in E,\ d(v,g)<d(u,g)\}$，其中 `d` 是图最短距离。这些动作答案仅供裁判判分，不进入训练。

使用贪心生成，每题一次。答案去除原生结束标记和首尾空白后，必须完整匹配一个规范十进制编号，再检查范围；解释句、多个编号、JSON 均记格式错误。保留原始输出，错误不自动修复。

| 评测 | 指标与判据 |
| --- | --- |
| 状态报告 | 当前正确率、目标正确率、同一有序对的两条报告均正确率 |
| 一步动作 | 编号有效率、动作合法率、一步成功率；成功要求 `v ∈ S(u,g)` |
| Prompt 变化 | 原模板与改写模板分别统计，同一语义题两次均正确的比例另报 |
| 状态使用 | 交换当前／目标嵌入，观察输出是否跟随新状态，并按交换后的标签判分 |
| 表示几何 | 图距离与表示欧氏距离的 Spearman 秩相关；比较原 Q、初始／选中／最终 Adapter 输出 |

各准确率的分母都是该条件下的全部题目，格式错误也在分母中。动作结果按图距离再分组，另看“两条状态报告均正确”的那些题上动作是否成功。几何统计覆盖全图不同无序节点对；并列距离采用平均秩，常量导致未定义时记为 null。

交换嵌入后，语义任务由 `(u,g)` 变为 `(g,u)`；可以复用测试集反方向的输出。分别记录输出变化、按原标签和新标签判分的结果。动作没变不一定说明没用状态，因为同一动作可能对两个方向都成立。

所有训练与选模完成后，再统一测试各条件，保留未训练 Adapter 与准确文字状态的成绩作参照。

## 7. 看完结果后怎么判断

- **报告好、动作差**：接口能读，问题在任务使用；先分析失败题，再考虑多 token 或远近关系诊断。
- **与文字状态相当**：连续接口可用，当前任务尚未体现额外收益。
- **几何保留但动作差**：保留远近关系不保证 LLM 会使用它。

本轮文字图完整公开，模型可能先读出编号，再利用文字图选动作。因此动作成功和距离相关都不能单独证明它使用了地图几何。

以下三项均为**首轮结果出来后再考虑的解决方案**，不放入当前训练：

| 后续方案 | 想解决的问题 |
| --- | --- |
| 每个状态使用多个 token | 单 token 接口可能难以承载或分离所需信息 |
| roadmap 保留图结构，prompt 给出编号规则并打乱编号训练 | 检查并减少对固定节点编号映射的依赖 |
| 加入少量一步动作选择监督 | 报告可读，但状态信息未能有效支持动作选择 |

具体采用哪一项及其训练设置，依据首轮失败情况再确定。
