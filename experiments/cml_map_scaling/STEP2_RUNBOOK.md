# Step 2 Runbook：地图接口训练与一步动作评测

**目标：让冻结的 Qwen Instruct 读取地图状态，并检验这些状态能否支持一步动作选择。** 先做状态报告训练，再比较加入少量动作监督的效果。

本文用于实施，原始想法与会议批注保留在 [STEP2_DISCUSSION.md](STEP2_DISCUSSION.md)。参数和精确 prompt 统一放在 [configs/step2.json](configs/step2.json)。目前尚未实现 Step 2 runner；本轮交付是执行方案。

## 1. 模型与信息流

首轮使用 **[Qwen/Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)**。这是仅支持非 thinking 的 Instruct 模型，使用原生聊天模板，无需设置 `enable_thinking=False`。模型和 tokenizer 的 revision 已锁定在配置中。

地图使用 Step 1 的 `local1000 / official32` 最终 Q/V。每个节点的向量经共享 Adapter 转为一个连续 token，放入 LLM 的**输入嵌入层**。

```text
程序保存当前节点 u 和目标节点 g
              ↓
读取 q_u、q_g → 共享 Adapter → 当前／目标两个状态 token
              ↓
与文字邻接表、问题一起输入冻结的 Qwen Instruct
              ↓
输出一个节点编号 → 外部裁判判分
```

| 模块 | 本轮设置 |
| --- | --- |
| Q/V 地图 | 冻结；Q 提供节点向量，V 本轮不参与状态推进 |
| Linear | 地图维度 → LLM 嵌入维度，带偏置 |
| MLP | 地图维度 → 隐藏层 → GELU → LLM 嵌入维度，带偏置 |
| LLM | 冻结全部参数，BF16；梯度仍经过 LLM 回传给 Adapter |
| 状态管理 | 程序持有真实节点；模型的报告只用于评测 |

所有节点、当前和目标角色共用同一套 Adapter。输入统一除以冻结 Q 的全元素 RMS，不逐节点归一化；Adapter 使用 FP32 参数，输出转为模型精度。状态向量直接插入序列，不打印为数字文本。

每题只生成一次答案。报告题与动作题独立调用，动作题不会得到模型先前的报告或裁判反馈。后续多步执行时，程序检查动作 `(u,v)` 合法后令 `u=v`，重新读取 `q_v`；本轮先完成独立单步评测。

## 2. 跑哪些条件

| 条件 | 训练内容 | 要回答的问题 |
| --- | --- | --- |
| `linear_report` | Linear＋状态报告 | 最简单接口能否读出状态、支持动作？ |
| `mlp_report` | MLP＋状态报告 | 非线性接口是否更有效？ |
| `linear_joint` | Linear＋报告＋少量动作监督 | 任务监督是否帮助使用接口？ |
| `mlp_joint` | MLP＋报告＋少量动作监督 | 同上，比较接口形式 |
| `text_control` | 不训练；直接提供正确的当前／目标节点 ID | 相同图信息下，文字状态的表现如何？ |

先做两个报告条件，再做两个联合条件。**联合条件从对应架构的同一份初始权重开始，不从报告 checkpoint 续训。** 四组使用相同划分、报告样本顺序和报告训练预算；联合组额外计算动作损失，单独记录新增计算量。

全部条件都提供同一份完整文字邻接表。文字对照只把两个连续状态槽换成正确节点 ID，其余模板与生成设置相同。

## 3. 数据与 Prompt

**“全量报告”指覆盖所有节点，并完整使用训练划分中的报告样本。** 验证和测试保留未见的节点组合。

以无序节点对划分数据，同一对的两个方向放在同一集合；每个方向生成当前／目标两类报告。按配置得到：

| 划分 | 无序节点对 | 报告样本 | 有序动作题 |
| --- | ---: | ---: | ---: |
| 训练 | 396 | 1,584 | 792 |
| 验证 | 50 | 200 | 100 |
| 测试 | 50 | 200 | 100 |

划分方法：枚举字典序 `u<g` 的节点对，用配置指定的 NumPy RNG 和 seed 打乱，再依次切分。保存实际划分，检查训练覆盖全部节点、各集合无交集。报告样本按“节点对 → 两个方向 → 当前／目标”展开后逐 epoch 洗牌。

三类问题共用以下结构；精确英文模板由配置直接读取：

```text
图规则与完整邻接表
Current node: [Adapter(q_u)]
Goal node: [Adapter(q_g)]

问题三选一：报告当前节点／报告目标节点／选择一步后更接近目标的节点
回答：只输出节点编号
```

邻接表按节点及邻居编号升序排列。不提供最短距离、正确候选或参考路径。训练和验证使用固定模板；测试再用一份预先固定的改写模板，交换当前／目标段落顺序并改写问句，观察呈现变化后的表现。

## 4. 怎么训练

状态报告答案是对应节点 ID。动作监督答案取自：

\[
S(u,g)=\{v:(u,v)\in E,\ d(v,g)<d(u,g)\}.
\]

`d` 是图最短距离。训练固定选择集合中编号最小的节点作为答案，评测接受集合中的任意节点。

损失采用 **SFT 的逐 token 交叉熵**，适用于多 token 编号。只监督答案及回答结束标记，屏蔽 prompt 和状态槽。先对每条答案按 token 数平均，再对任务批量按样本平均：

\[
L=L_{report}+\lambda_{action}L_{action}.
\]

每个优化器步骤处理一个报告批量；联合组额外处理一个动作小批量。动作样本只从训练节点对中抽取，按独立随机流打乱、循环、不放回地消耗。批量、动作权重、学习率及轮数见配置。

微批次按显存设置，使用梯度累积保持有效批量。最后不足一批的样本仍训练，按实际样本数计算均值。LLM 保持 eval 模式，但训练前向必须保留到 Adapter 的梯度。

每轮验证，按以下顺序选 checkpoint：**报告自由生成准确率最高 → 报告损失最低 → 轮次最早**。保存初始、选中、固定最终轮权重。动作测试和几何指标不参与选模；选中与最终轮结果均汇报。

## 5. 怎么评测

使用贪心生成，每题一次。答案去除原生结束标记和首尾空白后，必须完整匹配一个规范十进制编号，再检查范围；解释句、多个编号、JSON 均记格式错误。保留原始输出，错误不自动修复。

| 评测 | 指标与判据 |
| --- | --- |
| 状态报告 | 当前正确率、目标正确率、同一有序对的两条报告均正确率 |
| 一步动作 | 编号有效率、动作合法率、一步成功率；成功要求 `v ∈ S(u,g)` |
| Prompt 变化 | 原模板与改写模板分别统计，同一语义题两次均正确的比例另报 |
| 状态使用 | 交换当前／目标嵌入，观察输出是否跟随新状态，并按交换后的标签判分 |
| 表示几何 | 图距离与表示欧氏距离的 Spearman 秩相关；比较原 Q、初始／选中／最终 Adapter 输出 |

各准确率的分母都是该条件下的全部题目，格式错误也在分母中。动作结果按图距离再分组，另看“两条状态报告均正确”的那些题上动作是否成功。几何统计覆盖全图不同无序节点对；并列距离采用平均秩，常量导致未定义时记为 null。

交换嵌入后，语义任务由 `(u,g)` 变为 `(g,u)`；可以复用测试集反方向的输出。分别记录输出变化、按原标签和新标签判分的结果。动作没变不一定说明没用状态，因为同一动作可能对两个方向都成立。

所有训练与选模完成后，再统一测试各条件，保留未训练 Adapter 与准确文字状态的成绩作参照。

## 6. 执行顺序

| 步骤 | 做什么 | 完成标志 |
| --- | --- | --- |
| 1. 准备输入 | 绑定 Step 1 的 `map.npz`、`inputs.npz`；加载指定模型及 tokenizer | Q 按 `q[node_id, :]` 读取，图编号、邻接和距离一致；记录资产来源与环境版本 |
| 2. 实现数据与裁判 | 生成划分、模板、标签及判分逻辑 | 节点覆盖正确，多个最优后继均可得分，非法动作能被区分 |
| 3. 打通小批量 | 实现连续 token 插入、答案遮罩、反传及生成 | Adapter 有有限非零梯度，冻结参数无梯度；多 token 答案处理正确，固定小批损失下降 |
| 4. 确定运行预算 | 测量显存与每步耗时，设置微批次 | 有效批量保持一致，源码与配置提交，补上实际运行命令 |
| 5. 训练 | 报告条件 → 联合条件；正式训练重新初始化 | 保存训练曲线、每轮验证及选中／最终权重 |
| 6. 评测汇报 | 文字对照、状态报告、动作、模板变化和几何分析 | 保存逐题输出与判分，汇总所有条件 |

正式 Step 1 资产来源为配置指定的 `local1000/official32`。当前本地另有 `runs/cml_roadmap_replay/official32/` 可用于开发，其重放来源见 `runs/cml_roadmap_replay/replay.json`；正式运行记录实际采用哪份地图。

产物放在配置指定的 `runs/` 目录下，每次运行独立保存：实际配置与环境版本、数据划分、Adapter 权重、训练／验证曲线、逐题原始输出与判分、几何统计和耗时显存。逐题记录至少包括条件、checkpoint、模板、起终点、任务、输出、解析结果及各项判定。

最终结果按条件和模板列出报告准确率、动作合法率、一步成功率、距离相关和训练成本，所有比例附成功数／总数。执行结果更新到项目状态页及实验结果摘要。

## 7. 看完结果后怎么判断

- **报告好、动作差**：接口能读，问题在任务使用；先分析失败题，再考虑多 token 或远近关系诊断。
- **联合训练后改善**：少量动作监督有效；与只报告训练的迁移结果分开说明。
- **与文字状态相当**：连续接口可用，当前任务尚未体现额外收益。
- **几何保留但动作差**：保留远近关系不保证 LLM 会使用它。

本轮文字图完整公开，模型可能先读出编号，再利用文字图选动作。因此动作成功和距离相关都不能单独证明它使用了地图几何。后续是否去掉文字图、重新编号或扩展多 token，应由本轮具体结果决定。
