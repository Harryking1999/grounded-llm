# 地图读取接口：寻路与积木共同方案

本方案以[原始飞书方案](https://zcnhpsd26tyi.feishu.cn/wiki/ZNNSwpIo0iHwMgk7mk7coBA3nzb)和用户在旧 DESIGN 中的 `==...==` 修改为依据。会议自动总结只作线索，不代替这些决定。两项任务都实现，正式参数分别见 [寻路配置](configs/pilot_path256.json)和[积木配置](configs/pilot_blocks.json)。

## 一、研究目标

冻结已训练的 Q-map 和 Qwen2.5-1.5B-Instruct，**分别为寻路和积木训练各自的**投影、角色／编号嵌入、门控 cross-attention，让模型从当前状态、目标、全部合法后继的地图向量中读取远近关系，并在逐步环境反馈中选动作、判断终止。两项共用架构和训练代码，接口参数与 checkpoint 不共用。积木的状态更抽象，动作组合可能进入死局，不能因为这个差异省去寻路。两项地图已有可用的远近信号，但这并不保证每次贪心都成功，更不等于接口已经学会规划。

## 二、两项任务的数据与 Q

| | 寻路 | 积木 |
| --- | --- | --- |
| 状态与目标 | 256 节点无向图上的当前节点和目标节点 | 10×10 二值棋盘的当前状态和可达目标棋盘 |
| 合法动作 | 邻边，且不重复访问已走节点 | 按原八形状规则移除当前占据格 |
| 地图后继 | 已有 Q/V 的 `Q(current)+V(action)` | 共享冻结 `BoardEncoder` 对真实合法后继编码 `Q(T(current,action))`；位移可写为两次 Q 之差 |
| 远近度量 | Q/V 空间的欧氏距离 | 共享积木地图原有的 `directed_sum` 有向距离 |
| 离线真值 | 图最短步数用于分题与评测 | 精确求解器用于长题选择与可达性核验 |

地图原始向量输入读取接口，**不把距离标量、排序、已选动作或离线真值放进用户提示或地图槽**。标签在冻结 Q 空间中计算；P 的训练可能改变投影后几何，实验需要检验模型能否学到原空间的相对远近，不能预设它天然保距。

寻路使用现有五张图和对应 Q/V。前四图生成训练、验证；第五图完全留出。原五图题集的全部起终点及反向对不进训练／验证。训练／验证只取真实最短长度为 10 的题，每图 64／16 条，四图合计 256 条训练、64 条验证；不另采短题或起点即目标题。这是覆盖关系：一条十步题途经离目标更近的各个状态，并以到达后的终止轮结束，短题的逐轮判断已包含在内。跨图 Q 空间未必对齐，四图共训是否能读懂第五图是待检验的问题。若失败，先在原图内对照定位，不能把失败直接解释成读取接口无效。

积木使用共享棋盘编码器 `tree_1000_132f5a1/best.pt`。从 1,000 张八块初始棋盘各取 8 组可达起终点，整题构成 SFT；长题用真实最短步数筛选，数量不足如实报告。测试按**全部 SFT 的当前、目标、候选后继状态**判定见／未见，分“起终点均未见”“起点见、终点未见”“起点未见、终点见”三组；地图 Q 自身的训练覆盖单独记录。示范只收冻结地图贪心完成的题，地图贪心失败量需报告；测试题不按地图成功与否筛选。初始即达成和到达后终止仍需模型回答。

## 三、共用文字协议

两项任务的初始英文提示都先说清“找可行解，尽可能短；先保证到达，再减少步数”，后接各自规则、初始状态和目标。寻路给邻接表，积木给形状及棋盘。每轮 `[Environment update]` 只给**实际当前状态、已执行的实际动作日志、随机编号的合法候选**和编号提醒。不要在环境更新里重复要求排序、总结或输出格式；这些由 SFT 答案示范。

未完成时，assistant 用同一模板输出：当前未到目标；`Map-distance ranking to the goal, closest to farthest: ...`，排序必须包括 `current` 和所有候选，并列写 `=`；逐个说明候选相对当前更近、更远或相同；说明选择最小地图距离的候选；最后输出 `<action>i</action>`。**不输出具体距离数值。**“距离”是冻结 Q-map 的度量，不能冒充环境最短步数。终止时报告当前状态符合目标、实际动作序列、步数总结和 `<done/>`。具体示范由 [prompt.py](src/prompt.py)、[blocks_prompt.py](src/blocks_prompt.py)、[sft.py](src/sft.py)和 [text.py](src/text.py)共用实现。

执行器只按当轮编号执行合法动作，然后从真实环境状态更新文字与地图。非法编号、误报完成、到达后继续行动、预算耗尽分别记录。历史动作日志用稳定语义，不用已失效的候选编号。第一版沿用后续确认的**方案 A**：整题一次 SFT，旧 token 读旧轮地图，新增 token 读本轮地图；普通因果 self-attention 保留历史文字。推理可重算整段前缀，但仍保持上述逐轮绑定。

## 四、共用架构与训练

每轮地图槽为 `[current, goal, successor_1, …, successor_k]`。**每个任务内部**用一个可训练投影 P 处理其 Q 向量，与角色、候选编号嵌入拼接，再映射到语言隐层维度。编号作用类似位置编码，让地图槽与本轮文字候选对应；它不表示远近。Qwen 各解码层之前加入四头、每头 64 维的 cross-attention，并以零初始化门控的残差注入。每项任务自己的 Q-map 与语言模型底座冻结；该任务的 P、组合层、嵌入、cross-attention 和门控在该任务的一次 SFT 中联合更新。候选数可变，padding 槽屏蔽；不同题和不同轮的地图不可串读。

两个任务使用同一 [train.py](src/train.py)、地图 collator、assistant-only next-token 交叉熵、优化器与 checkpoint 机制，**分别从新初始化的接口开始训练，分别保存 checkpoint 和评测结果**。**每道完整题是一个样本，多个完整题组成实际 batch，一次前向、反向和更新；不按行动轮次切样本，也不做“累计八条轨迹才更新”。**实际 batch 按显存测量，各任务可因文本和候选数量不同而取不同值。超长题明确报错，不能截掉终止段。正式设置只存于各自配置，运行产物存 Git 外。

## 五、评测与解释

两项都测闭环到达率、正确终止、非法编号、预算耗尽、最优长度及生成成本；积木额外按三组未见状态报告，寻路按图及长度报告。环境裁判和离线最短解只用于造题／评测，不进入模型决策。地图贪心、无地图小模型以及已有文字地图结果作为不同用途的基线，比较时须对齐题、提示、预算与地图训练覆盖。排序正确、动作合法和最终到达分别报告，避免把任一代理指标当成规划机制证据。
