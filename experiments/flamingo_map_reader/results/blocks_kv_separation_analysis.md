# 积木读取接口分析：是否恢复 K/V 解耦

讨论稿，2026-10-08。分析对象是当前融合 FFN 小 batch 运行的 3.5 epoch 全量结果，以及旧分离 K/V 运行的已有输出。**当前建议：继续既定训练与四卡评测，把恢复 K/V 解耦列为后续对照候选，暂不修改运行中的架构、数据或优化设置。**是否恢复由后续讨论和匹配证据决定，本报告不是变更决议。

## 1. 需要解释的现象

现在有两个不同的问题：新断点首轮选择较弱，以及 reference 总体成绩远高于自主 rollout。首轮尚无模型自身的先前回答，所以其低编号偏向不能归因于之前走错；后续两模式的差距则同时受到状态、历史和轮次构成影响。二者需要分别检验。

| 已有证据 | 计数／结果 | 能支持的判断 |
|---|---|---|
| 新模型首轮保持目标可达 | reference 245/510（48.0%）；rollout 256/510（50.2%） | 当前首轮动作弱，整体 reference 的 81.8% 不能代表起步能力 |
| 新模型首轮选择编号 1–3 | reference 400/510（78.4%）；rollout 399/510（78.2%） | 有很强的低编号选择偏向，且在自主历史形成前就存在 |
| 新任务首轮候选数 | 最少 20，中位数 58.5，最多 102 | 约 78% 不是仅由首轮候选很少造成；均匀随机选择 1–3 的逐题平均概率只有 5.4% |
| 旧模型约同更新数的首轮 rollout | step 49,000：581/1,000（58.1%） | 描述性成绩高于新 step 48,125 的 50.2%，但题目和训练条件不同 |
| 旧模型 final 首轮 rollout | step 245,000：703/1,000（70.3%） | 用户指出的旧首轮七十多确实存在；旧 final 多约五倍更新 |
| 旧模型的低编号选择 | step 49,000：71.0%；final：23.2% | 编号偏向也存在于旧解耦架构，且随旧训练推进减弱；它不是融合架构独有的证据 |
| 冻结地图首轮最优动作 | 465/510（91.2%）保持目标可达 | 地图关系在大多数首轮包含可用行动信号，模型没有可靠转化为选择 |
| rollout 首次致命动作 | 504 次全部合法；466 次当时地图最优仍可解 | 主问题先发生在动作选择，不能用后来的终止错误解释最初失去可达性 |

计数来自[分层证据](blocks_rollout_reference_diagnostic.json)及[全量结果报告](report.md)。引用的《新模型选择偏好》预览把 reference／rollout 的 399 与 400 对调了；本报告按原始记录更正，结论不受这一个计数差异影响。对“同更新数已证明架构更差”的说法也作限制：旧 validation 与新 test 的物理初始棋盘／目标组合交集为零，不能直接把差值当作架构净效应。

这些是第二性原理层面的统计约束。它们足以确定优先调查的环节，尚未识别内部因果机制。

## 2. 代码里实际改变了什么

核对 [memory.py](../src/memory.py)、[fusion.py](../src/fusion.py) 和 [train.py](../src/train.py) 后，两种结构可以写成以下形式。令 `Q_i` 是一个地图槽位的状态向量，`r_i` 是角色，`c_i` 是本轮候选编号；`l` 表示读取层。

**旧结构：地址作 K 输入，状态作 V 输入。**

```text
a_i = concat(role_embedding(r_i), id_embedding(c_i))
u_i = P(Q_i)
K_l,i = W_K,l LayerNorm(a_i)
V_l,i = W_V,l u_i
```

角色和编号提供地址，地图向量提供内容。旧主运行没有值分支 FFN；现有 `AddressedMapMemoryEncoder` 另外支持可选的值分支残差 FFN，不能把这项可选功能当成旧运行已使用的设置。

**当前结构：先融合，再分别投影为 K 和 V。**

```text
z_i = FFN(concat(Q_i, role_embedding(r_i), id_embedding(c_i)))
K_l,i = W_K,l LayerNorm(z_i)
V_l,i = W_V,l z_i
```

共享 FFN 对各槽位使用相同权重，输出供所有读取层使用；各层仍有独立的 K、V 投影。这里的融合不是令实际 attention 的 K 与 V 相等，也不是取消 K/V 两个投影矩阵。真正取消的是输入的信息分工：状态现在能影响地址，编号现在也能影响内容。输入维度与参数化也随之变化，不能只把改动描述为“加了一个 FFN”。正式尺寸和训练参数以[当前合同](../configs/blocks_ffn_failure_batch4.json)为准。

两种结构都用语言隐状态生成 attention query，读取结果再经过输出投影和 `tanh(gate)` 残差加入冻结语言模型。因此，值分支中去掉编号不等于整个模型无法根据编号猜测；语言提示和地址分支仍包含编号。

评测新启用的地图 K/V **缓存**是计算复用，与此处讨论的地址／状态分工是两件事；已有配对短测的回答和评分一致，缓存不能作为恢复解耦或融合能力改变的证据。

## 3. 为什么解耦值得作为候选

**假设 A：稳定地址减轻读取难度。**旧结构固定角色和编号后，K 不随该槽位的棋盘内容变化。当前结构的同一编号则可以随 `Q_i` 改变 K，模型必须在变化的特征中保持编号绑定。如果新模型不能稳定把语言中的“候选 j”对应到该地图槽位，几十个候选的首轮可能更容易出现关系错误。恢复地址分支可移除这条依赖。

这是假设，不是已经观测到的 attention 错址。首轮排序差，也可能来自正确取到向量后不会比较 current、goal 和候选关系；本次没有测量各层是否取到了 intended slot，也没有通过固定状态干预区分检索与比较。

**假设 B：编号进入 V 后提供了更直接的输出捷径。**当前 FFN 可把编号编码进值内容，读取后可能较容易驱动某些编号 token，而不必正确理解地图关系。旧结构对值分支规定只接收状态，因而限制了这条路径。首轮集中输出 1–3，与这个机制相容。

但旧 step 49,000 同样有 71% 的低编号选择，说明旧分工没有自动消除捷径。语言模型也可以靠文本、查询或地址偏向输出低编号。当前 78% 只是强输出偏向的证据，尚不能说明偏向经过哪条计算路径，更不能证明完全不使用地图。

**假设 C：共同特征承受不同学习目标的牵引。**当前同一 FFN 同时为寻址和内容服务：其参数更新会同时改变 K、V。解耦使两类变化更容易分别调节，可能减轻学习难度。现有门控主导原始梯度的结果不能验证这个假设：还没有 K/V 分支梯度方向、实际 optimizer 更新或受控训练对照。

这三个假设提供了恢复解耦的理由；它们不是三个已经独立确认的失败原因。

## 4. 为什么现在不应直接归因或回退

**状态参与 K 本身没有逻辑错误。**按内容决定注意力可以帮助找到与目标相关的候选，编号参与 V 也可能帮助把所读内容绑定回输出编号。融合形式在表达上允许保留身份和状态信息，当前成绩不证明 FFN 必然丢失了地图几何关系。把状态影响 K 称为“污染”会先假定一种寻址方式必然正确，超出现有证据。

**候选早已重编号。**`blocks_step` 在 rollout 使用随机排列；训练的 `numbering_plans` 为大候选集合抽取不同排列，`numbered_step` 同步移动动作、后继、向量与距离，保持编号和物理动作对应。普通非零步训练任务有多套固定编号。因此，预览中“候选按固定 placement 顺序导致低编号答案”的解释与现有实现不符。固定有限增强仍可能留下样本统计偏差，但需读取实际 gold 标签后验证，不能用猜测替代。

**训练成熟度和监督分布仍是竞争解释。**旧低编号偏向从约 71% 降至约 23%，支持将后续断点变化纳入观察。当前逐轨迹平均损失同时监督排序、动作与终止；晚轮候选较少，低编号出现机会更高，也可能影响总体 token 学习，但本次尚未按训练轮次核对编号标签频率和各部分有效更新。相同更新数、相同 epoch 或相同 loss 都不能单独消除 batch、样本曝光及目标差异。

**不能把高 reference 当作融合接口已学会读取。**首轮 reference 为 48.0%，第 2 轮起显著升高；下一轮使用 gold 排序和动作历史，状态也沿参考轨迹。仅按 rollout 的轮次构成重新加权，reference 总体从 81.8% 降到 68.5%，仍高于 rollout 的 55.9%。这剩余差距并未控制状态和历史，所以既不能全归因于寻址，也不能全归因于自身回答历史。

**“门控打不开”不是现有证据的充分解释。**同一批成功训练输入上，接近更新数时旧／新的局部注入幅度约为 9.74%／11.28%；新架构并不更小。这只是注入能量，不是有用信息或任务因果贡献，故也不证明读取有效。当前不据此调门控或裁剪。

旧／新历史对照还混入不同留出任务、global batch、失败数据、训练预算和初始化。即使旧模型在当前题上更强，也首先说明旧训练得到的整体系统更有效；要识别 K/V 分工自身的收益，还需要其余条件匹配的训练比较。

## 5. 当前错误对架构讨论的约束

3.5 epoch 的 504 道失败中，420 道在前三轮首次失去可达性。239 次删掉目标占用格，265 次保留目标格却留下无法按合法形状移除的结构。原始格式大体可执行：首轮排序全部可解析，动作全部跟随自身排序第一名；整个 rollout 的 3,994 个可解析排序也都选择自己第一名。

首轮输出 top-10 与地图实际 top-10 的平均交集约 2.53 个，随机期望为 1.81 个，说明输出关系很弱但不能据此称为完全随机或完全无地图依赖。当前 reference／rollout 的首轮物理状态与合法动作集合相同，经 CPU 检查地图向量逐位一致；两种模式的编号则不同。现有问题优先定位为地图关系到排序、动作的转化，不能进一步宣布已经定位到 K 分支。

耗尽动作后的 418 个失败末端中，224 个误报已经达标，192 个正确报无解；真正到目标的 6 个全部正确停止。终止分类是另一个问题，恢复 K/V 解耦未必解决它。当前失败监督只覆盖动作耗尽，不覆盖中途不可达判断，不能把模型在死局后继续执行直接算作缺失已训练的提前无解能力。

## 6. 后续讨论可选择的最小证伪步骤

以下是候选方案，**本次没有启动模型干预或新训练，也没有修改正式配置**。先做便宜的判别，再决定是否需要新架构训练；不预先铺开网格。

| 顺序 | 固定什么、只改变什么 | 回答什么 | 解释边界 |
|---|---|---|---|
| 1：核对训练标签 | 只读已有准备数据，按轮次及候选数统计 gold 编号、排序首项与监督 token | 低编号偏向是否符合训练标签／语言模板的统计机会 | 标签分布相似不证明模型经过该路径学习 |
| 2：固定首轮输入 | 选同一批物理题、地图、编号和预算，比较现有旧／新断点；分别看近似更新数与旧 final | 历史差距在同题上是否仍成立 | 可排除测试集组成，不能排除训练设置差异 |
| 3：一致重编号 | 同一权重、同一物理首轮，改变候选编号；文字、ID 嵌入、后继地图同步调整，检查还原后的真实动作 | 输出跟随固定数字，还是跟随某个物理候选 | 编号与展示位置一起改变时，只能识别联合偏向；该结果仍不直接定位到融合 FFN |
| 4：改变地图内容 | 保持文字、物理候选和编号，置换候选 Q；目标 Q 单独作为另一项干预 | 新接口动作是否依赖地图关系 | 输出敏感不等于读取正确；无变化也不直接说明为何不读取 |
| 5：必要时匹配训练 | 固定基座、地图、准备数据、采样、全局 batch、逐轨迹目标和更新预算，只比较信息分工 | 恢复解耦是否改善首轮及完整执行 | 需新训练；不同形状参数不能要求初始权重逐位相同，单次训练也不能排除随机性 |

第 5 步若有必要，首选讨论两个条件：当前融合 FFN，以及“地址 K＋状态 V、仅值分支加 FFN”。后者可用已有 `AddressedMapMemoryEncoder` 的值分支 FFN 表达，保留非线性处理，避免把“去掉 FFN”和“恢复信息分工”再次混在一起；是否匹配参数量和 FFN 形式需在正式合同中明确。若之后确有必要区分 K 与 V 的影响，再考虑“地址 K＋融合 V”，本次不实现这项混合结构。

主要判据应是非空目标首轮保持可达、地图最优选择及首个死局轮次，辅以编号改变后的真实动作一致性；完整 rollout 成功和耗尽失败误报成功分别报告。只提升整体 reference 或降低训练 loss，不足以据此恢复解耦。未来训练对照应同时记录更新次数、曝光量与实际耗时，不能只对齐 epoch。

## 7. 决策边界与运行安排

恢复 K/V 解耦是有实现依据的候选：它能重新限制状态影响地址、编号影响内容的路径，也有旧运行较好首轮成绩作为探索线索。目前缺少的是匹配条件下的净收益和编号偏向的具体路径证据。

建议继续当前运行，先收齐后续断点，观察首轮关系读取与低编号偏向是否随训练改善；后续讨论优先决定上表的只读标签核对和固定首轮比较是否值得做。若匹配条件下首轮仍持续较弱、重编号后动作不稳定，且受控训练显示解耦改善主要判据，才支持将解耦恢复为主线。若偏向随训练消退或解耦没有改善，应保留融合并继续定位关系比较、历史或监督分布问题。

当前融合 FFN 的 checkpoint 与解耦结构存在参数名称和维度差异，不能只改 `memory_mode` 就把同一 optimizer 状态当作原训练接续；恢复应作为独立、可比较的运行，由后续决议确定。

北京时间 2026-10-08 05:06 的只读快照确认：训练继续到 step 56,424（4.104 epoch），最近 500 次更新平均 loss 为 0.2087，无非有限 loss／grad norm；四卡评测均存活且启用地图 K/V 缓存，4 epoch 已写出 reference 175/510、rollout 177/510 题。训练仍按已批准的两卡每卡 2、全局 4 运行。快照不作为模型能力对比；运行状态会继续变化，实时文件保留在 Git 忽略目录。
