# 地图读取实验：失败分析与改进建议

讨论稿 · 2026-10-02

**当前结论：接口尚未学会稳定地根据地图比较候选。** 原接口能在部分训练题上写出正确格式、选中最近候选，但交换地图后选择通常不变；K/V 解耦、尺度校准和短式 swap 监督尚未解决这一问题。最明确的负结果是：短式训练已能稳定输出合法答案，两项任务的 16 对训练题却都是 **0 对原题／swap 同时正确，0 次选择改变**。

本报告以同题小样本对照为主，区分实验事实、机制解释和待验证方案。首要目标是学会比较不同 candidate 到同一 goal 的地图距离；这还不是完整规划能力。

## 1. 实验设置：训练什么、怎样监督

| 项目 | 本轮设置 |
|---|---|
| 任务与基座 | 寻路、积木；均使用 Qwen2.5-1.5B-Instruct，但两题分别训练接口、分别保存权重 |
| 冻结部分 | 语言模型主干、各自的 Q-map |
| 可训练部分 | 状态投影 P、角色／编号 embedding、门控 cross-attention；未加关系模块 R |
| 地图输入 | current、goal、全部合法候选后继的 Q；状态 128 维，P 投影为 256 维 |
| 注入架构 | 28 个语言层前分别插入 cross-attention；4 heads × 64 维；gate 经 tanh 后控制残差，初始为 0、保持可训练 |
| 监督方式 | SFT，teacher forcing；只计算 assistant token 的交叉熵，原条件监督完整轨迹 |
| 优化参数 | AdamW；学习率 2×10⁻⁵；weight decay 0.01；5% warmup 后恒定学习率；梯度裁剪 1.0 |
| 批量与精度 | 实际 batch=1，不做梯度累积；冻结基座 BF16，接口参数 FP32，训练使用 BF16 混合精度 |
| 小样本预算 | 每题 16 条训练、4 条验证记录；旧／新接口使用同一批题，各 256 次更新 |
| 数据重复次数 | 整题：16 条轨迹 × 16 epochs；首轮 swap：16 原题构成 32 个样本，256 次更新实际覆盖 8 epochs |

寻路小样本来自四张图，每图 4 道训练、1 道验证题；积木来自 16 张训练棋盘和另 4 张保留棋盘。这些验证题用于接口诊断，不等同于正式的未见图／未见状态评测。

寻路提供预测后继 Q(current)+V(action)，按欧氏距离排序；积木用冻结棋盘编码器编码合法后继，沿用原地图的有向距离 `directed_sum`。距离只用于生成监督和评分，**不作为数值输入喂给模型**。

原回答依次包含：**全部候选及 current 的排序 → 逐项解释 → Choose candidate → `<action>`**。积木首轮有 38–86 个候选，示范回答约 712–1578 token；首轮完整生成上限为 2048 token，因此不能简单解释成“正确答案必然超预算”。

这里讨论的是 **attention 的 K/V 解耦**，不是环境状态 Q 与动作位移 V 的解耦：

| 接口 | K 和 V 从哪里来 | 意图与变化 |
|---|---|---|
| 原混合记忆 | 将 P(Q)、角色、编号拼接，经线性融合与归一化后生成 K、V | 内容与标签共同参与读取 |
| K/V 解耦 | K 仅来自角色／编号；V 仅来自 P(Q)，不逐状态做 LayerNorm | 保留状态尺度，分开地址与内容 |

新条件也改变了融合层、维度和归一化路径，不能把它看作只修改一个变量的纯寻址消融。正式参数与选择规则见[小样本合同](../configs/kv_pilot.json)、[寻路配置](../configs/pilot_path256_addressed_kv.json)、[积木配置](../configs/pilot_blocks_addressed_kv.json)和[后续实验合同](../configs/kv_scale_followup.json)。

## 2. 结果：哪些尝试没有解决问题

**第一轮同题对照：K/V 解耦没有带来读出改善。** “合法排序”只要求格式和候选集合符合协议，不代表顺序正确；“最近候选命中”按模型输出动作评分。

| 任务／接口 | 训练合法排序 | 训练最近候选命中 | 验证合法排序 | 验证最近候选命中 |
|---|---:|---:|---:|---:|
| 寻路：原混合记忆 | 14/16 | 12/16 | 4/4 | 0/4 |
| 寻路：K/V 解耦 | 0/16 | 0/16 | 0/4 | 0/4 |
| 积木：原混合记忆 | 0/16 | 0/16 | 0/4 | 0/4 |
| 积木：K/V 解耦 | 0/16 | 1/16 | 0/4 | 0/4 |

寻路原接口的训练完整排序真正正确仅 **5/16**；另取 4 道训练题交换最近／最远候选 Q，动作改变 **0/4**，交换后的最近候选命中 **0/4**。训练原题表现不能证明模型依赖地图。积木完整排序无效时，评测器会把逐对分数记为 0；这不能解释成模型每一对内部关系判断都错误。

**后续控制实验：尺度和长输出都不是完整解释。**

| 尝试 | 关键结果 | 能支持的判断 |
|---|---|---|
| 在真实排序 token 位置校准分支尺度 | 未乘 gate 的分支强度中位数：寻路旧／新为 4.562／0.317，积木为 4.399／5.692；据此分别固定 value 缩放 14.41、0.773 | 寻路新接口明显偏弱；积木新接口反而更强，不能统一归因于 value 太弱 |
| 校准后整题 SFT | 寻路最终训练首步合法排序仍为 0/16 | 匹配分支尺度不足以建立读出 |
| 校准＋首轮完整排序 swap 监督 | 寻路合法排序 0/16，动作最近候选命中 1/16 | 加入反事实样本后，完整排序仍未学会 |
| 积木改用短问答评测旧／新／校准整题权重 | 每组 16 对训练题均为 0 对同时正确；格式有效率不一致 | 长输出确有负担，但单独缩短评测回答不能修复地图使用 |
| 独立训练短式 swap 问答 | 两题格式都学会，地图变化仍未控制选择，见下表 | 已能把格式失败与比较失败分开 |

尺度数值是分支范数／hidden 范数的无量纲比值，按训练题排序位置汇总；它衡量注入强度，不衡量信息是否有用。后续寻路完整排序采用 256-token 快速首轮评测，短式比较采用 64-token 上限；不与最初 2048-token 完整评测混作同一预算。

**短式 swap 训练最终结果（同文字，只交换候选 Q，正确答案随之改变）：**

| 任务 | 原题／swap 格式有效 | 原题正确 | swap 正确 | 两题同时正确 | 选择改变 |
|---|---:|---:|---:|---:|---:|
| 寻路训练集 | 16/16、16/16 | 3/16 | 13/16 | **0/16** | **0/16** |
| 积木训练集 | 16/16、16/16 | 12/16 | 4/16 | **0/16** | **0/16** |

两题各 4 对验证题也均为 0 对同时正确。每对恰好只对一边，合计单题准确率均为 50%；这与“保持同一选择”的行为一致，不能将积木原题 12/16 单独报成比较能力。

## 3. 模型实际输出：学到了什么倾向

以下均取自已有运行日志，不是为说明问题编造的回答。

**例一：把编号大小当作候选优劣。** 校准整题后的寻路模型在 `graph_00`、start=0、goal=64 上输出了以下两句（中间内容省略）：

```text
Choose the move with the smallest candidate number.
Choose move 1 because 1 is smaller than 2 and 3.
```

这段文字表现出编号启发式倾向；它不能单独证明所有样本都使用同一机制，但与 swap 后选择不变的结果一致。

**例二：积木学会排序句式，却没有完成排序。** 原混合接口在 board_row=3184 上的原文节选：

```text
Map-distance ranking to the goal, closest to farthest: 8 < 1 < 24 < 10 < 11 < ... < 78 < 80 < 81 < ...
<action>8</action>
```

省略号来自模型原文；两行之间省略了解释文字。K/V 接口同题还出现候选编号重复。此类回答具有排序外观，但不是合法完整排列。

**例三：短式格式正确，内容不随地图变化。**

| 任务／比较对象 | 原题正确答案 → 实际输出 | 换 Q 后正确答案 → 实际输出 |
|---|---|---|
| 寻路：candidate 1 与 2 | 1 → `<closer>2</closer>` | 2 → `<closer>2</closer>` |
| 积木：candidate 28 与 47 | 28 → `<closer>28</closer>` | 47 → `<closer>28</closer>` |

第三类是最直接的失败证据：没有长文本负担，也没有前面正确排序可复制，模型仍没有作出对应的地图比较。

## 4. Loss 是否收敛：必须区分语言拟合与地图能力

下表是**每个 epoch 内训练步 loss 的平均值**，不是最终权重重新遍历数据的评估 loss，也不是训练全过程平均值。整题、完整首轮、短式回答的监督 token 不同，跨行数值不可直接比较任务难度。

| 条件 | 首 epoch | 倒数第 3 个 | 倒数第 2 个 | 最后 epoch | 判断 |
|---|---:|---:|---:|---:|---|
| 寻路原接口，整题 | 0.3514 | 0.0305 | 0.0255 | 0.0226 | 文本拟合较好，仍无稳定 swap 响应 |
| 寻路 K/V，整题 | 0.3512 | 0.3084 | 0.2977 | 0.2860 | 仍明显下降，不能认定训练充分 |
| 寻路校准 K/V，整题 | 0.3512 | 0.1256 | 0.0954 | 0.0730 | 仍下降，首步读出未通过 |
| 寻路校准 K/V，完整首轮 swap | 2.5014 | 1.4158 | 0.8199 | 0.3368 | 仍快速下降，尚不能判定收敛 |
| 积木原接口，整题 | 0.2531 | 0.1557 | 0.1529 | 0.1516 | 下降趋缓，完整排序未学会 |
| 积木 K/V，整题 | 0.2531 | 0.1550 | 0.1522 | 0.1506 | 与旧接口相近，未带来读出改善 |
| 寻路校准 K/V，短式 swap | 1.1090 | 0.0966 | 0.0925 | 0.0890 | 下降趋缓，成对比较仍为 0/16 |
| 积木校准 K/V，短式 swap | 1.2971 | 0.1037 | 0.0966 | 0.0971 | 最近两 epoch 近似平台，成对比较仍为 0/16 |

短式模型在 step 64 的 8 道训练诊断题上，两题格式均为 0/8；step 128 均升到 8/8，但成对正确仍为 0/8。**这一阶段明确观察到了格式学习，没有观察到地图比较改善。**

Teacher forcing 下，末尾动作可以利用此前正确排序与解释。对两道积木训练首轮、两种原始接口的条件 loss 检查发现：排序部分 CE 约 **0.82–0.96**，末尾动作编号 CE 却仅 **9×10⁻⁶–1.8×10⁻⁴**。后者衡量“给定正确前文后的动作续写”，不是独立决策能力。

平均 loss 也可能掩盖错误：举例而言，若 11 个回答 token 中只有一个二选一位置尚不会，其余完全正确，不看地图、对两个答案各给一半概率时，平均 CE 仅为 ln(2)/11≈0.063。这是说明量级的理想例子，不是宣布实际模型已经达到某个收敛下界。

答案 token 的梯度并未消失，teacher forcing 也不会把当前答案提前泄露给模型。**目前应表述为：部分条件尚未收敛，部分条件的文本 loss 已趋缓，但没有任何条件证明地图比较已收敛。**

## 5. 为什么没有稳定读到地图：证据与原因分开

| 编号／可能原因 | 现有证据 | 目前能说到哪里 |
|---|---|---|
| F1：首次决策监督被后续续写掩盖 | 积木排序 CE 0.82–0.96，而给定正确前文的动作 CE 接近 0 | 确实存在复制捷径；但解释不了独立短式 swap 仍失败 |
| F2：候选身份与 Q 没有形成可靠读取绑定 | 短式 swap 训练两题均 0/16 成对正确；积木首个探针中，按 head 平均的两候选合计注意力约 2.16%–2.28%，接近均匀读取的 2/88≈2.27% | 支持寻址／混合读取是重要瓶颈；单个位置的注意力不是完整因果证明 |
| F3：注入尺度不匹配 | 寻路需要约 14.41 倍校准，积木反而缩到 0.773 倍；校准后仍失败 | 是寻路的优化不利因素，不能解释全部失败 |
| F4：长排列输出、编号模式形成额外负担 | 积木出现省略号、重复编号；寻路出现“按最小编号选” | 缩短输出合理，但短式负结果说明不能只修格式 |
| F5：训练尚未完成，或有效关系样本覆盖不足 | 寻路多条曲线仍下降；只有 16 个原题场景，swap 只是其对应干预 | 未排除训练预算与泛化数据问题；训练题本身未拟合前，不宜只归因于数据量小 |
| F6：冻结主干难以适应新几何，或数值精度削弱差异 | 小样本前向中 Q 变化能传入模型，但不足以翻转选择；各一题改用 FP32 前向仍未翻转 | 是待验证的计算／优化限制，不能据此宣称架构不可能，也不能把 BF16 当作唯一根因 |

F2 的最小机制解释是：对某个 head，在输入 query 不变时，交换 A、B 的 value 带来的读取变化为 **Δr=(αA−αB)(VB−VA)**。如果两个权重接近，交换变化就小；若权重相等，这次读取完全不变。放大整个分支并不能补回这种对应关系。

补充前向证据：在各一题的 FP32 探针中，“原题正确 token 的 logit − swap 正确 token 的 logit”在寻路为 **−0.2687→−0.2910**，积木为 **0.5739→0.5729**。符号均未翻转；存在地图响应，不等于足以改变决策。探针是在同权重上提高前向精度，未重新训练；不能外推成全量结论。

## 6. 对应方案：先让状态能被区分，再直接训练关系

以下均为**拟议方案，尚未实施或证明有效**。优先目标是 candidate 到 goal 的相对远近，current 比较后续补充。

| 方案 | 针对的失败原因 | 怎样改、为什么可能有效 | 限制与验收 |
|---|---|---|---|
| **监督普适性：从固定文案转向候选关系** | F1、F4、F5 | 输入保留全部候选，训练同一 goal 下任意候选的相对次序；覆盖不同候选数量、编号、目标和远近差异，允许并列 | 不只比较最近／最远，也抽取接近的候选；首要指标是逐对比较，而非只有 top-1 或格式 |
| **动作在前，只输出前几个候选** | F1、F4 | 首先输出动作，再给两个备选；删除完整排列和重复解释。首次决策前不出现正确答案，降低无关生成负担 | 仍读取全部 38–86 个候选；不能先按真实距离筛好前三名再输入 |
| **保留 swap，扩展其覆盖** | F2、F5 | 原题和换 Q 题提供相反的正确标签，文字保持相同；另做同步重编号，检验编号与实际状态的对应 | 此前已加入 swap，单独加入并未奏效；应与读取改动一起验证。Q-only swap 是地图诊断，不冒充真实规划轨迹 |
| **增加共享线性排序读出头** | F1、F5、F6 | 从结合 goal 的候选隐藏表示 hi 得到 si=wᵀhi，直接监督“更近者分数更高”；同一头处理任意数量候选，loss 不依赖解释长度 | 新增了可训练组件，但不是直接比较两个原始 Q 的非线性 R；若仅作辅助头，还须证明 LLM 生成动作也改善 |
| **显式状态位置＋真实 attention mask** | F2；也帮助区分 F3 与 F6 | 用 goal、current、candidate 的标记位置分别绑定对应 Q，再经 LLM self-attention 组合；避免先把大量状态近似平均后再恢复身份 | 标签本身不是 mask；单槽硬 mask 相当于确定性注入，只保证读取对应，不能保证关系学会或投影无损 |

动作在前的示意输出：

```text
<action>17</action>
<alternatives>42,8</alternatives>
```

共享排序头的监督可写为：当地图标签满足 di<dj 时，最小化 **log(1+exp[−(si−sj)])**。这直接惩罚次序错误；不要求回归精确距离，也不把距离喂给输入。并列不强制严格次序，训练可以采样候选对，无需每题穷举全部关系。若直接用排序头选动作，应作为独立的模型决策条件报告，不能与原词表生成混为一谈。

显式读取的逻辑结构可以是：

```text
<goal><state/></goal>                   ← Qgoal
<current><state/></current>             ← Qcurrent
<candidate id="1"><state/></candidate>  ← Q1
<candidate id="2"><state/></candidate>  ← Q2
...
所有候选表示 → LLM 比较 → 首次动作与前几个候选
```

`<state/>` 是连续状态的读取位置，不是把 Q 数字写成文本。路由只依据已知身份，不使用正确排序。这里借鉴了 Flamingo 的文字位置与外部内容 mask 绑定，以及多模态模型保留多个特征位置的做法；它们是机制参照，不是本项目的成功保证。[Flamingo](https://arxiv.org/html/2204.14198#S2.SS3)、[LLaVA](https://arxiv.org/html/2304.08485#S4)、[RankNet](https://www.microsoft.com/en-us/research/publication/learning-to-rank-using-gradient-descent/)

**建议顺序：**先固定简短、动作在前的监督，比较原读取与显式状态 mask；若需要更直接的关系训练，再单独增加共享线性头对照。先保持 4×64 heads：8×64 同时增加宽度与参数，不能单独解释为 head 数收益；若所有 head 都只读同一状态，固定总宽度下增加 head 也不会改变该线性读取。

后续判断是否继续训练，应看训练内关系错误、swap 成对正确率和首次动作正确率是否同步改善。训练题通过后再增加未见状态／目标、候选数量变化及闭环任务评测。**地图比较通过，仍不等于最短路或完整规划通过。**
