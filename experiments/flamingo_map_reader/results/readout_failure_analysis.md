# 地图读取实验：结果与原因分析

讨论稿 · 2026-10-03

**充分训练改变了早期结论：寻路已能在训练题上随 Q 改答案，但尚未证明学会通用比较。积木能拟合原题，地图响应仍较弱。**

报告按“拟合原题 → 使用地图 → 泛化关系”解释结果。原来的 16 条训练、4 条验证只作为小样本诊断；寻路已开始扩大到 1024 条训练、256 条同图验证和 256 条新图测试。第 1、3 节按要求原样保留，描述第 256 步时的设置与案例。

## 1. 实验设置：训练什么、怎样监督

| 项目 | 本轮设置 |
|---|---|
| 任务与基座 | 寻路、积木；均使用 Qwen2.5-1.5B-Instruct，但两题分别训练接口、分别保存权重 |
| 冻结部分 | 语言模型主干、各自的 Q-map |
| 可训练部分 | 状态投影 P、角色／编号 embedding、门控 cross-attention；未加关系模块 R |
| 地图输入 | current、goal、全部合法候选后继的 Q；状态 128 维，P 投影为 256 维 |
| 注入架构 | 28 个语言层前分别插入 cross-attention；4 heads × 64 维；gate 经 tanh 后控制残差，初始为 0、保持可训练 |
| 监督方式 | SFT，teacher forcing；只计算 assistant token 的交叉熵，原条件监督完整轨迹 |
| 优化参数 | AdamW；学习率 2×10⁻⁵；weight decay 0.01；5% warmup 后恒定学习率；梯度裁剪 1.0 |
| 批量与精度 | 实际 batch=1，不做梯度累积；冻结基座 BF16，接口参数 FP32，训练使用 BF16 混合精度 |
| 小样本预算 | 每题 16 条训练、4 条验证记录；旧／新接口使用同一批题，各 256 次更新 |
| 数据重复次数 | 整题：16 条轨迹 × 16 epochs；首轮 swap：16 原题构成 32 个样本，256 次更新实际覆盖 8 epochs |

寻路小样本来自四张图，每图 4 道训练、1 道验证题；积木来自 16 张训练棋盘和另 4 张保留棋盘。这些验证题用于接口诊断，不等同于正式的未见图／未见状态评测。

寻路提供预测后继 Q(current)+V(action)，按欧氏距离排序；积木用冻结棋盘编码器编码合法后继，沿用原地图的有向距离 `directed_sum`。距离只用于生成监督和评分，**不作为数值输入喂给模型**。

原回答依次包含：**全部候选及 current 的排序 → 逐项解释 → Choose candidate → `<action>`**。积木首轮有 38–86 个候选，示范回答约 712–1578 token；首轮完整生成上限为 2048 token，因此不能简单解释成“正确答案必然超预算”。

这里讨论的是 **attention 的 K/V 解耦**，不是环境状态 Q 与动作位移 V 的解耦：

| 接口 | K 和 V 从哪里来 | 意图与变化 |
|---|---|---|
| 原混合记忆 | 将 P(Q)、角色、编号拼接，经线性融合与归一化后生成 K、V | 内容与标签共同参与读取 |
| K/V 解耦 | K 仅来自角色／编号；V 仅来自 P(Q)，不逐状态做 LayerNorm | 保留状态尺度，分开地址与内容 |

新条件也改变了融合层、维度和归一化路径，不能把它看作只修改一个变量的纯寻址消融。正式参数与选择规则见[小样本合同](../configs/kv_pilot.json)、[寻路配置](../configs/pilot_path256_addressed_kv.json)、[积木配置](../configs/pilot_blocks_addressed_kv.json)和[后续实验合同](../configs/kv_scale_followup.json)。

## 2. 结果与原因：先分清三件事

**能答对训练原题、答案会随 Q 改变、能答对未见题，是三种不同能力。** 以下按这个顺序解释。原来的第 256 步结果保留作早期对照，不能继续当作最终结论。

### 2.1 先排除“还没训够”

十组实验都从原 checkpoint 续训，保留数据、优化器状态和监督形式。每次在同一训练集上重新计算两项 loss：**整体 loss**包括全部回答；**关系 loss**只看排序内容或短式选择编号，不含末尾重复动作。两项都持续进入平台才停止，达到步数上限不算收敛。按训练整体 loss 选权重，不用验证成绩选。

十组均已按同一规则进入 loss 平台，下面使用各自选定的权重。

| 条件 | 停止／选用步 | 整体 loss：256 步 → 续训后 | 关系 loss：256 步 → 续训后 |
|---|---:|---:|---:|
| 寻路：原接口，整题 | 1792／1536 | 0.0217 → 0.000043 | 0.2211 → 0.000095 |
| 寻路：K/V，整题 | 4608／4224 | 0.2792 → 0.000046 | 0.5622 → 0.00012 |
| 寻路：校准 K/V，整题 | 2304／2304 | 0.0624 → 0.000025 | 0.3128 → 0.000037 |
| 寻路：校准 K/V，首轮排序＋swap | 2944／2944 | 0.1756 → 0.000035 | 0.5923 → 0.000044 |
| 寻路：校准 K/V，短式比较＋swap | 2304／2304 | 0.0838 → 0.000035 | 0.9055 → 0.00006 |
| 积木：原接口，整题 | 7680／6912 | 0.1507 → 0.0013 | 0.7825 → 0.0064 |
| 积木：K/V，整题 | 5376／4864 | 0.1497 → 0.0234 | 0.7800 → 0.1209 |
| 积木：校准 K/V，整题 | 10496／9984 | 0.1506 → 0.0027 | 0.7820 → 0.0131 |
| 积木：校准 K/V，首轮排序＋swap | 7680／7040 | 0.1876 → 0.000968 | 0.8811 → 0.0045 |
| 积木：校准 K/V，短式比较＋swap | 2304／1792 | 0.0929 → 0.0769 | 0.6938 → 0.5904 |

表中“停止／选用步”分别是停止训练的步数、用于评测的 checkpoint。不同输出任务的 loss 不宜横向比较大小；“进入平台”也不保证学到了正确机制。具体规则见[收敛合同](../configs/kv_convergence.json)。

**一项实现偏差：**框架按扩展预算重算了 warmup，旧小样本续训在第 258–410 步的学习率短暂低于 2×10⁻⁵，随后恢复固定值。全部选用权重均在更晚阶段；结果仍可说明充分拟合后的行为，但停止步数不能直接作为结构训练效率的严格比较。此问题已修正，扩大寻路的受影响尝试中止留档后从头重跑。

评测已统一并完成：256 步与续训后的权重都测同一批题，完整排序最多生成 2048 token，短回答最多 64 token。**下面的主表只列充分训练后的结果，256 步对照保留在证据文件中。**

### 2.2 寻路：已经能在训练题上使用 Q，尚未证明能泛化

| 训练内容 | 训练原题 | 原题与换 Q 后同时正确 | 留出题 |
|---|---:|---:|---|
| 普通整题 SFT，原接口／K/V／校准 K/V | 三组完整排序均 16/16 | 三组均 0/16 | 三组完整排序均 0/4 |
| 完整首轮排序＋swap | 完整排序 16/16 | 完整排序 16/16 | 完整排序 0/4 |
| 短式两候选比较＋swap | 选择正确 16/16 | 选择正确 16/16 | **成对选择正确 1/4** |

1. **普通 SFT 能拟合题目，却没有通过地图响应检查。** 保持文字不变，只交换两个候选 Q，三个普通 SFT 模型的动作都没有改变。因此训练题全对，仍不足以证明它会根据候选—状态的对应关系作答。
2. **加入 swap 并训够以后，训练内地图响应确实学到了。** 同一文字对应两种 Q、两种正确答案，模型两边都答对。这排除了“当前冻结 LLM＋接口完全不可能利用 Q”的判断；但仍可能记住具体 Q 模式，并不自动证明学会了通用距离规则。
3. **1/4 只说明这四对留出题尚未通过。** 它属于短式比较：每题要求原 Q 和 swap 都对。不是完整排序成绩，更不是规划成功率。四题太少，不能据此可靠估计泛化率，也不能确定只要增加数据就会解决。

这里完整排序＋swap 还把整条轨迹改成了独立首轮监督，提升不能全部归因于 swap 一个变量。

### 2.3 积木：原题拟合、长排序表达、地图响应仍有明显差别

| 训练内容与接口 | 训练原题正确 | 原题与换 Q 后同时正确 | 留出题 |
|---|---:|---:|---|
| 原接口，整题 | 完整排序 16/16 | 完整排序 0/16 | 完整排序 0/4 |
| K/V，整题 | 完整排序 1/16 | 完整排序 0/16 | 完整排序 0/4 |
| 校准 K/V，整题 | 完整排序 13/16 | 完整排序 0/16 | 完整排序 0/4 |
| 校准 K/V，首轮排序＋swap | 完整排序 8/16 | 完整排序 3/16 | 完整排序 0/4 |
| 校准 K/V，短式比较＋swap | 短式选择 10/16 | 短式选择 1/16 | 成对选择 1/4 |

**有三点需要修正或单独说明。**

- **长输出并非绝对学不会。** 原接口从早期完整排序 0/16，提升到 16/16。但 Q 交换后动作变化仍为 0/16，说明“会写训练题的长答案”与“会按地图变化选择”可以完全分离。
- **K/V 的错误不全发生在第一选择。** 未校准 K/V 的训练题中，排序开头最近候选为 16/16，但完整排序只有 1/16、末尾动作命中 5/16；校准后完整排序提高到 13/16，开头仍为 16/16。它可以写对开头，随后在长生成中失效。这个现象支持缩短输出；但两种 K/V 的开头正确同样没有通过 Q 交换。
- **短式监督也没有彻底解决地图比较。** 短式 swap 在训练原题与交换题上都能合法作答，但只有 1/16 对同时正确。这里没有长排序，也没有此前正确答案可复制，因此还必须检查候选读取、关系计算和优化。

另一个容易误读的数字是“逐对正确率”。积木原接口在换 Q 后仍有 **32893/34931≈94.2%** 的排序关系正确，但最近候选命中是 **0/16**。原因是只交换两槽，其他大量候选间的次序没有改变；照抄原排序也会得到很高的逐对分数。后续必须同时看首次选择、被交换候选的关系和成对正确率。

### 2.4 原因分类：哪些已有证据，哪些还只是解释

| 层面 | 已观察到的现象 | 目前判断 | 对应处理 |
|---|---|---|---|
| **训练预算** | 寻路 K/V 从早期 0/16 合法排序变成 16/16 完整正确；寻路短式 swap 从 0/16 变成 16/16 成对正确 | 256 步不足，早期否定结构或 swap 的结论过早 | 先对齐收敛程度，再比较；仍下降的条件继续训练 |
| **监督捷径** | 普通 SFT 原题全对，换 Q 不改答案；原回答先排序、后输出动作 | 训练可以靠记忆文字与复制正确前文降低 loss，没有迫使首次判断依赖 Q | 首次决策前不放答案；直接监督候选关系；加入同文字 swap |
| **候选读取与比较** | 积木短式充分训练后仍只有 1/16 成对正确 | 格式和长输出不足以解释；究竟是读错候选还是读到后不会比较，尚未分开 | 显式状态位置＋mask 保证分别读取，再检验比较；必要时用共享线性头检查关系表示 |
| **生成负担** | 积木 K/V 能写对排序开头，却难以完成后续排序与动作 | 自由生成会积累错误，末尾动作不能代表第一选择 | 动作在前，只输出少量备选；输入仍保留全部候选 |
| **训练覆盖与泛化** | 寻路训练 swap 16/16，原留出题仅四对；训练只抽自十步题，短式只比最近与最远 | 覆盖太窄，尚不能区分记住训练 Q 模式与学到通用关系 | 扩大当前状态、目标、路径长度和任意候选对；同图新目标与新图分别测试 |

**为什么 loss 小仍可能不会决策？** Teacher forcing 训练末尾动作时，模型已看见前面的正确排序。历史积木探针中，排序 loss 约 0.82–0.96，而末尾动作编号 loss 只有 0.000009–0.00018。后者说明“能照着正确前文续写”，不代表独立决策正确。若 11 个回答 token 中只有一个二选一位置不会，其余全对，平均 loss 也只有 ln(2)/11≈0.063。答案梯度没有消失，而是容易的续写占了很大比例。

**K/V 解耦到底解决了什么？** 它把角色／编号用于 key，把状态用于 value，减少标签与状态直接混合；并没有保证 attention 能读准候选。假如一个 head 对 A、B 权重相等，它读到的是二者的平均，交换 Q 后平均完全不变。放大分支也恢复不了“A 对应哪个状态”。但这只是可能机制：寻路 swap 成功已证明当前软 attention 可以学出有效响应，不能再笼统断言它必然抹掉地图信息。

历史探针显示寻路 K/V 未乘 gate 的分支强度约为旧接口的 1/14，而积木略强；所以分别用了约 14.4 和 0.77 的尺度校准。两个任务不能统一归因于注入太弱。K/V 的可训练参数还从约 4474 万降到 2444 万，旧／新对照同时改变了容量、归一化和读取方式，不能将差异只归于解耦。

### 2.5 扩大寻路：用更广的题目检验关系，而不是继续重复 16 题

**旧小样本权重的大样本评测已完成；扩大训练的结果仍在等待。**

| 旧小样本模型的评测 | 基础题数 | 原题／swap 都答对的候选对 | 全部候选对都答对的题目 |
|---|---:|---:|---:|
| 同图未见目标 | 256 | 55/768 | 0/256 |
| 新图 | 256 | 30/768 | 0/256 |

同图验证中，原题和 swap 都输出所问候选编号的有 705/768 对，但只有 55 对两边都对；多数失败并非回答格式无效。该较大评测同时增加了目标、路径长度与任意候选对，比旧的四道最近／最远比较题更广；两种训练规模的模型将在同一较大协议下比较。

| 用途 | 基础题数 | 当前状态—目标覆盖 | 检查什么 |
|---|---:|---|---|
| 训练 | 1024 | 四张图，567 个不同目标、643 个不同当前状态 | 扩大关系学习范围；每题抽任意一对候选，加原 Q／swap 两个样本，共 2048 个监督样本 |
| 同图验证 | 256 | 四张图，167 个不同目标；这些目标未以 goal 身份进入训练 | 在熟悉的地图上，能否比较未训练的目标关系 |
| 新图测试 | 256 | 第五张图，168 个目标 | 能否迁移到另一张独立训练 Q/V 的地图 |

这里的状态、目标数量按“图＋节点”去重。训练与验证在拆分目标后才生成 swap，避免原题和其变体跨集合。验证目标可能以 current／candidate 身份出现，不能称为完全未见状态；第五张图也只是一个新图实例。

题目覆盖最短路径 2、4、6、8、10 步，比例见[正式配置](../configs/path_readout_expanded.json)。十步题在这些图中本来就少，因此不再只抽十步题。训练不要求该题的地图贪心完整轨迹成功，避免只保留容易规划的样本。

较大评测在每道题上检查**全部非同距候选对**，分别生成原 Q 和 swap 的答案；基础题数与候选对数分开报告，不能把一题拆成三对就当作三个独立样本。旧小样本模型和扩大训练后的模型使用同一批较大题目。输入仍是 current、goal 和全部候选 Q，没有增加 R、线性头或 mask。

这次同时扩大样本、目标与候选对覆盖，并延长训练；结果用于判断这套监督能否泛化，不是只改变样本数量的消融。寻路首步仍只有三个候选，不能替代积木 38–86 个候选的验证，也不能直接代表闭环规划。

第 3 节按要求保留第 256 步的历史输出例子；它解释早期现象，不代表续训后的全部表现。

## 3. 模型实际输出：学到了什么倾向

以下均取自已有运行日志，不是为说明问题编造的回答。

**例一：把编号大小当作候选优劣。** 校准整题后的寻路模型在 `graph_00`、start=0、goal=64 上输出了以下两句（中间内容省略）：

```text
Choose the move with the smallest candidate number.
Choose move 1 because 1 is smaller than 2 and 3.
```

这段文字表现出编号启发式倾向；它不能单独证明所有样本都使用同一机制，但与 swap 后选择不变的结果一致。

**例二：积木学会排序句式，却没有完成排序。** 原混合接口在 board_row=3184 上的原文节选：

```text
Map-distance ranking to the goal, closest to farthest: 8 < 1 < 24 < 10 < 11 < ... < 78 < 80 < 81 < ...
<action>8</action>
```

省略号来自模型原文；两行之间省略了解释文字。K/V 接口同题还出现候选编号重复。此类回答具有排序外观，但不是合法完整排列。

**例三：短式格式正确，内容不随地图变化。**

| 任务／比较对象 | 原题正确答案 → 实际输出 | 换 Q 后正确答案 → 实际输出 |
|---|---|---|
| 寻路：candidate 1 与 2 | 1 → `<closer>2</closer>` | 2 → `<closer>2</closer>` |
| 积木：candidate 28 与 47 | 28 → `<closer>28</closer>` | 47 → `<closer>28</closer>` |

第三类是最直接的失败证据：没有长文本负担，也没有前面正确排序可复制，模型仍没有作出对应的地图比较。

## 4. 改进建议：每项改动对应一个已定位的问题

首要目标仍是**比较不同 candidate 到同一个 goal 的远近**。current 比较、终止判断和真实规划分别验收，不用一种成绩替代另一种。

### 4.1 监督更普适：直接教关系，覆盖任意候选对

训练“哪个候选更接近目标”，覆盖不同目标、状态组合和远近差距；不能只重复最近／最远这一种比较。输入始终保留全部合法候选。扩大寻路实验已经开始落实这一点；它仍使用短式 SFT，先检验是否需要改变架构。

**作用：**减少对固定题目和编号的记忆，训练可复用的候选关系。**限制：**二选一比较学会后，还需要检验全候选的首次选择与规划，不能自动外推。

### 4.2 动作在前：缩短输出，避免先给答案再让模型抄

最终规划接口可只输出动作与两个备选：

```text
<action>17</action>
<alternatives>42,8</alternatives>
```

首次动作之前不出现正确排序，删除重复解释和全部候选排列。动作、备选、格式分别计算平均 loss，再明确分配权重，使主要训练压力落在首次决策上。允许同距候选的合理次序。

**作用：**同时减少复制捷径与长生成错误。**限制：**只缩短输出；仍要读取全部候选，不能把真实前三名预先筛给模型。当前短式积木仍失败，说明这一项不能单独解决全部问题。

### 4.3 Swap：阻断纯文字捷径，但不能替代新关系

保持文字相同，交换任意两候选的 Q，并监督新的正确答案。“始终选同一编号”就至少错一边。它适用于完整候选集合，不要求最终输入只有两个候选。

**作用：**明确要求答案依赖 Q 与候选的绑定。寻路训练内已证明这一点可以学会。**限制：**同一批状态反复交换仍可能被记住；必须配合新的目标与状态组合。另做同步重编号，检验是否仍选择同一个实际动作。Q-only swap 是独立地图读出，不作为真实环境转移。

### 4.4 共享线性头：直接监督排序，检查关系是否已经形成

从每个候选**已经结合 goal 的隐藏表示**输出一个分数，训练“较近者分数更高”。所有候选共享同一个线性头，因此候选数量改变时不需要更换输出层，也不必生成几十个编号。

**作用：**把关系错误直接传给接口。若打分头能排对、文字动作仍错误，问题更靠近语言输出；若头也不会，继续检查读取与关系表示。**限制：**孤立的 P(Qi) 不能只经线性打分就完成任意 goal 的距离比较；目标相关的非线性关系仍需前面的模型形成。若直接用该头选动作，应单列成绩。这是后续建议，尚未加入。[RankNet](https://www.microsoft.com/en-us/research/publication/learning-to-rank-using-gradient-descent/)

### 4.5 显式状态位置与 mask：先保证每个候选被分别读到

为 goal、current、每个 candidate 留一个位置，并把对应 Q 绑定进去。答案位置通过后续 self-attention 读取这些状态表示。

```text
goal 位置        ← Qgoal
current 位置     ← Qcurrent
candidate 1 位置 ← Q1
candidate 2 位置 ← Q2
……                ↓
              模型比较并选择
```

`<map>`、`<goal>` 等标签只标明位置；实现中还要用真正的 attention mask 限定读哪个槽。也可以在每个候选位置让几个 head 分别读 goal、current、该候选。路由只用角色与编号，不使用距离答案。

**作用：**减少大量状态先被混合、再恢复候选身份的困难，帮助分清“读不到”与“读到后不会比”。86 个候选用 86 个位置、共享一套参数，不需要 86 个 head。**限制：**正确寻址不保证比较成功。先保留 4 heads；改成 8 heads 不会自动解决地址绑定，8×64 还同时增加了模型宽度。这借鉴多模态内容按位置绑定的机制，但不是本任务的成功保证。[Flamingo](https://arxiv.org/html/2204.14198#S2.SS3)、[LLaVA](https://arxiv.org/html/2304.08485#S4)

**推进顺序：**寻路先完成当前扩大覆盖的比较；积木的充分训练对照已收齐，下一步建议用短式监督对比现有读取与显式位置／mask，再决定是否加共享线性头。每次只检验一个主要解释，避免同时改动后不知道哪里起作用。
