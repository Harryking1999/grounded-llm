# 完整长轨迹 SFT：结果

**寻路已在留出目标上用上地图：final 的 reference 逐轮选中地图最优候选 76.8%，闭环到达 202/256（78.9%）。积木只到 39.5%，且积木的地图上限本身只有 71.2%。两任务的控制协议（格式、合法动作、终止）都接近 100%，差距几乎全部集中在排序内容。**

运行：`long_f73b700_20261004`，协议提交 `f73b700`。数据范围与数量、动作覆盖、初始／更新文本、Top-10 监督与优化设置见[设计页](../DESIGN.md)；原始计数与分片路径见[结果摘要](long_trajectory_summary.json)。表内数字截至 2026-10-05，闭环电池仍在跑（见 §6）。

## 1. 口径：两种模式、两种划分

**reference 与 rollout 回答不同的问题，但用同一份权重、同一个 adapter。**

| 模式 | 每轮喂给模型的历史 | 模型的错误动作 | 回答什么 |
|---|---|---|---|
| reference | 正确示范历史；一轮结束后把示范答案放回 | 不执行 | 给定正确历史，这一轮能不能读对 |
| rollout | 模型自己的回答，进入下一轮 | 由环境执行，真实状态照常推进 | 能不能真的到达、停止、总结 |

所以 reference 高不等于闭环成功：闭环里每一轮的小错都会改变后面看到的状态。下表凡未注明者都是 reference。`no_map`（同权重、旁路地图 cross-attention 的依赖消融）尚未运行；它不是另训的纯文字 baseline。

**validation 与 test 都是留出划分，但"留出"在两任务里含义不同。**

| 划分 | 寻路 | 积木 |
|---|---|---|
| train | 192 个目标 | 1,000 张初始棋盘，每张 8 个长任务 ＋ 1 个初始即目标 |
| validation | 32 个未作训练目标的目标 | 训练棋盘上 500 个新任务 ＋ 100 张新棋盘×5 ＋ 100 个初始即目标 |
| test | 32 个未作训练目标的目标 | 训练棋盘上 1,000 个新任务 ＋ 200 张新棋盘×5 ＋ 200 个初始即目标 |

寻路的留出目标在训练里没当过 goal，但会作为 current 或后继出现，因此是"未作训练目标"，不是"没见过该节点"。积木新棋盘与训练棋盘互斥，但中间状态不保证全部未见。两组都**没有**按地图贪心是否成功来筛选——留出指标不是选择性样本。

## 2. 地图上限：任何读图模型的天花板

清单里的 `greedy_baseline` 记录**冻结地图自己**沿距离最小后继走的结果（`prepare_trajectories.py`）。一个把地图读得完全正确的模型，轨迹应当就是它，所以这是上限而不是参照基线。

| 任务／划分 | 题数 | 到达 | 其中恰好等于环境最短路 |
|---|---:|---:|---:|
| 寻路 validation | 532 | 532（100%） | 147（27.6%） |
| 寻路 test | 1,032 | 1,032（100%） | 232（22.5%） |
| 积木 validation | 1,100 | 783（71.2%） | 411（37.4%） |
| 积木 test | 2,200 | 1,549（70.4%） | 839（38.1%） |

三条直接决定怎么读下面的表：

- **积木约三成题地图自己都走不到。**闭环到达率低于约 71% 时，不能推断是模型没读对地图。
- **"到达"与"最短"是两件事。**寻路上地图自己 100% 到达，但只有 23–28% 的题同时是最短路。所以闭环的"到达且最短路"要对着 27.6% 读，不是对着 100% 读。
- **衡量读图的是"选择地图最优候选"，不是"选择环境最短路动作"。**后者是逐轮标签、分母是决策轮，上表是逐题标签、分母是题数，两者不可换算；本表第三列不是它的上限。

## 4. 寻路闭环 rollout（validation 前 256 题，进行中）

| 指标 | final | 同划分 reference |
|---|---:|---:|
| 到达 | 202/256（78.9%） | — |
| 成功结束（到达且正确停止） | 200/256（78.1%） | — |
| 到达且为最短路 | 19/256（7.4%） | — |
| 逐轮：选择地图最优候选 | 71.0% | 76.8% |
| 逐轮：整条排序全对 | 46.5% | 56.2% |
| 逐轮：控制格式可解析 | 100% | 100% |
| 逐轮：总结正确 | 90.1% | 97.2% |

- **闭环确实有损耗。**同划分下逐轮地图最优 76.8% → 71.0%，排序全对 56.2% → 46.5%，总结 97.2% → 90.1%：模型自己的错误进入历史后，后续轮次变难。
- **到达 78.9% 要对着上限 100% 读**（§2 寻路 validation 行），不是对着 100% 的成功。
- **"到达且最短路"7.4% 要对着地图自己的 27.6% 读**——连地图贪心也只有约四分之一的题走出最短路。
- 逐轮"选择地图最优候选"（71.0%）低于逐题到达率（78.9%）并不矛盾：不选地图最小后继不等于到不了目标，该标签衡量的是与地图的一致性，不是成败。
- 分母：5,580 段（其中 5,378 决策轮、202 终止段）；只覆盖 532 题中的前 256 题，跑完后数字会变。

**留出 validation（1,100 题、8,242 决策轮 ＋ 783 终止段）**

| 指标 | epoch 1 | epoch 2 |
|---|---:|---:|
| 控制格式可解析 | 99.9% | 99.9% |
| 合法动作 | 99.7% | 99.5% |
| 整条排序全对（含 current） | 7.3% | 8.5% |
| 报告的最近候选集合正确 | 18.8% | 22.7% |
| 选择地图最优候选 | 26.2% | 39.5% |
| 选择环境最短路动作 | 48.9% | 60.4% |
| 逐对远近／并列关系正确 | 10.6% | 13.0% |
| 与 current 的关系正确 | 14.5% | 17.2% |
| 到达后正确终止 | 97.3% | 99.5% |
| 真实历史与步数总结正确 | 96.3% | 98.2% |

- **协议学会了，地图没学会。**控制格式与合法动作约 100%，但完整排序只有约 9%，逐对关系约 13%。积木的失败点和寻路不在同一处：寻路是"排得大致对、偶尔错"，积木是"格式全对、内容接近随机"。
- **动作比排序好得多，但方向和地图不一致。**选地图最优从 26.2% 升到 39.5%，而"选环境最短路动作"是 48.9% → 60.4%，**比地图最优更高**。也就是说模型在有相当比例的动作上是在走环境最短路，而不是在复现地图的选择——它并没有在跟随地图。
- **仍在明显上升**（地图最优 26.2 → 39.5，一个 epoch 涨 13 点），远未收敛，现在不能下"积木学不会"的结论。
- 分母：validation 的 783 终止段来自 1,100 题中地图能到达的那部分；其余 317 题的参考轨迹只有失败前缀，不伪造终止段。

## 6. 现在能判断什么

- 冻结 LLM ＋ 只训读取接口，**在寻路上足以把地图用起来**：留出目标上排序、动作、终止都对得起正确历史，闭环也真的到达（78.9%）并停止（78.1%）。
- **完全没有饱和。**两个任务的地图最优指标到最后一个 checkpoint 都还在涨，尤其积木一个 epoch 涨 13 点。任何"上限在 X"的说法现在都缺依据。
- **积木远落后于寻路，且落后在内容不在协议。**候选从最多 3 个变成最多 102 个、距离度量从欧氏变成有向和，是目前最可疑的两个差异，但本轮设置同时变了多处，不能单独归因。
- **闭环损耗真实存在但不大**：逐轮排序 56.2% → 46.5%，到达 78.9%。错误会累积，但没有到崩掉的程度。
- **留出与训练内几乎重合**，所以目前没有过拟合证据；反过来，样本量是否足够也还没被这组数据检验到。
