# 地图读取实验：现象、设置与待解决的问题

## 1. 原始完整轨迹：回答损失下降，逐步判断与闭环表现仍差

### 训练设置

- **任务：**在真实图上逐步寻路。初始文字给出完整图、起点和目标；每轮环境给真实当前节点、已执行路径、随机编号的合法动作及真实后继。动作执行后更新文字与地图。
- **模型：**冻结 Qwen2.5-1.5B-Instruct 和各图 Q/V，只训练状态投影、角色／编号嵌入、门控 cross-attention。原接口把状态、角色与编号混合后生成 attention 的 K、V。
- **数据：**四图共 256 条训练轨迹、64 条同图验证轨迹，起终点的真实最短距离均为十步。示范沿地图距离贪心走，实际轨迹不一定恰好十步；训练共 3436 个动作轮。
- **监督：**整条轨迹 SFT，保留每轮文字与对应地图；每轮回答“包含 current 的完整排序 → 解释 → 动作”，到达后回答终止。距离数值不写进文字，无 swap 训练。候选编号变化时，动作、真实后继和 Q 一起对应。
- **预算与评测：**两轮训练、512 次更新，实际 batch 为 1，无梯度累积；固定首轮自由生成和五图 120 题完整闭环分别评测。正式设置见[原始合同](../configs/pilot_path256.json)，运行 `runs/path10_sft_20261001`。

### 已观察到什么

| 观察范围 | 结果 |
|---|---|
| 64 条同图验证轨迹的整题文字损失 | 从 0.3083 降至 0.02061；这是验证损失 |
| 256 条训练题的固定首轮 | 最近候选 93/256；完整排序 19/256 |
| 64 条同图验证题的固定首轮 | 最近候选 18/64；完整排序 4/64；排序格式 64/64 合法 |
| 五图 120 道保留题的固定首轮 | 最近候选 47/120；完整排序 7/120 |
| 同一保留集的完整闭环 | 到达 18/120；正确结束 15/120；最短 0/120 |
| 闭环中全部 3458 个非终止轮 | 逐对远近判断正确 5186/10436；这是关系对数，不是正确轮数 |

验证与保留题的首轮动作都遵循模型自己生成的排序，包括错误排序。因此，“能输出合法排序”和“动作与自己说的一致”都不等于远近判断正确。

地图本身也要单独看：直接按冻结地图距离贪心，在这 120 题上到达 120/120、最短 69/120。这是代码使用地图选动作的参照，不是 LLM 成绩；也说明“地图最近”与“图上最短”不能混作同一个标签。

### 这些现象能说明什么

- 失败已出现在训练题首轮，不能全部归于走错之后的误差累积或未见图。
- 闭环全程也有大量关系错误，但现有总数不能说明第几轮开始出错、错误是否随轮次累积。
- 低整题文字损失不能代替关系准确率。它尚未告诉我们失败主要来自监督、优化、编号绑定还是关系计算。
- 当前状态和合法后继由环境提供；这轮结果主要涉及关系读取、动作选择与执行后的表现，不能直接推成“状态估计能力失败”。

### 两项已完成的局部对照

两组均沿用上述完整轨迹、文字协议与训练预算，无 swap，分别从新初始化训练接口。

| 条件 | 相对原始训练只改什么 | 同图验证首轮最近候选 | 当前用途 |
|---|---|---:|---|
| [关系 token 加权](../configs/pilot_path256_relation_weighted.json) | 排序可变内容及末尾 action 编号的损失权重 ×16 | 12/64 | 此设置未改善该读数，结束此消融 |
| [固定 gate](../configs/pilot_path256_fixed_gate.json) | 将地图残差门控固定为 tanh(g)=0.1 | 23/64 | 训练首轮也仅 101/256，未建立可靠读出；结束此消融 |

原始模型与固定 gate 的实际地图注入均非零。这里只排除了“地图通路完全没有数值输入”这种说法，不能用注入大小代替正确使用地图的证据。上述两组没有完整的逐轮对照结果，不据此排除所有加权或优化方案，也不继续扩展参数试验。

## 2. 小样本原接口：固定训练首轮能拟合，留出未成功

### 条件 A：原混合接口＋整题 SFT

- 寻路与积木分别训练，基座均为冻结的 Qwen2.5-1.5B-Instruct，各自地图也冻结；不共享训练后的接口权重。
- 每个任务取 16 条完整训练轨迹、4 条留出轨迹；寻路从四图各取 4／1 条，积木从不重叠的训练／留出棋盘各取一题。
- 输入当前、目标和全部合法后继 Q，训练状态投影、角色／编号和门控 cross-attention。
- 保留完整轨迹与“排序 → 解释 → 动作”监督，无 swap 训练。
- 从早期 256 步继续训练，按固定训练集的整体损失和关系损失判断平台，按整体训练损失选权重；**下面只评测了固定首轮**。设置见[小样本合同](../configs/kv_pilot.json)、[续训合同](../configs/kv_convergence.json)。

### 结果

| 任务 | 训练首轮完整排序正确 | 留出首轮完整排序正确 |
|---|---:|---:|
| 寻路 | 16/16 | 0/4 |
| 积木 | 16/16 | 0/4 |

### 能说明什么

- 原接口能拟合这些固定训练首轮的答案；**没有证明整条训练轨迹的每轮都拟合了**。
- 四道留出题上未观察到成功，样本不足以确定一般泛化水平。
- 文字本身含任务信息，原题答对不能单独证明读了 Q。末尾动作的低损失还可能来自复制前文排序。
- 旧 Q 交换测试属于文字与地图不一致的输入干预，不用它来断言自洽任务下模型一定不读图。

## 3. K/V 解耦与尺度校准：小样本拟合有所变化，原因仍未定位

### 条件 B、C：只改接口，保留整题 SFT

这里的 K/V 是 attention 的 key 与 value，不是地图的状态 Q 与动作位移 V。

| 分支 | 接口变化 | 保持相同的设置 |
|---|---|---|
| B：K/V 解耦 | K 只含角色／编号；V 只含投影后的状态 Q | A 的题集、完整轨迹、文字、损失和冻结范围，无 swap 训练 |
| C：校准 K/V | 在 B 上对 value 分支使用全状态共享的尺度系数 | 同上；尺度按训练位置的测量确定，见[校准规则](../configs/kv_scale_followup.json) |

两任务分别训练、分别校准。各条件续训到各自记录的平台，预算并非完全相同；下表仍是固定首轮自由生成。

### 结果

| 任务 | 接口 | 训练首轮完整排序正确 | 留出首轮完整排序正确 |
|---|---|---:|---:|
| 寻路 | B：K/V | 16/16 | 0/4 |
| 寻路 | C：校准 K/V | 16/16 | 0/4 |
| 积木 | B：K/V | 1/16 | 0/4 |
| 积木 | C：校准 K/V | 13/16 | 0/4 |

积木未校准 K/V 的排序开头最近候选为 16/16，完整排序却只有 1/16，末尾动作正确 5/16；校准后排序开头仍为 16/16，完整排序为 13/16。

### 能说明什么

- 积木确有“开头选对、长排序或末尾动作出错”的现象，应把关系判断与输出保持分开计分。
- 寻路三种接口在这些训练首轮都能拟合，不能凭这一结果选定哪种接口更适合完整任务。
- 现有有效比较没有定位编号绑定、状态混合或非线性比较谁是主要瓶颈，也不直接推出应增加 mask、关系模块或打分头。

## 4. 每一轮都要看：现有证据缺在哪里

### 已覆盖与未覆盖

- **已有固定首轮结果：**原始 256 条轨迹基线及 A／B／C 小样本，说明进入轨迹时的判断。
- **已有全程汇总：**原始基线五图闭环，覆盖模型自己实际到达的状态；目前正文可确认上述 3458 轮总数。
- **尚缺完整对照：**在示范轨迹的每一轮固定真实状态和历史，让模型独立生成当前回答；以及同一批权重的逐轮闭环错误分解。小样本 A／B／C 也缺这些全程结果。

训练数据里只有首轮有三个候选，其余轮的候选更少。首轮分数既不能代表后续轮，也不能与后续轮不加区分地平均；单候选轮选对动作尤其不能说明比较能力强。

### 后续评测口径

1. **示范轨迹逐轮判断：**给截至该轮的正确历史、真实状态和当轮地图，自由生成本轮完整回答。覆盖首轮、中间轮、近目标轮和终止轮；用于看模型在尚未被自身错误带偏时会不会判断。
2. **闭环逐轮判断：**模型自己选动作，环境执行并反馈真实新状态。逐轮记录关系、动作和终止错误，观察首次错误及后续传播。
3. **分别计分：**关系逐对准确率、完整排序、最近候选、动作合法性、动作是否遵循排序、终止判断；整题另报到达率和路径长度。地图距离排序与图上最短动作分开。
4. **交代分母：**按训练／同图留出／新图、行动轮次、剩余距离和候选数量分列，同时保留题数、轮数、关系对数。总分与分层结果一起读。

现有 `evaluate_graph_readout.py` 只取首轮；`summarize_graph_eval.py` 能重放已有闭环并分首轮／后续轮，但尚不是上述完整逐轮对照。本次整理没有运行模型，也没有把这些缺口写成已完成。

## 5. 接下来只保留能回答明确问题的工作

### 优先事项

先整理无 swap 完整轨迹条件的逐轮证据，回答：**在真实一致的输入下，是关系先错、长回答写错、动作执行不一致，还是终止判断错？这些错误出现在什么轮次和状态？**

已有日志能回答的先用已有日志；确实缺生成结果时，再明确最小评测范围。看到失败位置后才决定是否改训练，不再由已归档的 swap 成败推出新架构或新训练。

### 已有但暂不推进的自然目标草案

工作树保留了未提交、未启动训练的 `path_natural_qonly_ce.json`、`path_natural_qonly_rankids15.json` 及相关实现。设置是：

- 沿用冻结地图、冻结 LLM 和校准 K/V；只训练接口。
- 每道独立状态题配两个真实目标，使地图最近候选改变；训练共 2048 道，同图新目标验证 256 道、新图测试 256 道。
- 文字只给候选编号；当前、目标和候选位置从 Q 输入。候选动作与 Q 一起重编号，无人工 Q swap。
- 输出完整“排序 → 解释 → 动作”；拟比较普通 CE 与仅排序编号 token ×15，两组均十轮。
- **它仍是独立状态读出，不覆盖完整轨迹各轮。**它只能检验这种删去文字状态信息后的读出条件；不能补齐第 4 节的主任务证据。

该草案没有训练结果，暂不列入执行 TODO。其用途是否必要，要由有效任务的逐轮观察决定。动作前置、读取 mask、共享打分头同样没有足够证据排出优先级，暂不推进。

## 6. 已退出判断的实验

小样本完整／短式 swap、1024 题短式、十轮完整首轮，以及由这些权重得到的泛化、hidden-state 与探针分析，统一移入[归档](archive/swap_training.md)。完整寻路的 swap 破坏文字与真实后继 Q 的一致性；这条实验链不再用于解释当前瓶颈，不续训、不等余下分数、不据此安排下一组实验。

整体随机重编号仍保留：它同步改变编号和对应的真实动作、后继及 Q，保持每道题自洽。归档保留原设置和负结果以供追溯，不将“退出判断”写成“已证明 swap 是全部失败的原因”。
