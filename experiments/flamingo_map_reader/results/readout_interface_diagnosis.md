# 寻路读取：16 题能到 6e-5、1024 题停在 ln2 的机制诊断

测量记录 · 2026-10-03 · 只读诊断，不含训练

**结论：扩大后停在 ln2 不是"训练不足"或"样本变难"，而是模型只学会了纯文字的答题策略（答案是这两个候选之一），地图对选择没有任何贡献。原因是接口给语言模型的是一份固定线性混合，而本题需要的比较是二次型，混合必须被反解才能用——这一反解在 1024 题规模下没有发生。**

## 1. 被比较的两个条件

| | 小样本 16 题 | 扩大 1024 题 |
|---|---|---|
| 运行目录 | `kv_convergence_20261002/graph_calibrated_pairwise_counterfactual` | `path_readout_expanded_20261003/training` |
| 训练记录 | 16（长度 10） | 1024（长度 2–10） |
| 候选对选法 | 全是"最近 vs 最远" | 任意非同距对 |
| 距离差中位数 | 0.181 | 0.193 |
| 距离差范围 | 0.018 – 0.384 | 0.0004 – 1.509 |
| `decision_ce` | 6e-5（成对全对） | 0.70015（13 次测量最低值，从未低于 ln2=0.6931） |
| 到达平台步数 | 2304 | 12288 仍未进入平台 |

两次运行的 batch=1、学习率 2e-5、weight_decay 0.01、优化器 AdamW、`value_scale`=14.410007800237114、接口维数、监督方式与读取样式全部相同，因此"同一套监督、只是数据变多"这一前提成立，差异只能来自数据分布与规模。

## 2. 扩大后到底学到了什么（`diagnose_readout.py`，2048 个配对样本）

| 指标 | 测量值 | 含义 |
|---|---|---|
| `decision_ce` | 0.700148648902541 | 与训练流程自己记录的数值逐位一致 |
| 正确率 | 0.5117 | 与 0.5 无显著差别（n=2048，标准误 0.011） |
| `top_in_pair_rate` | 1.000 | 模型的首选**永远**是被点名的两个候选之一 |
| `mean_mass_in_pair` | 0.99929 | 99.93% 的概率质量压在两个被点名的候选上 |
| `mean_p_correct_minus_wrong` | +0.0081 | 对正确一侧的偏好约 0.8%，可忽略 |

按候选边际（两候选到目标距离之差）分成五档，**每一档的正确率都在 0.506–0.518**，包括距离差 0.49–1.38 的档位（小样本条件最大距离差只有 0.384）。所以"候选对变难/存在近似并列"不能解释这个结果：在距离差比小样本大 3.6 倍的地方，模型依然是对半猜。

`training_ce`=0.064 而 `decision_ce`=0.700，比值说明除决策 token 外的所有 assistant token 已近乎零损失。纯文字策略的损失恰为 ln2：模型读出"答案是 A 或 B"（这正是 `mass_in_pair`≈1 的来源），再对半分配。

## 3. 接口实际送达了什么（`diagnose_interface.py`）

对配对样本的前向做逐层挂钩。适配器前向返回 `hidden + tanh(gate) * read`，因此钩子直接相减即可精确取得读入项；只有注意力分布需要重算，重算结果与读入项的相对误差 0.54，与"差值仅为隐藏态的 1%、处于 BF16 有效位"的抵消量级相符（`rounding_loss_rate`=0，即读入项**没有**被舍入抹掉）。

| 层（0/8/16/24/27） | 小样本 16 题 | 扩大 1024 题 |
|---|---|---|
| `tanh(gate)` | −0.0054 … 0.0104 | −0.0014 … 0.0131 |
| 读入项 / 隐藏态 | 0.0056 – 0.25 | 0.0087 – 0.09 |
| 两槽注意力的绝对差 | 0.48 – 0.67 | 0.39 – 0.69 |
| **左候选正确时的槽位差** | **0.5225**（第 12 层） | **−0.2732**（第 12 层） |
| **右候选正确时的槽位差** | **0.5221**（第 12 层） | **−0.2729**（第 12 层） |
| 交换后决策位残差变化 | 0.098 – 0.42 | 0.018 – 0.026 |

两个关键事实：

1. **两个模型的注意力都强烈偏向两个被点名候选中的一个（绝对差 0.4–0.7），但偏向哪一个是与答案无关的** —— "左候选正确"和"右候选正确"两种情况下的槽位差在四位小数上相同（0.5225 vs 0.5221）。也就是说，模型从未学会把"题面点名的候选"与"该加权的槽位"绑定，注意力只是固定的位置／头模式。
2. 两个模型的 `tanh(gate)` 都在 0.01 量级，即地图通路在两次运行中都是**近乎关闭的细线**；区别在于交换对决策位残差的影响，能解出题的模型是 10–42%，停在 ln2 的模型只有 2–3%。

## 4. 这个标签到底需要什么计算（`diagnose_scoring.py`，1024 个训练对）

`graph.py:68` 定义 `candidate_distances = ‖后继Q − 目标Q‖`，所以标签恰是 `sign(‖v_L − v_G‖ − ‖v_R − v_G‖)`，是记忆里那三个向量的**确定性函数**。

| 打分函数 | 留出 512 对的正确率 |
|---|---|
| 线性 `w·[v_候选, v_目标]` | 0.551 |
| 二次 `[v_候选, v_目标, v_候选·v_目标, v_候选², v_目标²]` | 0.803（权重共享的梯度拟合，未完全收敛） |
| 二次闭式解 `w = [0, 2, −1, −1]` | **1.000** |

因为 `−‖v_c − v_G‖² = −Σv_c² + 2Σv_c·v_G − Σv_G²`，闭式解必然满分。所以：**该任务需要的是候选与目标的乘性交互，线性打分只有 0.55（近似随机）。**

## 5. 机制

读入 `r = Σ_i α_i v_i`。当 α 与题面无关（第 3 节实测）时，残差里只有三者的**固定线性混合**，而目标函数是它们的二次型。要算出答案，语言模型必须先从混合中把 `v_候选` 与 `v_目标` **分离**，再让 MLP 做乘积——这等于在没有监督的情况下隐式反解一个线性方程组，而这条通路的信噪比只有隐藏态的 1%。

- **16 题能到 6e-5**：交换 Q 仍然改变混合 `r`，所以 16 个标签可以在 `r` 空间里被"查表"拟合，不需要分离混合。32 个样本上跑约 72 个 epoch，查表很容易。这也与"同一权重放到 768 个候选对上只剩 55 对正确"一致——它拟合的不是比较规则。
- **1024 题停在 ln2**：查表不可行，通用规则又需要分离混合；同时文字提供了一条 100% 可靠的捷径（"答案必是这两个之一"，损失恰为 ln2），优化器停在这条捷径上。

## 6. 建议方向

诊断把瓶颈定位在**接口的送达形式**，而不是监督、规模或超参。最小且机制上对症的改动是：

1. **让每个候选的状态各自落到固定文本位置，并用读取掩码限制该位置只读对应槽位。** 这样残差里是纯 `v_i` 而不是混合，无需反解；语言模型只要用自注意力把"候选位置"与"目标位置"连起来，就能用自身 MLP 形成所需的乘积——而这正是冻结语言模型最擅长的操作。改动面小，且直接消除第 3 节测到的失败模式。
2. **共用的成对打分头 + 成对 logistic 损失**（RankNet 式）：让比较有一个直接的、稠密的监督目标，不再依赖语言模型逐字输出数字，从根上绕开"细线 + 反解"。

两者都不在当前接口的表达能力之外，属于架构改动，需在动手前确认。
