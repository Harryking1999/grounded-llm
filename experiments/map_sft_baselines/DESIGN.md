# 积木：统一增强数据的地图与 SFT 多基线方案

**本轮先统一增强数据，再比较有无地图、仅训接口与全参训练。采样以长轨迹为先，在这一条件下扩大状态覆盖，并兼顾起点和目标大小的多样性。**

- **主实验：**B0–B4，共五组，使用同一批数据。
- **监督格式：**无地图输出 R＋A；有地图输出 R＋排序＋A。
- **共同数据：**保留全部 1,000 张训练来源棋盘，取消编号增强，目标为每 epoch 50,000 条不同样本。
- **当前状态：**增强数据和新训练尚未启动，当前 SFT 续训不变。B5–B7 移至文末，仅作补充实验，不默认运行。

## 1. 实验目的与依据

### 1.1 现有证据

当前地图组与 SFT 同时改变了数据、动作教师、输出格式和训练参数范围，不能把成绩差异直接归因于地图。已核实的差别是：

| 普通动作监督 | 旧地图数据 | 当前多路线 SFT |
|---|---:|---:|
| 来源棋盘 | 1,000 | 1,000 |
| 不同物理动作（形状＋坐标） | 664/664 | 664/664 |
| 不同当前状态—目标组合 | 62,230 | 292,758 |
| 不同状态—目标—监督动作 | 62,230 | 337,299 |
| 普通路线最短性 | 44.23% 最短 | 全部经求解器认证最短 |

旧数据每张棋盘取官方路线，再采 **32 条随机合法路线**，由前后状态组成任务，优先选长且地图贪心成功的 8 题，再制作六份编号变体。这里的 32 是每张棋盘的路线数，训练来源始终是 1,000 张。

8,000 题只有 2,400 个不同起点，208 张棋盘的八题共用同一起点。因此需要增加动作出现的任务情境，不能只靠重复编号扩大样本数。完整分布与审计边界见[策略分析第 6–7 节](../llm_task_sft/results/policy_comparison.md)。

### 1.2 本轮回答三个问题

| 问题 | 比较 |
|---|---|
| 冻结主干是否限制任务学习？ | B2 对 B1：同地图、接口、数据和输出，只改变主干是否训练 |
| 新增接口本身是否有益？ | B4 对 B0：均无地图、全参训练，比较有无接口 |
| 地图方案是否有额外收益？ | B1 对 B3；B2 对 B4：匹配接口和训练范围 |

最后一项检验的是**地图输入＋排序监督的整体收益**，因为有地图时也增加了排序输出。本轮把覆盖增强与最短示范作为共同条件，不单独量化它们相对旧数据的收益。

## 2. 共同数据：长轨迹优先，兼顾覆盖

### 2.1 固定来源与合格标准

- **来源：**原来的全部 1,000 张训练棋盘。候选采样、产量检查和最终验收均覆盖全部来源。
- **地图：**统一使用 `tree_continue_986cb4d/checkpoints/step_015000.pt`，始终冻结 Q。该版独立贪心为 397/510，旧版为 345/510；这用于说明版本选择，不保证 LLM 接图后的成绩。文件位置见[开发机手册](../../DEVELOPMENT_MACHINES.md)。
- **合格轨迹：**逐步选择新版地图距离最小的合法候选，成功到达目标，且路线长度等于求解器认证的真实最短距离。
- **一致标签：**动作、向量和排序均按新版 Q 重新生成；所有组共享动作标签。求解器仅用于离线认证和评测裁判。

**长的是任务所需的最少步数，示范本身仍然是最短解。** 合格路线每一步都合法、保留目标、保持可解，并使真实剩余最短距离减少 1。地图排名不加人为距离容差，也不将非第一名改写为第一名。

### 2.2 每张棋盘如何扩充候选

1. 取官方路线，再采 **128 条随机合法路线**，收集沿途物理状态。
2. 将前后状态组成不同起点—目标，去重并精确求解，保留真实最短距离至少 6 步的任务。
3. 检查新版地图贪心，仅保留成功且最短的路线。
4. 合格数量或覆盖不足时，将该棋盘的随机路线总数增至 **256、512 条**，继续补采。

旧地图 64,155 个决策的最优候选全部唯一，固定起终任务通常只有一条严格贪心路线。因此本轮主要增加**不同起终任务及其路线**；新版 Q 若出现真实并列最优动作，可保留产生的不同合格路线。

### 2.3 入选顺序：长度 → 新状态覆盖 → 起点与目标多样性

每张棋盘从合格池选 49 条普通轨迹，按以下顺序逐条选择，不设置必须填满的分层配额：

1. **先选长的。**按真实最短步数从长到短取；较短任务不会因为更均衡而挤掉较长的合格任务。
2. **同长度优先增加状态覆盖。**选择能为当前已选数据增加最多不同“状态—目标”组合的路线，每选一条后更新计数。
3. **新增覆盖相同时兼顾分散。**先选该棋盘内已入选次数较少的起点，再选较少出现的目标大小，最后优先新目标。目标大小按 0、1–2、3–4、至少 5 格统计；这些档位仅用于同等候选的优先选择，不设配额、不强制轮转。
4. **仍相同则固定随机选择。**种子为 20261013；棋盘处理顺序也固定，确保可以复现。

例如，某棋盘有 20 条合格 9 步路线和 100 条合格 8 步路线，就先取全部 20 条 9 步路线，再从 8 步路线中按覆盖和多样性选 29 条，不为平衡分布而改取 7 步路线。

补采后将新旧候选合并，重新按上述规则选择。按“起点—目标—物理动作序列”去重，另统计忽略动作顺序后的移除集合。覆盖不足时继续补采，不悄悄降低长度优先级。

### 2.4 数量与验收

| 项目 | 目标或规则 |
|---|---|
| 来源 | 1,000/1,000 张，每张均保留 |
| 每张样本 | 49 条不同普通轨迹＋1 条初始即目标 |
| 总样本 | 49,000＋1,000＝50,000 条完整多轮样本/epoch |
| 覆盖目标 | 至少 292,758 个不同非终止“当前状态—目标”组合，参照现有 SFT |
| 编号 | 统一按 `(shape_id,row,col)` 排列，不制作重编号副本，不携带地图排名 |

验收报告必须分清两类信息：

- **硬性目标是否满足：**逐棋盘合格轨迹数、实际入选数、最短性与地图一致性、状态—目标覆盖及缺口。
- **多样性达到什么程度：**逐棋盘和全局的题长、不同起点/目标、目标大小、状态—目标—动作、移除集合、合法候选数及地图前两名距离差。起点和目标大小尽量分散，但不要求分布均匀。

上述产量和覆盖尚未验证可达。达到候选上限仍不足时，报告缺口再调整方案；不删棋盘、不将配额转给易生成棋盘、不重复凑数。若不能达到覆盖目标，应如实报告，不能宣称已对齐。

### 2.5 数据与结论的边界

- 五组共享最终任务、动作、编号和终止样本，只按有无地图生成对应输入与输出格式。
- 只从指定训练来源取数据；先锁定共同参考路线，将既有留出任务的初始状态—目标及参考决策对排除出新训练。原新初始棋盘评测保持来源隔离，不根据 510 题的失败个例造题。
- 严格地图贪心通常只给同一状态—目标一个动作标签。本轮对齐的是情境覆盖规模，不承诺复制旧 SFT 的多最优动作分支分布。
- 新版 Q 的训练关系与监测题重合尚未审计，制作数据时记录曝光边界。训练只保留地图成功且最短的示范，评测仍保留地图失败题，检查效果能否超出筛选区域。

## 3. 五条基线与监督输出

### 3.1 主实验 B0–B4

所有组从原始 **Qwen2.5-1.5B-Instruct** 开始，共用第 2 节增强全集。接口使用相同随机初始化，不加载旧 adapter 或已训练 SFT 权重。

| 编号 | 条件 | 可训练参数 | 输出 | 用途 |
|---|---|---|---|---|
| **B0** | 无地图、无接口 | LLM 全参 | R＋A | 普通任务 SFT 主基线 |
| **B1** | 新版地图＋接口 | 仅接口，LLM 冻结 | R＋排序＋A | 原地图架构使用增强数据 |
| **B2** | 新版地图＋接口 | LLM 全参＋接口 | R＋排序＋A | 检验解冻主干的收益 |
| B3 | 无地图、保留接口 | 仅接口，LLM 冻结 | R＋A | 对照 B1 |
| B4 | 无地图、保留接口 | LLM 全参＋接口 | R＋A | 对照 B2，并与 B0 检查接口作用 |

**全参＋接口不包含地图 Q。** B3/B4 按以下方式保留接口：

- 结构、候选地址、角色、槽位和 mask 与地图组相同。
- 状态内容改为固定、各槽位不同的非零伪向量，与棋盘和目标无关；候选数量保留，因为文本也提供全部合法候选。
- 接口从头训练并参与正常前向计算。这是训练对照，不是推理时临时拔掉地图。

### 3.2 每轮监督格式

R 是现有 SFT 的事实短依据，A 是动作/停止标记。地图排序为真实 Q 的 **Top-10＋current**，按距目标从近到远排列。

**有地图：R → 排序 → A。**

```text
Reason: Clearing {cells} is legal, preserves all goal cells, and leaves a solvable board with one fewer removal needed.
Map-distance ranking to the goal, closest to farthest: {ranking}.
<action>{candidate_id}</action>
```

**无地图：R → A。**

```text
Reason: Clearing {cells} is legal, preserves all goal cells, and leaves a solvable board with one fewer removal needed.
<action>{candidate_id}</action>
```

花括号由真实动作、裁判和 Q 填写，不由教师自由编写。一步到达时，R 末句改为 `leaves exactly the goal board`。到达后所有组均输出同一达标短句＋`<done/>`，不输出排序或长总结。

## 4. 统一训练设置

正式参数见 [configs/study.json](configs/study.json)。以下说明各组共同执行方式。

| 项目 | 统一设置 |
|---|---|
| 固定训练预算 | 每条基线一次性配置为 20 epoch，每 epoch 50,000 条；每 epoch 12,500 次更新，共 250,000 次更新 |
| 训练卡与 batch | 每条基线使用 2 张卡；每卡 micro-batch 1，梯度累积 2 次，global batch＝2×1×2＝4 |
| 优化 | AdamW 与完整 20 epoch 的 warmup/cosine 调度，具体参数读取正式配置 |
| 数值与内存 | BF16、gradient checkpointing；完整对话训练，不截断动作或停止标签，先检查最长样本 |
| 数据采样 | 每张棋盘样本数相同，普通/初始即目标样本数为 98:2；损失中不另设类别或样本权重 |
| 随机性 | 各组采用相同种子、可匹配的数据顺序；关键差值再补两个种子 |
| 输出上限 | 暂定全组 256 token/轮；按最长监督答案检查，必要时统一调高并在训练前锁定 |
| 环境预算 | 同样的状态、全部合法候选、历史和停止解析；每题最多 32 次动作 |

训练与评测分开：每条基线在训练端使用两张卡，一次性训练到 20 epoch；每 0.5 epoch（6,250 次更新）保存完整断点，并将该点推理所需的权重和配置自动同步到 4090 评测队列。训练保存后继续，不等待远端评测完成，优化器和学习率调度连续运行。完整恢复状态保留在训练端。补充基线若启用，也使用相同预算。

**损失统一为标准 SFT token-level Cross-Entropy。**完整多轮对话中，所有有效 assistant 监督 token 一起取平均；user、system 和 padding 标为 -100。不按 R、排序、A 分段加权，也不先按轨迹平均或设置物理任务权重。两卡梯度累积时按整个 global batch 的有效 token 总数归一化，避免长短样本在不同卡上引入隐式权重。

地图组的排序 token 与其余监督 token 权重相同，因此排序较长时会自然占据更多 token；记录 token 数、loss、步时和 GPU 小时，不用跨组绝对 loss 判断任务能力。

## 5. 统一评测与诊断

### 5.1 评测对象与时点

- **只用既定 510 题**，在 0.5、1.0、1.5……20.0 epoch 自动评测，共 40 个评测点。B1/B2 同时运行第 5.4 节的固定 100 题地图内容探针。
- **评测统一使用 4090 的 1–4 号卡，0 号卡备用。**所有基线共用这四张评测卡，由队列分配任务分片；评测不占用各基线的两张训练卡。
- **权重完整传输后再入队。**训练端保留待同步权重，评测优先领取最新检查点的待评分片并回传结果；出现积压时保留所有待评点，不跳过半轮评测。最终须评齐各基线的 40 个点再验收。
- **主结果固定第 20 epoch** 的到达目标率，同时报告完整曲线，不按各组最佳点判胜。到达且正确停止率保留为诊断指标。
- 510 题已参与前期选择，属于监测集；独立泛化结论需另行封存评测，本轮不自动增加。

### 5.2 TF 与 RO 的含义

| 模式 | 输入和执行 | 回答的问题 |
|---|---|---|
| **TF：参考动作推进** | 共用 510 题求解器最短参考路线的 3,690 个非终止状态和编号；逐状态单独作答，提供同题面、当前棋盘与真实已执行动作，不拼接 assistant 示范历史。模型自由生成当前回答，其动作不改变后续参考状态 | 相同状态下，动作与排序判断是否正确？ |
| **RO：自主 rollout** | 相同起终任务，保留模型自身完整历史并执行实际动作；途中不由求解器纠正 | 自身轨迹上的判断是否正确，最终能否到达目标？ |

这里的 TF 指参考轨迹决定状态，不是逐 token 强制输入正确答案；仍沿用本方案已确定的共同状态评测。它与旧版带 assistant 示范历史的 reference 不同，结果独立报告。TF 可逐状态配对；RO 的状态由各模型自身动作决定，单步均值不能脱离整题到达率解释。

### 5.3 主报告列与计分口径

每条基线维护一张 0.5–20 epoch 总表，每个评测点一行。**到达目标只报 RO；其余列按 TF／RO 顺序并列。**

**地图组（B1/B2；补充实验启用时含 B5/B6）：**

| epoch | 到达目标 | 保持可达 TF／RO | 地图最优 TF／RO | 位置 NDCG@1 TF／RO | 位置 NDCG@10 TF／RO | 距离 NDCG@1 TF／RO | 距离 NDCG@10 TF／RO |
|---|---|---|---|---|---|---|---|
| 0.5 … 20.0 | — | —／— | —／— | —／— | —／— | —／— | —／— |

**无地图组（B0/B3/B4；补充实验启用时含 B7）：**

| epoch | 到达目标 | 保持可达 TF／RO | 单步最优率 TF／RO |
|---|---|---|---|
| 0.5 … 20.0 | — | —／— | —／— |

具体定义如下：

| 指标 | 判定与统计范围 |
|---|---|
| 到达目标 | RO 中实际到达目标的题数／510，报告计数与百分比；不将参考轨迹必然到达算成模型成功，也不要求在该列同时正确停止 |
| 保持可达 | 在动作前仍可解且未达目标的状态中，模型选择合法动作后目标仍可达的比例 |
| 地图最优 | 在未达目标且有合法候选的状态中，所选动作的后继 Q 到目标的距离为所有合法候选最小值的比例；真实并列最小均算对 |
| 单步最优率 | 与保持可达使用同一统计范围；所选合法动作使求解器给出的真实剩余最短步数减少 1 的比例 |
| 位置 NDCG@1／@10 | 评价模型输出的候选排序，gain 为真实地图排序位置倒数 `1/r`，真实距离并列时取所占位置 gain 的均值 |
| 距离 NDCG@1／@10 | 评价同一候选排序，gain 为该状态全部候选的地图距离归一化值 `(d_max-d)/(d_max-d_min)`；距离全相等时均为 1，并另记数量 |

计分时统一遵守：

- **动作错误计零。**在相应统计范围内，非法动作、提前停止或动作无法解析均计错；RO 已经无解的后续状态不重复计入保持可达和单步最优率分母，但仍计入地图最优与 NDCG。
- **NDCG 沿用现有定义。**使用线性 gain、`1/log2(i+1)` 位置折扣，并按理想排序归一化；current 不参加候选 NDCG，排序无法解析或缺失位置计零。对所有未达标且有候选的状态逐轮计分后求均值，@1 指排序首位，不是任务首轮。定义来源见[现有地图评测设计](../flamingo_map_reader/DESIGN.md)。
- **记录分母。**保存 TF／RO 各自的有效决策数及分子；NDCG 保存计分状态数。未完成的评测填 —，不以部分结果替代整点。
- **区分两种最优。**地图最优是符合 Q 的排序；单步最优是真实最短解进度，两列不能直接视为同一能力。

到达且正确停止、首轮、配对救回/退步、首次致命错误、成功路线额外步数、R 的事实正确率及训练 loss/耗时保留在诊断附件，不增加主表列。

结果另按题长、来源、地图独立贪心成功/失败分组，检查改善是否局限于地图擅长的任务。

### 5.4 地图内容探针

从既定 **510 题测试集中无放回随机抽取 100 题**，使用固定种子 20261013 并保存题目清单。B1/B2 及各检查点共用这 100 题的配对状态，比较正常 Q 与候选后继 Q 反序。保持模型、文字、历史、地址、输出格式和预算相同，观察排序和实际动作是否改变。

这 100 题仅用于地图内容探针；整题评测仍使用全部 510 题。探针检查模型是否使用地图内容，不替代训练对照，也不作为新的整题成功率。

## 6. 执行顺序与结果解释

### 6.1 执行顺序

1. **固定数据配置：**使用正式配置；求解超预算记为未知，不当成无解。
2. **生成并验收数据：**遍历全部 1,000 张棋盘，补采后验收逐棋盘数量、最短性、地图一致性和覆盖，形成共同数据文件。
3. **028 先同时跑 B0–B3：**八张卡分为四对，每条基线独立训练、保存和记录状态。
4. **空出的卡接 B4：**完成或获准停止的训练对继续队列里的下一项；不自动增加方案以外的实验。
5. **平台期独立判断：**至少 5 epoch 后，根据连续完整的整题评测标记平台期，不能用低 loss 或缺失评测自动判断。提前结束时报告实际 epoch 与完整曲线，不冒充已完成 20 epoch。关键差值再补种子，B5–B7 不在默认预算。

### 6.2 如何解释结果

| 结果 | 可支持的判断 |
|---|---|
| B2 优于 B1 | 共同配方下，解冻主干有益 |
| B4 优于 B0 | 无地图时，增加可训练接口本身有益 |
| B1 优于 B3，或 B2 优于 B4 | 对应训练范围下，地图＋排序监督整体有益 |
| B2 优于 B0，但与 B4 接近 | 地图方案额外收益尚未确立，新增接口可能解释改善 |
| 正常地图比反序更好，且实际动作改变 | 模型使用地图内容；不等于它必然优于无地图训练 |
| 增强后各组仍接近 | 当前任务与预算下未观察到明显增益，不能把历史差距全归因于采样 |

B1 与 B0 同时改变地图、训练范围和输出，只能比较系统表现。更广的数据、更短的示范和更低的 loss 都不能替代任务结果。

## 7. 补充实验（不默认运行）

### 7.1 B5–B7：数据覆盖贡献

仅在需要量化“新增训练情境带来多少收益”时安排，不是主实验的前提。

| 编号 | 条件 | 可训练参数 | 输出 | 配对比较 |
|---|---|---|---|---|
| B5 | 新版地图＋接口，小覆盖子集 | 仅接口 | R＋排序＋A | B1 对 B5 |
| B6 | 新版地图＋接口，同一子集 | LLM 全参＋接口 | R＋排序＋A | B2 对 B6 |
| B7 | 无地图、无接口，同一子集 | LLM 全参 | R＋A | B0 对 B7 |

子集与预算按以下方式确定：

1. 仍保留全部 1,000 张来源棋盘，每张从增强全集按第 2.3 节规则取 8 条普通任务，共 8,000 条；保留同一 1,000 条初始即目标。
2. 普通路线各重复六次，每张棋盘再为其中一条增加一次，共 49,000＋1,000 条。序列重复是这里有意设置的低覆盖条件，不做编号增强。
3. 损失同样采用有效 assistant token 的统一平均，不额外校正六/七次重复的权重；记录重复次数差异。
4. 子集来自新版地图全集，不能拿旧地图数据替代。记录题长、目标和候选数分布差异；比较的是相同训练预算下新增情境的整体收益，不是同题多路径的独立贡献。

### 7.2 后续可选增强

- **几何变换：**旋转、翻转或平移训练棋盘；同步变换动作，重新生成 Q、排序与贪心路线，并认证最短。
- **困难可解状态：**从训练棋盘补采容易误删目标或留下孤立格的任务，仍遵循长轨迹优先；不把无解状态标成可恢复。

这两项不加入首批数据。后续若采用，仍须向所有比较组提供同一批样本。
