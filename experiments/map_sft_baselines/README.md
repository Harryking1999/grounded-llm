## 八类FLAN大泛化：当前训练与选题设计

**本轮只训练地图1.5B的三个版本：4类、5类、6类。三个版本同时各用两张卡，从同一个基座分别开始。文字3B／7B暂不运行。** 推箱子和反向放积木不参与；移车、21／24点始终留作整类OOD。更大文字模型的比较仍是后续研究目标，不是当前运行组。

这里一条数据指一条完整求解轨迹，包含沿途多次动作及最后的停止回答，不是单步问答。三份50,000条数据不同；已有大类从同一任务候选池取嵌套子集，因此题目会有重叠。这样比较时，增加任务种类的同时会减少每个原任务的样本数；这项实验回答固定总数据量下任务广度的作用，不能单独分离“新增类别”和“旧类别样本减少”的影响。不是三次完全独立重新采样，也不是4类模型续训成5类、再续训成6类。

### 训练什么、给模型看什么

三组都是Qwen2.5-1.5B-Instruct加地图读取接口，Qmap冻结；LLM主干和读取接口一起训练。每个任务提供自己的已采用Qmap，新图或新人数可以使用另训地图。采用身份只维护在各任务的`Qmap/selection.json`。

每一轮模型收到任务规则、完整目标、环境更新后的真实当前状态、实际动作历史和全部合法动作编号。地图接口另收到当前状态、目标及所有合法后继的Q向量；文字里不直接提供精确距离或最优动作。模型先输出地图预测距离的排序，再给简短Reason和一个动作编号；到达完整目标后输出停止标记。这个Reason是简短动作说明，不是完整长篇CoT。

环境负责真实转移和合法候选枚举。因此本轮主要检验读取关系、选分支、连续完成与停止，不能将它写成LLM自己学会了环境转移。精确教师只用于离线认证和评分，不在执行时替模型选动作。地图监督的排序来自冻结Qmap，不把精确教师距离改写成地图预测。

### 训练轨迹怎样入选

1. 从对应任务来源产生完整的“起点、目标”查询，排除重复物理查询和受保护的验证关系。
2. 每步保留全部物理合法后继，按“即时动作成本＋地图预测的后继剩余成本”贪心选动作。
3. 精确教师逐步核对该动作是否保留最优完成；一旦走错、循环、不可达或超预算，整条候选不入选。不会用教师替地图改选动作再把它冒充地图成功。
4. 对入选轨迹生成Q向量、预测排序、动作及停止监督。评测题不按地图成功筛选。

所以训练集刻意限定在地图已经能正确最优执行的部分，验证／OOD则包含地图的失败题。两边成绩有差距并不自动证明LLM过拟合；还需看同题地图参照。按大类和小类平衡，不代表按每个精确距离层都均匀采样。

### 两个始终整类留出的任务

**移车出库：**不进入任何一档SFT。使用熟悉车辆配置的原占格MLP，取32种配置的可达分量，起终点精确距离限定1–7步；目标包含A到出口的完整排列和A未到出口的中间完整排列。先生成640个去重可达查询，再固定随机取500题；不用地图成功率筛选。一次动作是同一辆车沿自身方向合法滑动任意若干格，整次滑动计一步。这一范围不代表新布局或长原题已经解决。

**21／24点：**也不进入任何一档SFT。Qmap使用已采用的有限数字范围：来源数1–10互异四数，共210组；后缀来自这些四数运算图。500题中，四数到21／24各100题，三数后缀到21／24各100题，两数后缀到21／24各50题；都用精确有理数运算。后缀可以含分数或负数，并非重新从1–10选两／三个整数。只从精确可解查询抽题，不按Qmap成败抽题；本轮未另测任意中间数值多重集目标、5数初题或无限数字范围。一步合并两个当前数，因此可解题的剩余步数由元素个数决定，关键看是否保留解。

这两项的正式采样条件见[大OOD选题配置](configs/flan_generalization_ood_queries.json)，地图能力与LLM是否见过该类分别记录。

## 四任务联合SFT

[地图1.5B](configs/flan_four_50k_map.json)、[文字3B](configs/flan_four_50k_3b.json)、[文字7B](configs/flan_four_50k_7b.json)联合训练积木、二阶魔方、8-Puzzle与寻路，每任务12,500条，共50,000条。前三任务从已有正式轨迹均匀无放回抽样；寻路使用已采用固定图与纯Q，先锁定500个随机测试关系，再按长轨迹及新增状态—目标覆盖选择经精确距离认证的地图贪心路线，全程排除测试初始关系。测试不按地图成败筛选。

`src.multitask_prepare`准备两组相同物理轨迹，`src.multitask_data`按任务复用逐轮重编号；训练仍调用公共SFT，评测由`src.multitask_evaluate`分派既有任务裁判。地图组排序→Reason→Action，文字组去掉排序，模型与GPU拓扑沿用最近三组。学习率时程、batch和20轮上限不变，已有收敛判断改为自动停止：至少5轮、连续6个完整评测点未比既往最好提升5题。达到预算上限与满足收敛标准分别记录。

固定评测每任务500题，按任务分别报告，联合2000题供已有停止判断使用。该配置仅含上述四任务；汉诺塔、过桥等是否进入下一轮由任务组合决定。

## FLAN 1.5B 稀疏 cross-attention

[正式配置](configs/flan_four_50k_sparse_crossatt.json)比较每2层、每4层和仅最后3层接入地图，接入点均位于对应decoder层之前。Qwen2.5-1.5B的28层中，三组分别接入14、7、3层；间隔按一基层号整除选择，最后3层为第26–28层。配置中的各baseline仅覆盖自己的地图接入层设置，训练与评测共用此选择。

三组从同一1.5B基座重新初始化，复用原四任务50k数据、地图、重编号、全参训练、优化器、学习率、global batch、20轮上限及停止规则。保存频率保持每5k步；原固定2000题的RO／TF优先评整50k步断点，同类中新断点优先，其余断点在容量允许时补评。传输与评测使用相同优先级，当前分片完成后切换，源权重与已有答卷保留。028各用两卡训练，一卡参与评测；4090完成当前三组150k RO重评后接续，与028通过既有共享claim分配分片。150k原验证及小OOD仍单独报告，不并入新实验曲线。

该对照已停止训练及后续评测，已有同预算结果见[报告](results/report.md#8-稀疏cross-attention的同预算比较)。保留逐题结果、选定推理权重与最新完整恢复状态，清理其余中间张量，不再补曲线图。原缓存采用[稀疏实验缓存配置](configs/flan_sparse_retention.json)；产物与跨机路径由本实验runtime维护。

文字3B使用原完整断点续训。文字7B的原优化器状态已丢失，使用[动量校准配置](configs/flan_four_50k_7b_adam_calibration.json)，从保留的150K推理权重开始独立优化阶段：`src.train --resume SOURCE --reinitialize-optimizer`复用公共训练器，用原训练批次在零学习率下累计Adam动量，模型权重保持不变；随后学习率接原全局步数，Adam偏差修正步数按校准批数计。随机状态重新初始化；后续完整断点使用普通`--resume`，不重复校准。这不是原优化器状态的完整恢复。

## 150K RO重评测与类别内小OOD

三组FLAN模型的150K重评测范围由[重评配置](configs/flan_150k_reassessment.json)维护。每组使用准确的150K断点：原验证四任务各500题，另加积木、二阶魔方、8-Puzzle小OOD各500题。三组150K推理权重均保留；最新训练恢复状态见[报告](results/report.md#原训练停止与恢复条件)。只做RO，沿用各模型的上下文、生成和动作预算；独立重评目录不向原训练的自动停止曲线写入混合成绩。

小OOD保持对应原验证起点，积木取原认证最短清空路线最后一步之前的非空状态作为目标，即留一个合法块；魔方与华容道分别在距复原态1–3步的目标中固定种子取样，距离层题数尽量均分。题集生成不按地图成败筛选，参考路线用原精确环境认证。近复原的是目标，起点到目标的路线仍可能较长；规则化非复原目标可作后续独立条件，本配置先采用复原邻域。

这里的小OOD是类别内新目标任务，FLAN大OOD是未训练的新任务类别，另行准备。寻路训练本就含任意终点，旧积木路线中段目标OOD保留原题集及结果，不与本轮留一块题集拼接。

魔方仅在本轮FLAN小OOD评测及同题地图贪心参照中使用保留的低学习率2000步候选；身份由重评配置维护，逐题记录实际地图来源。原验证、其他任务、FLAN训练地图及任务selection保持不变。准备题集时通过`--cube-small-ood-checkpoint`传入该候选权重；原`qmap.pt`不覆盖。

评测资源可用`queue evaluate --workers-per-gpu N --worker-memory-gib G --poll-seconds S`在同卡并发独立分片；默认每卡一路，并发必须显式指定单进程所需空闲显存。重启加`--resume-workers`接管现有分片，仍由同一claim排除重复领取；资源参数不改变生成参数、单题预算或评分。节点使用情况在runtime维护。

`src.small_ood_prepare`复用原FLAN评测数据与任务环境，生成带`original`／`small_ood`标签的固定题集，并可用`--map-reference-out`跑同题冻结地图Top-1贪心。模型评测复用`src.queue evaluate`，只领取配置中`only_steps`指定的断点。每组完整结果的`by_cohort`与`cohort_report.md`分别报告七项500题成绩，包括到达与到达且正确停止；汇总3500题仅用于核对完整性，地图贪心参照使用相同动作预算、合法候选与终止目标，保留逐题动作和失败；它是经验参照。

## 运行入口

以下为接口形式，不表示许可重启或扩大已有运行；实际配置、机器与预算以本次任务为准。

```bash
python -m experiments.map_sft_baselines.src.prepare --config CONFIG --sources SOURCES --model-path MODEL --out DATA --workers WORKERS
python -m experiments.map_sft_baselines.src.queue train --config CONFIG --data DATA --model-path MODEL --root RUN
python -m experiments.map_sft_baselines.src.queue evaluate --config CONFIG --data EVAL_DATA --model-path MODEL --q-checkpoint Q --root EVAL_RUN
python -m experiments.map_sft_baselines.src.bridge --profile PRIVATE_RUNTIME_PROFILE
```

runtime profile 保存路径、节点、known_hosts 与传输映射；凭据仅通过 stdin 进入内存。模型与机器入口见[开发机手册](../../DEVELOPMENT_MACHINES.md)。正式参数从配置读取，不在队列或说明中另抄。

二阶魔方与8-Puzzle用 `src.restoration_prepare` 准备数据，训练、评测分片、桥接和缓存清理仍用上述入口。任务文字、物理动作、重编号和裁判位于 [restoration_sft.py](../../grounded_llm/tasks/restoration_sft.py)，复用已有任务规则和提示原文。魔方沿用QTM六动作与复原目标；8-Puzzle沿用所选地图的标准目标 `1 2 3 / 4 5 6 / 7 8 0`。

新任务各取50,000个不同非终止起点，不单独加入初始即终止样本；完整轨迹保留到达后的停止监督。先从全部可达状态锁定统一随机留出题，再用冻结Q选动作，只保留每步真实最短距离减少一且最终复原的路线。按最短路长度递减选择，同长度优先增加未见状态—目标覆盖；任何训练轮次均排除留出题初始状态。固定目标、有限状态空间下不沿用积木的绝对覆盖门槛；真实覆盖、长度分布、筛选比例和最长token数保存在数据 `acceptance.json`。题集不按Q成败筛选；Q本身的训练曝光不因此被排除。

这四组的评测按配置 `evaluation.priority_step_interval` 优先选择整 5 万步断点；`evaluation.prioritize_full_epochs` 将其余整数 epoch（每 12,500 步）排在半 epoch 前，同类中新断点优先，每个断点先 RO、再 TF、最后 probe。整数 epoch 必须补齐，半 epoch 在容量允许时补评。传输与评测使用同一优先级；在跑分片完成后才让出旧缓存，源权重与已完成答卷保留。低优先级断点评测暂缓，训练保存频率与评测题集不变。

四组从同一基座初始化，沿用原B2的优化器、学习率时程、batch、训练预算、生成和动作预算。内容MLP沿用既有诊断实现；重编号每个epoch重绑候选ID，不新增物理样本。028每组两卡；4090使用1–4号卡，评完且结果回传后删除推理缓存。028保留最新完整恢复状态及已评最佳模型；未评权重保留等待队列。

### 12块清空的三组对照

`src.blocks12_prepare` 从新种子生成原八形状、12次非重叠构造的候选棋盘，使用新地图，保留地图贪心成功且由精确求解器认证最短的清空轨迹。先按最短解长度降序，再按新增状态—目标覆盖选出50,000个不同起点；覆盖下限沿用原设计，不通过重复编号凑样本。三组共用物理动作、短Reason监督和题集；地图组另有地图与排序监督。没有初始即终止样本，轨迹末尾保留停止监督。采样数量、种子、覆盖下限和预算只维护于配置。

正式评测从 `tasks/blocks/data/clear1000.json` 按配置种子固定抽取500题，不按地图成功筛选；原1000题的非终止参考状态全部从SFT轨迹排除。该题集曾用于Qmap选模，数据覆盖、长度与token统计保存于数据目录的 `acceptance.json`。模型权重身份见配置的 `map_source` 与任务selection。

地图组沿用1.5B；3B、7B都是无地图全参SFT，采用已有FSDP训练实现。global batch均为4；保存与评测至少每整数epoch一次，整5万步和新断点优先。沿用现有训练、评测与按需传输入口，数据验收通过后队列才启动训练。

## 多节点评测

多节点评测通过同一主节点的 `.worker.claim/` 原子占位；非共享磁盘的节点通过 SFTP 访问这个目录。已有 worker 用 `--resume-workers` 接管，不能因等待过久就释放占位或重复领取。辅助节点使用独立 `--node-id` 和 `--coordination-profile`，完整答卷回传后发布摘要。训练后评测入口已有 `--training-queue` 或 `--after-training`；`--after-evaluation SUMMARY...`等待指定断点在各自run配置要求的所有模式、全部题目完成后接续，无需另造监控脚本。

bridge 先回传结果、再按配置清理缓存、最后发布推理权重。训练端保留完整恢复状态；评测未完成或仍有占位的权重不能清理。账号配额与整盘空间分别检查，跨机原始答卷、缓存状态和失败日志留在 runtime；传输重试不构成重启训练的授权。
