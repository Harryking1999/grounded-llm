# 移车出库 Qmap：跨布局泛化

当前范围为无墙6×6棋盘；144个训练、35个验证、37个测试场景，另有8道已知题。每题要求所有车辆到达指定位置，A在最右端。地图比较全部合法后继，不排除死路或使用搜索。规则和来源见[任务数据](../../../../tasks/rush_hour/data/README.md)，验收见[总报告](../report.md)。

**移车出库：主要差距发生在新布局。** 卷积方案把未见布局完成率从50.78%提高到54.59%，幅度有限。只改变普通车辆的字母名称，模型表现也会变化，说明它依赖了一些与物理规则无关的输入差异。针对这一点的编码对照尚无最终成绩。证据：[原基线](rush_hour_pairs_baseline.json)、[输入变化检查](../shared/input_isometry_validation.json)。

较好方案在三个各1,024题的测试组中完成：熟悉布局新关系1,006题（98.24%）、未见目标1,012题（98.83%）、未见布局559题（54.59%）。原始起点完成270/1,024，已知困难题1/8；各组题目距离分布不同，只在同题条件下比较模型。详细结果见[卷积方案](rush_hour_pairs_spatial.json)。

## 车辆命名与普通中间目标

多目标小规模对照使用同一CNN、数据、初始化和更新预算，加入A尚未到出口的完整车辆排列。固定身份编码与几何编码的熟悉关系完成均为127/128；留出目标分别124/128和122/128，新布局分别47/128和45/128，原始起点分别2/128和0/128。小规模结果不与上文更大数据、不同预算的历史百分比直接比较。

几何编码保留A，其他车辆按固定方向、长度、车道和车道内身份一致分配通道。在四组各128题的联合改名检查中，候选距离、第一步物理动作和完整完成数均保持完全一致。原身份编码在熟悉关系组的完成数从127降到85，新布局从47降到25。该检查固定并运输物理候选顺序，以隔离输入编码；未据此宣称重新枚举候选时的并列打破也不受名称影响。

因此，几何编码解决了这项命名依赖，但没有改善跨布局求解；命名敏感不是当前跨布局缺口的充分解释。配置见[身份](../../configs/rush_hour/rush_hour_multigoal_identity.json)与[几何](../../configs/rush_hour/rush_hour_multigoal_geometry.json)，完整比较与命名检查见[结果](rush_hour_multigoal_encoding.json)。

原lane-order MLP对照已完成，三个主要测试组分别993/1024、990/1024和520/1024，与身份MLP完全相同。核对224个原始场景发现两种编码的起始输入均相同；车道内车辆不能互穿，因而分量内映射也不变。这份公共数据本来已按该顺序分配字母，原lane-order训练不是有效的不同表示对照，见[完成结果与编码核对](rush_hour_lane_order_completed.json)。当前未登记采用权重，见[selection](../../../../tasks/rush_hour/Qmap/selection.json)。

棋盘覆盖扩展使用完整公开数据库，训练目标为至少1,000个独立车辆配置组，按原题最短移动数分层选取，保留旧场景、目标和整布局留出。原144个训练场景对应141个不同配置组，不能按144个不同配置组计算。新增棋盘补A未到出口的完整中间目标；点关系和完整候选分别按场景均衡遍历。模型、距离、损失及更新预算沿用原CNN，布局和目标分布的变化单独记录，见[覆盖配置](../../configs/rush_hour/rush_hour_coverage1000.json)。预算跑完或状态源遍历完并不等于距离场和长程执行收敛。

已准备1,000个训练配置组、1,003个训练场景，四个原题难度层各250组；训练场景4,760,561个状态，全体场景合计5,263,995个状态。训练棋盘每图8–14辆车，训练配置组与35个验证、37个测试和8个诊断场景无交叉，见[结构统计](rush_hour_coverage1000_structure.json)。从完整恢复状态开展[大batch阶段](../../configs/rush_hour/rush_hour_coverage1000_large_batch.json)：点关系2,048→8,192，完整候选1,024→4,096，保留优化器、随机状态与曝光计数；更新轨迹改变，不能视为原固定batch的直接复现。原小batch在25,000步完整断点停止，权重和恢复状态保留，大batch在10,000步完整断点加载等价采样加速后继续。

[固定1,000更新的吞吐检查](../../configs/rush_hour/rush_hour_coverage1000_batch_speedcheck.json)与正式大batch后半阶段均约每秒6.4万点关系、3.2万完整候选决策。加速仅重查被拒绝的目标提案，保留提案和随机数序列；评测向量缓存另通过逐元素一致性检查。吞吐、利用率或显存增长本身不构成能力改善；完整新布局和原始起点执行仍须独立验收。

扩量后所选15,000步节点已完成准备点源覆盖，但仍只完成整布局留出411/1,024（40.14%），原始起点0/1,024；训练布局的关系测试1,020/1,024、未见完整目标1,024/1,024。原始起点MAE为17.34步，随机起终点的新布局MAE为3.92步，见[完成结果](rush_hour_coverage1000_development.json)。这些训练布局关系池加入了新增棋盘与中间目标，不能与历史144场景测试直接作同题百分比相减。布局数量达标没有解决长关系和跨布局执行，未采用该地图。

后续[关系采样控制](../../configs/rush_hour/rush_hour_coverage1000_control_fit.json)与[真实距离分层](../../configs/rush_hour/rush_hour_coverage1000_distance_fit.json)固定同一棋盘、完整目标、保护关系与初始末权重。两组采用相同更大batch和每批棋盘数，分层组保留广域源遍历，再补按布局及真实起终点距离分配的点关系；全部动作候选按实际距离分层抽取。移车可达分量的动作可逆，没有推箱子式的死锁边界，边界采样配额设为零；不为套用死锁采样器制造不可达样本。该比较用于检查长关系覆盖假设，不预设误差或完成率必然改善。

匹配比较完成后，控制与距离分层在整布局留出分别完成458/1,024（44.73%）和466/1,024（45.51%），MAE分别3.456和3.331步；原题起点两组仍为0/1,024，MAE分别14.755和13.170步。阶段末实际训练批次的MAE分别1.011和1.087步，最优动作率79.76%和84.44%；分层组21步以上训练关系MAE仍为2.077步。数据覆盖和训练拟合的缺口同时存在，不能把完成率停滞只归因于布局不足，也不能以两组预算结束宣称收敛。结果见[同题比较](rush_hour_coverage1000_development.json)。

同一距离分层条件从完整优化器、采样器与随机状态继续后，所选节点的新布局完成474/1,024，原题起点18/1,024，8道困难题0/8。训练批次MAE约0.949步，21步以上约1.550步，最优动作率86.56%；误差降低尚未解决连续长程与布局泛化，不采用，也不替代原历史较好地图。完整匹配起点和分项见[续训结果](rush_hour_distance_continuation.json)。
