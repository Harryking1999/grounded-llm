# 可逆任务的共享 Qmap 核心

本目录只共享汉诺塔与 2×2×2 魔方已经需要的数据、编码、训练和评测流程。任务规则与精确求解留在 [hanoi_qmap](../hanoi_qmap/README.md)、[cube2_qmap](../cube2_qmap/README.md)，不复制积木实验的专属数据结构或启动系统。

## 因果假设与模型

假设：离线精确距离加同一目标下的候选排序，能让目标无关状态编码器 `Q(s)` 的固定距离反映最短动作远近，进而改善一步选择和连续到达。状态输入是符号真值，合法后继由环境提供；这一实验不检验视觉解析、状态估计或 LLM。

直接复用积木的 `BoardEncoder`：只给原类增加默认值为 100 的可选输入维数；新任务仍为两层 ReLU MLP、128 维输出和 `cap * sigmoid`，末层初始化也完全一致。cap 取任务直径。目标不进入编码器。对可逆任务使用积木 `directed_sum` 的双向平均：`D(s,g) = (D_directed(s,g) + D_directed(g,s))/2 = sum(abs(Q(s)-Q(g)))/(2*sqrt(dimension))`。它是**学习到的动作距离近似**，不是物理位置距离，也不能保证任意图在固定维度中无误差表示。

只有两项损失：精确距离 Huber；完整软排序交叉熵。排序沿用积木的 `softmax(-真实距离/temperature)` 作为目标分布，与 `log_softmax(-Q距离/temperature)` 比较；每组含同一目标下的全部合法后继，包括所有非最优候选的远近和平局。不再使用只奖励最短候选的损失。任务适配的是排序组来源，积木还使用同起点／同终点的采样关系组。这里只有 Q 编码器参数，没有转移头、V、策略头或额外对称损失。

## 对称增强与划分

汉诺塔同时重命名全部状态中的柱名，完整枚举六种置换；动作的源柱和目标柱同步重命名。按无序状态对在六种置换下的**关系轨道**划分训练／验证／测试。每个训练轨道先取一个代表关系，再增强、去重；验证和测试枚举各自轨道的全部关系。整组候选一起变换，再按环境动作顺序重建，因此不会把旧候选列误当作新动作列。没有将单个状态规范成同一个 Q；所有盘在 A 和所有盘在 B 仍是相距七步的不同状态。

魔方使用 `s -> k*s` 的共同左乘：`(k*s)^-1*(k*g)=s^-1*g`，所以任意两端的精确距离保持不变；同时 `k*(s*a)=(k*s)*a`，九种动作及后继关系保持不变。k 本身属于 DBL 固定群，因此变换后仍处于原规范框架。这是角块身份／参考扭转的重标记，不是执行同一串右乘转动，也不需要引入六面动作或整块旋转。状态对与候选组中所有状态必须采用**同一个 k**。

魔方保留完整状态空间的原稳定哈希划分。增强仅接受所有训练端点、父状态、目标及全部候选仍属于训练划分的变换；达到配置尝试次数仍不满足时保留原训练行，摘要记录实际改变数和回退数。所有增强距离由精确 oracle 再核对。对称性只用于构造监督，不是推理时的搜索工具，也不保证普通 MLP 学到严格等变性。

## 模块接口

| 模块 | 职责 |
|---|---|
| `src/tasks.py` | 延迟加载任务；不依赖 torch |
| 每个任务的 `src/environment.py` | 状态编号／验证、文字说明、动作执行、合法后继、特征、Hamming 基线、精确距离和最短解 |
| `src/data.py`、`src/symmetry.py` | 固定划分、精确标注、整组对称增强与去重；不导入 torch |
| `src/sampling.py` | 广度无放回遍历、真实距离均衡和同目标上下文采样；记录实际覆盖轮次 |
| `src/model.py` | 复用积木编码器、对称距离、完整软排序；`MapReader` 冻结读取接口 |
| `src/run.py` | 构建数据、训练、验证选模型、冻结评测与向量导出 |
| `src/evaluate.py` | 距离、完整软排序、候选与连续到达；oracle 仅为标签或独立基线 |
| `src/solve.py` | 输出可重放动作与状态序列，支持精确解或纯 Q 贪心 |

向量接口读取 checkpoint 中的完整配置并核对任务／动作约定：

```python
from experiments.hanoi_qmap.src.environment import Hanoi
from experiments.puzzle_qmap.src.model import MapReader
reader = MapReader(Hanoi(), "runs/hanoi_qmap/RUN_ID/best.pt")
q = reader.encode([0, 26])       # [2, state_dim]，目标不进入编码器
action, successor = reader.choose(0, 26)
```

## 比较与证据边界

同题比较随机初始化 Q、训练后 Q、原始状态 Hamming、精确最短距离。距离报告 Huber、MAE、Spearman 与按真实步数分桶的预测均值。一步选择报告固定动作顺序打破平局的最短动作率、均匀打破平局的期望正确率与严格候选排序准确率。转移关系仅作为距离为一步的监督和环境后继结构，不再报告学习转移预测能力。

连续到达使用同一批任务、相同且不依赖 oracle 的固定最大步数；重复状态判为确定性贪心循环并停机。报告成功率、循环率、超预算数、成功题额外步数和按初始真距离分层的成功率。合法候选由环境枚举，非法动作率结构性为零，不能解释为模型学会了合法性。oracle 的 100% 到达是环境／标签检查，不是学习结果。全部状态在各自环境中互相可达，因此不伪造“不可达状态对”负标签；非法状态和非法动作单独测试。

汉诺塔按关系的柱置换轨道留出，双向及对称等价关系不跨划分；排序训练也只读取训练轨道内关系。测试父状态—目标的候选—目标关系仍可能见过，因此是关系补全，不是未见状态泛化。魔方训练距离和排序候选全部排除留出状态，包含增强后的状态；测试父状态和目标均未参与训练损失。魔方距离均衡采样不代表均匀随机打乱分布，两个任务的指标不可混算。

## 产物与执行

从仓库根目录运行各任务 README 的命令。运行目录必须不存在；所有生成物写入 Git 外的 `runs/`。每次保存实际 `config.json`、`data.npz`（包含增强前的训练关系与任务）、增强／划分摘要、验证曲线、最佳 checkpoint、初始与最终评测 `summary.json`、示例 `q_vectors.npz`；魔方还保存完整精确距离表。模型只按验证 Huber 加完整软排序损失选择，测试不参与选择。单 seed 首轮只证明该条件的表现；未运行无增强消融时，不能单独归因于对称增强。读取接口只接受纯 Q checkpoint。

依赖：环境与数据只需 NumPy；学习和冻结 Q 推理另需 PyTorch。不修改仓库通用依赖或公共环境。

新一轮覆盖实验的任务专属构建器位于 `cube2_qmap/src/data.py`，不把魔方群结构塞进通用训练器。模型和两项损失保持不变。只有在实际完成合同要求的广度遍历后，checkpoint 才能参与验证选择。汉诺塔四至六盘和魔方新数据使用距离分层的评测任务；旧参考测试保留原顺序单独对照。详细划分以各实验合同和数据设计为准。
