# 状态接口试点：报告适配能否迁移到规划

本文是具体执行设计，尚未实现或运行。参数提案见 [configs/pilot_design.json](configs/pilot_design.json)；该文件不是现有 runner 可以执行的配置。项目当前结果和工作顺序仍只在 [项目状态页](../../docs/PROJECT_STATUS_AND_TODO.md) 维护。

建议先做 **Qwen3-8B thinking + 输入层状态 tokens + 积木闭环**。训练仅涉及状态／关系报告，规划时冻结所有参数。先验证一个问题：在获得同样准确状态、同样真实反馈和同样生成预算时，这种接口是否比文字状态更有助于冻结 LLM 规划？选择 8B 是沿用已测模型家族、兼顾反传成本和能力的起点；现有结果没有证明它是最优规模。4B／32B 留作之后的规模比较，不同时展开训练网格。

飞书回复已确认，“线性状态”指首版维护顺序推进的轨迹，不是网络不能有非线性激活。作者也确认两个任务分别处理；这回答了近期任务分工，没有解决同一接口从小棋盘扩到大棋盘的容量问题。

历史 Qwen 积木全错来自一次性完整计划、固定预算协议。改成逐动作反馈后，**文字闭环基线必须重跑**。此前 768 次中有 511 次生成触顶，不能从总体失败率推出“状态模块一定有效”。历史结果只用于解释为什么值得做这项诊断。

## 2. 架构：先接输入层

```text
准确当前网格 s_t、目标网格 g
          ↓ 固定二值表示；无物体分割、无解题信息
     共享逐行 MLP + 行号／角色编码（可训练）
          ↓ 当前状态和目标的连续 token embeddings
规则文字 + 对话历史 + 当前状态 tokens + 目标 tokens
          ↓ 冻结的 Qwen3-8B，正常 thinking
可见 CoT → 最终提交一个动作
          ↓ 环境验证并执行已提交动作
更新真实网格 → 下一轮
```

采用 PaLM-E 的接口思路，并不复现其整套任务训练。每行十个格子映射为一个向量；当前和目标各占十个 token。共享 MLP 为 `10 → 256 → 4096`，中间 GELU；加行号和 current/goal 角色向量。含偏置约 **1.10M** 可训练参数。原词嵌入和输出头不扩词、不训练；输入占位位置替换为连续向量。

逐行结构保留明确空间次序，也避免把整张棋盘挤进一个 token。它只编码格子，不使用生成棋盘时的隐藏积木分解。十个 token 是可解释的首轮工程选择，**没有论文证明它在这里最优**。原有位置编码仍用于整个序列；行号编码用于明确板内位置。

若报告训练集都读不准，先检查梯度、监督位置和坐标；若仅未见棋盘读不准，再检查表示容量和数据覆盖。只有出现这种具体失败，才在开发集比较更细的分块输入。不能因规划失败就直接宣布需要更多 token；更不能由本轮推出 100×100 棋盘也用十个 token。

为什么暂不选另外两种：

- **Flamingo 类 cross-attention**：是有依据的备选，适合检验独立状态 memory 的读取。它新增注意力／门控模块，并引入更新 memory 后的历史计算语义。先判断输入层是否确有读取或旧状态干扰问题，再承担这些变量。参数量取决于模块宽度、FFN 和插入频率，不是必然翻倍。
- **动态 prefix／LoRA**：状态放入输入层本身已经是一种条件化连续提示。动态改深层前缀或低秩权重还需明确旧 KV 是否重算，当前没有证据表明这能解决本项目已经定位的瓶颈。首轮不同时开展三种训练。

## 3. 任务与数据

复用 [Sol 积木配置](../sol_dag_blocks/configs/sol_medium.json) 的棋盘、十种固定方向形状、合法动作定义和无重力／无库存规则。复用 `BlocksTask.apply`；它验证完整形状是否覆盖当前占据格子。旧 `prompt` 和最终 `judge` 要改造成逐动作、可非空目标的协议，不能直接照搬。

成功定义是到达目标网格，不要求最少动作，也不要求恢复生成时的原始分块。形状的零格是空洞，不约束对应板格。动作采用零起始的 `shape_id, row, col`；只能按规定方向放置。

**数据划分提案：**

| 用途 | 数量 | 生成方法与用途 |
| --- | --- | --- |
| 对齐训练 | 2,048 个状态—目标对 | 初始板由 4／6／8 块构造；当前板可取原板或随机保留构造块的子集；一半目标为空，另一半保留当前构造块的非空子集 |
| 开发集 | 256 对 | 与训练不同初始板家族；用于损失、读出和协议校准，不能用正式规划测试选模型 |
| 独立能力探针 | 128 个查询 | 当前报告 16、目标报告 16、关系报告 16、单步转移 32、合法性 24、目标判断 24 |
| 规划测试 | 128 个实例 | 4／6／8／12 块各 32；每档一半空目标，一半非空目标；初始板就是当前板 |

训练对一半保留完整初始板作为当前状态，另一半先均匀选择需保留的块数，再随机选择构造块子集，兼顾起点和执行中间状态。每对产生当前、目标、差分三类报告，合计 6,144 条监督样本。非空规划目标随机保留至少一块且至少需移除一块；见证分解仅用于保证有解，不进入 prompt、接口或损失。12 块作为规模外推，不称为跨任务泛化。

生成顺序先固定初始板家族的划分，再产生派生状态；同一初始板、其平移副本和派生样本不得跨训练／开发／测试家族。额外去除跨划分完全相同的当前—目标对。空目标、简单子形状仍可重复，不能把测试集每个目标都称作未见目标。探针与正式规划样本不按模型失败筛选。

生成器可枚举合法放置并保留隐藏解，裁判可事后分析死局；这些能力都不提供给 agent。非空目标被错误移除时，这是可能**物理合法但目标已不可恢复**的动作，应与非法动作分开。

训练关系为 `s_t - g`。可达训练对中是零／一；独立关系探针另外包含目标格已经缺失的样本，真值可为负一，单列为分布外测试，不能截成零。

## 4. 三个条件与它们能排除的解释

| 条件 | 当前与目标如何输入 | 训练 | 回答的问题 |
| --- | --- | --- | --- |
| T0：准确文字状态 | 相同规则下的二值网格文字 | 无 | 获得同样真实反馈的基础模型能做到多少？ |
| T1：文字报告适配 | 与 T0 相同 | 普通固定 LoRA，仅同一批报告监督 | 改善能否仅由做过报告适配解释？ |
| S：状态接口 | 连续状态 tokens | 逐行 MLP，仅同一批报告监督 | 状态接口是否带来额外实用收益？ |

三组使用同一原始 Qwen checkpoint、同一任务信息、动作反馈、实例、生成参数和预算。规则只给文字；S 不再额外给一份准确网格文字，也不直接输入差分。差分是要让模型根据两个状态生成的训练目标。

T1 的 LoRA 是训练后固定的对照，**不是本轮选择了动态 LoRA 状态架构**。在各层 q/v 投影使用 rank 2，约 0.96M 参数，与 S 接近。两者数据和训练步数相同；可训练位置、输入长度和实际计算仍不同，因此不是完美的单变量因果控制。需要同时报告参数、训练时间、输入 token 和生成 token。

T0、T1、S 都能提出最终动作，但没有专家规划示例、合法动作表、候选打分器或假想环境查询。格式例子只说明字段，不提供一个完整任务解。

## 5. 报告对齐怎样训练，thinking 怎样保留

**对齐阶段使用“状态输入 → 文本续写”的监督，不构造假的专家思考。** 给出固定的报告前缀，例如当前状态和目标之后接 `Report the CURRENT board in row order.\nAnswer:\n`，用冻结 LLM 的原输出头预测准确的十行文本。其余两类任务分别指定目标和有符号差分。

仅答案文本计算自回归交叉熵；状态向量、问题和固定前缀不计算损失。梯度经过冻结 LLM 回到接口；不能对整段 LLM forward 使用 `no_grad()`。T1 在相同报告前缀、答案和损失上训练新增 LoRA。报告按类型等权，各样本按目标 token 数归一化。

这里采用 plain completion 的接口预训练，**不是把规划的 `enable_thinking` 设为 false**。对齐样本没有 chat thinking 标签，也不监督空的 `<think></think>`。这意味着从报告续写迁移到 thinking 对话本身也是待验证环节：训练 loss 降低后，必须在真实 thinking 模板下测报告生成，不能用 teacher forcing 准确率代替它。若迁移失败，先修正接口训练协议，不对规划能力下结论。

这项处理参考多模态投影器的对齐阶段，而非已经存在的 Qwen 积木 CoT 配方。若后续加入模型自生成解释或专家 CoT，属于另一项训练条件，应单独比较。

首轮优化设置：AdamW，零 weight decay，cosine schedule，3% warmup，梯度裁剪 1.0，有效 batch 32，最多三轮。只比较两个学习率 `1e-3` 和 `1e-4`，T1 与 S 各获得相同选择次数；每轮按开发集答案 NLL 保存候选，选择最小 NLL，平局取更早轮次。正式测试成功率不参与选择。

这是单个训练种子的工程试点，不把一次训练的差异当稳健结论。两类接口各两个学习率，共四次短训练；每次最多 576 次参数更新。若要形成方法结论，需冻结配方后对全部条件补充多个训练／采样种子，无论第一轮结果正负。

默认 BF16，不引入量化变量；实现采用可访问 `inputs_embeds` 的 Transformers/PyTorch。先做一小批真实反传的显存／速度测量，再决定 microbatch 与梯度累积。冻结 8B 仍需要反向传播所需的激活，不能按“只有百万参数可训练”估算显存。软件版本、模型 revision 在实际实现时锁定，不能把未验证的版本号写成已验证环境。

## 6. 逐动作执行与预算

每次 assistant 正常生成 `<think>…</think>`，其后只提交一个最终 JSON 动作，例如 `{"action":{"shape_id":0,"row":2,"col":3}}`，或 `{"done":true}`。CoT 里的动作提议、否定和回溯都不执行。收到完整回合后，解析唯一最终对象；不从思考里抢先提取动作，不修复非法动作。

环境执行后提供准确的新状态。达到目标即记任务成功；提前宣称 done 为失败。非法动作、破坏目标、未达目标的结束、格式错误和预算耗尽分别记录。目标判断能力另用独立探针评测，避免由环境自动成功判定掩盖该能力缺陷。

**thinking 全开，完整原始 CoT 保存；下一轮默认只保留历史最终动作和状态消息，不回填历史 CoT。** 这是 Qwen 官方多轮模板建议，与关闭本轮 thinking 不同。每轮重新渲染对话并重新 prefill，轮内使用 KV cache；不复用包含上一轮被移除 CoT 的缓存。历史状态仍可见，当前和目标在最新 user 消息中明确标记。

由于多轮协议与连续 assistant 内注入不同，本轮不声称验证了后者的缓存或推理语义。若用户希望比较历史 CoT 回填，可作为独立协议，三组同时改动。

采样沿用已有 Qwen thinking 基线：temperature 0.6、top_p 0.95、top_k 20、min_p 0、repetition_penalty 1。**整局累计生成上限 16,384 tokens，包含所有回合的 CoT 和最终输出；不是每步重新发放 16k。** 每轮可用上限为剩余整局预算和上下文空间中的较小者，不另设任意短 CoT 限制。

上下文首轮限制在原生 32,768 tokens 内，不开 YaRN；不自动截掉旧状态或目标。超出时单列 context-cap。能力探针每个独立查询同样最多 16k。16k 来自历史对照与首轮成本约束，并非论文证明充分；Qwen 官方通常建议更长输出。若开发集显示明显触顶，先给出所有条件共同增加预算的成本，再固定修订配置后测试，不能只给 S 追加预算或重采失败样本。

首轮每题一条轨迹，无 pass@8、无外部评分选解。未来多路径实验须让所有条件有同样的采样次数及评分信息，并区分“候选中存在正确解”和“最后选中正确解”。输入 token、重复 prefill 和实际时间另报；相同生成上限不等于严格 FLOPs 匹配。

## 7. 读什么结果，下一步做什么

主指标是固定预算下的到达目标率，主要比较 S−T0；S−T1 是训练解释的关键补充。三组各在同一 128 个实例上运行，主测试共 384 个 episode；一个 episode 可包含多个模型调用。按实例配对，报告差值、配对 bootstrap 区间和各规模／目标分层结果。128 题只能筛查较大效应，不能承诺检测几个百分点的差异；小分组主要作描述。

能力探针分别评估完整网格精确匹配及逐格准确率、单步转移、合法性和目标判断。稀疏网格的逐格准确率可能被全零答案抬高，必须同时给完整匹配和占据格错误。转移探针给定一个动作，不用环境向模型预先返回后果；合法性探针平衡合法／非法动作并包含空洞语义。goal 判断包括相等、仍需移除、目标格已缺失。

不要为了记录状态而要求所有主 rollout 每步再输出完整网格，这会改变规划负担。完整 CoT、最终动作与精确环境状态全部留档；额外强制状态报告放在独立探针。CoT 可供发现矛盾和设计后续干预，但流畅的自述不是内部因果机制的证明。

另做两项预先固定的小诊断：

1. **状态／目标干预**：使用 16 对合法、可解的小局面，八对改变当前状态，八对在同一当前状态下改变目标，正确动作应相应改变。三组各测两种输入，共 96 个单动作查询。动作改变本身不够，要检验改变后是否适合新状态和新目标。
2. **历史干扰**：预先从规划集均衡取 32 题，让 T0 与 S 再运行“仅最新状态／目标、无历史状态及旧动作”的条件，共 64 个 episode。完整日志仍保留。它检验冗余历史是否妨碍当前状态使用，不单独宣称已定位某层 attention 的机制。

| 观察 | 可作出的判断与下一步 |
| --- | --- |
| 报告在 thinking 模板下读不准 | 先处理对齐／格式／容量；当前方案尚未通过接口验证 |
| 报告很好，转移或合法性差 | 读出不等于理解动作规则；定位具体规则错误，再讨论是否加转移监督 |
| 状态、转移都好，但长程任务差 | “只训练报告即可迁移规划”的假设在此设置下受挫；不能仅靠换 memory 宣称解决 |
| S 优于 T0，但与 T1 相当 | 报告适配有效；专用状态接口的额外价值未确立 |
| S 优于 T0/T1，且干预响应正确 | 支持该任务／预算下的状态接口收益；再做种子重复和机制扩展 |
| 去历史明显改善，其他条件不变 | 优先研究历史呈现，再考虑独立 memory；不能默认 cross-attention 必然更好 |
| 准确文字闭环已经很好 | 研究问题应转向效率、规模或有证据的困难子类；保留这个简单解释 |

不设置没有依据的“读出超过 95% 就算学懂”硬门槛。报告错误率及其对整段动作的影响直接呈现；没有正增益也完整保存。

## 8. 寻路如何衔接

首个 LLM 接口试点只做积木。抽象图先做独立地图诊断，避免把“地图没有方向性”和“LLM 不会读地图”混成一次失败。

起点采用 [GCML 官方抽象图代码](https://github.com/LH-cbicr/GCML/blob/ff76859b71a2bc2056b50f5e052475351c007f76/gcml_abstract_graph.ipynb) 的小图与完整 Q/V/W 更新规则，固定源码 revision。只训 Q/V 后直接按欧氏距离贪心是对原方法的简化，必须单列。记录探索覆盖：若每条有向边都是独立动作，未见边就涉及未训练动作参数，不能宣称那是普通的未见起终点测试。

地图训练数据不含最终评测的规划答案；同图起终点对可留作评测，但训练可以覆盖其节点和边。先比较随机合法邻居、嵌入距离贪心、原 W 选择器；BFS 只提供裁判距离和上界。使用相同可访问邻接信息和动作步数预算，记录合法到达、绕路、循环与最短距离相关的动作排序。低转移损失不能替代这些指标。

小图机制核对后再迁移到已有 path256 双向图，主要目标改为合法到达，最短性作效率指标。只有地图方向信息确有用，才讨论给 LLM 输入当前／目标／候选下一状态；文本对照应获同样候选信息。若贪心已经足够而 LLM 没有额外收益，应如实收缩 LLM 作用的主张。该阶段还没有获验证的容量和预算，不在本轮伪装成可直接运行的寻路合同。

## 9. 文献能支撑什么，不能支撑什么

| 设置 | 可参考的原始工作 | 本项目中的边界 |
| --- | --- | --- |
| 状态经 MLP 转连续输入向量，允许冻结 LLM | [PaLM-E](https://arxiv.org/html/2303.03378v1)，§3–5 | 其机器人规划训练含专家任务数据；不能作为本轮“仅报告监督就能规划”的证明 |
| 冻结语言模型，通过接口对齐后测新任务 | [Frozen](https://arxiv.org/abs/2106.13884) | 提供迁移先例；图像描述到少样本视觉任务不等于积木报告到零策略监督规划 |
| 两层 GELU 投影器、plain 对齐、1e-3 起点 | [LLaVA 官方预训练脚本](https://github.com/haotian-liu/LLaVA/blob/main/scripts/v1_5/pretrain.sh) | 可借优化起点；本轮数据、输入与模型不同，不能照搬其成功结论或总训练量 |
| thinking、采样和历史 CoT 处理 | [Qwen3-8B 官方模型卡](https://huggingface.co/Qwen/Qwen3-8B)；本地历史 thinking 配置 | 采样沿用；16k 是项目预算选择，低于模型卡常用输出建议 |
| 文字报告适配控制 | [LoRA](https://arxiv.org/abs/2106.09685) | 固定低秩适配有依据；rank 2 是近似匹配参数量的工程选择 |
| 条件化独立 memory | [Flamingo](https://arxiv.org/html/2204.14198v2) | 稀疏插层是有实验依据的后备方向；不是先验优于输入 tokens |
| “读懂状态后泛化到新任务”的动机 | [FLAN](https://arxiv.org/abs/2109.01652) | FLAN 训练了语言模型的多任务指令能力；不证明冻结模型只做状态报告对齐即可完成所有子任务 |

行粒度、隐藏宽度、样本量、三轮上限和两个学习率候选都属于**本项目首轮选择**。处理无直接配方的方式是：给出机制理由和有限预算，只在开发集校准；冻结设计后看独立测试，失败时改变有证据的问题环节。没有查到直接验证本任务完整配方的工作，不等于已经证明文献中不存在。

## 10. 实施交付与成本边界

执行顺序：先实现新目标／动作协议，运行 T0 的开发集探针和预先固定的 16 个非平凡闭环实例，确认新反馈协议下还存在什么问题。再实现新增输入／训练模块，做极小数据的反传和真实 thinking 读出检查，最后才进行配置中的报告训练和独立评测。如果准确文字闭环已足够可靠，先解释这一结果，再决定状态接口是否仍有明确的效率或泛化问题可检验。最便宜的实现检查应覆盖：坐标／形状空洞语义、非空目标被破坏、CoT 提议不执行、LLM 权重冻结但接口有梯度、回合预算累计、重建历史后不复用旧缓存。

这些是未来实现时针对明确风险的测试；本次没有编写占位 runner 或运行训练。首轮主测试、能力探针、两项诊断合计最多 928 份独立查询或 episode 槽位，其中 448 个是可能多回合的 episode；实际计算量须由校准吞吐和每局动作数估计，不给未经测量的 GPU 小时承诺。

运行产物放忽略目录 `runs/`；保留模型与配置 revision、分割种子、准确输入、完整原始输出、token 使用、动作环境轨迹和失败类型。公开仓库只保存代码、紧凑配置和与结论有关的摘要。下一次实施应先把本设计配置接入具体 runner 并完成最小检查，再提出有硬件与时间依据的运行安排。
