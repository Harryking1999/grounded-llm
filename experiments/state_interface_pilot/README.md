# 状态接口试点：报告适配能否迁移到规划

本文是具体执行设计，尚未实现或运行。参数提案见 [configs/pilot_design.json](configs/pilot_design.json)；该文件不是现有 runner 可以执行的配置。项目当前结果和工作顺序仍只在 [项目状态页](../../docs/PROJECT_STATUS_AND_TODO.md) 维护。

按用户 2026-09-14 决定，首轮回到合作者原方案：**Qwen3-8B 非 thinking 模式 + 输入层状态 tokens + 单条规划轨迹**。训练仅涉及状态／关系报告，规划时冻结所有参数。先验证一个问题：在获得同样准确状态、同样固定转移更新和同样生成预算时，这种接口是否比文字状态更有助于冻结 LLM 规划？选择 8B 是沿用已测模型家族、兼顾反传成本和能力的起点；现有结果没有证明它是最优规模。4B／32B 留作之后的规模比较，不同时展开训练网格。

状态接口按用户决定先比较**每个状态 1、2、4 个向量**，替换原先每行一个、共十个的起点。当前与目标分别编码，初始状态输入合计为 2、4、8 个向量；之后每步只追加更新后的当前状态。

## 1. 与研究简述、飞书和 TODO 的关系

| 来源或主张 | 本试点如何对应 | 结果能解释到哪里 |
| --- | --- | --- |
| RESEARCH_BRIEF：冻结 LLM，仅训练状态网络与接口 | 冻结词嵌入、LLM、输出头；训练小型状态接口 | 满足训练约束；积木状态与动力学本身没有被学习 |

| TODO：积木 Q=I、V 固定，不训练专家动作策略 | 复用准确状态和固定动作规则；没有动作、最优路径或专家 CoT 训练标签 | 检验状态使用；不等于自主形成认知地图 |
| RESEARCH_BRIEF：行动前内部推演候选后果 | 在内部顺序推进一条规划状态轨迹；单步转移能力单独测 | 第一版不支持状态分支或回滚，也没有学习积木转移，不能宣称已实现可泛化的神经想象模型 |

| 飞书／TODO：短 CoT 或 instruct 候选 | 关闭专用 thinking，生成简短显式理由和一个确定动作 | 降低首轮交互复杂度；不把它解释为长 thinking 在原理上不可用 |
| 飞书／TODO：同一 assistant 序列中持续插入状态 | 在动作边界暂停、追加更新状态，再续写同一序列 | 保留原方案的顺序推进；不再用逐动作多轮对话替代它 |

飞书回复已确认，“线性状态”指首版维护顺序推进的轨迹，不是网络不能有非线性激活。作者也确认两个任务分别处理；这回答了近期任务分工，没有解决同一接口从小棋盘扩到大棋盘的容量问题。

历史 Qwen 积木全错来自 thinking 模式下的一次性完整计划协议。改成非 thinking、逐动作插入更新状态后，**文字状态对照必须重跑**。此前 768 次中有 511 次生成触顶，不能从总体失败率推出“状态模块一定有效”。历史结果只用于解释为什么值得做这项诊断。

这里的“采纳动作”指把一个动作确定为当前规划轨迹的下一步，再按固定 V 更新脑补状态；不强行等同于真实环境已执行并返回新观测。积木中 Q=I、V 精确，所以这条内部轨迹可与规则裁判一致，文字对照也必须获得同样更新。长期真实反馈与观测校准目标保留，但不是首轮新增的学习机制。

## 2. 架构：先接输入层

```text
准确当前网格 s_t、目标网格 g
          ↓ 固定二值表示；无物体分割、无解题信息
     共享分块 MLP + 块位置／角色编码（可训练）
          ↓ 当前状态和目标的连续 token embeddings
规则文字 + 目标 tokens + 初始状态 tokens
          ↓ 冻结的 Qwen3-8B，非 thinking
简短显式理由 → 确定一个动作
          ↓ 按固定 V 推进规划状态
追加当前状态 tokens → 续写同一 assistant 序列
```

采用 PaLM-E 的接口思路，并不复现其整套任务训练。三种编码均覆盖完整棋盘，不使用生成时的隐藏积木分解。每块先按行展平，再经过两层 MLP，中间 GELU，输出一个 4096 维向量；加块位置和 current/goal 角色向量。原词嵌入和输出头不扩词、不训练；输入占位位置替换为连续向量。

| 条件 | 每个状态的分块 | MLP | 可训练参数（含偏置、块位置和角色） |
| --- | --- | --- | --- |
| S1 | 整盘 | `100 → 256 → 4096` | 1,090,816 |
| S2 | 上五行、下五行 | `50 → 256 → 4096` | 1,082,112 |
| S4 | 左上、右上、左下、右下四个 5×5 象限 | `25 → 256 → 4096` | 1,083,904 |

同一条件内，所有块及当前／目标共用 MLP；S1、S2、S4 各自独立训练，三种配置不会复用已训 checkpoint。分块和块内坐标均使用按行顺序。原有位置编码仍用于整个序列，块位置编码用于区分板内区域。三种参数量接近，可以避免把输出 token 增加时投影器参数也成倍增加；状态序列长度与实际计算量仍不同，必须报告。

一个 4096 维向量并不存在“装不下 100 个二值格子”的必然容量限制，是否容易被冻结 LLM 读取要靠实验判断。这里同时改变了向量数量与空间分块粒度，**不把它称作严格隔离 token 数量的单变量消融**。空间分块是工程选择，不能把它当成模型自行学出的物体结构。首轮不加入十向量或其他划分方向的额外网格。

按 S1、S2、S4 顺序检查训练和开发集读出，三种配置使用同一批状态对、相同训练步数和学习率选择次数；不得把验证失败的候选从记录中隐藏。若训练集都读不准，先检查梯度、监督位置和坐标；若仅未见棋盘读不准，再检查表示容量和数据覆盖。不能因规划失败就直接宣布需要更多 token，也不能由本轮推出更大棋盘的最优向量数。

为什么暂不选另外两种：

- **Flamingo 类 cross-attention**：是有依据的备选，适合检验独立状态 memory 的读取。它新增注意力／门控模块，并引入更新 memory 后的历史计算语义。先判断输入层是否确有读取或旧状态干扰问题，再承担这些变量。参数量取决于模块宽度、FFN 和插入频率，不是必然翻倍。
- **动态 prefix／LoRA**：状态放入输入层本身已经是一种条件化连续提示。动态改深层前缀或低秩权重还需明确旧 KV 是否重算，当前没有证据表明这能解决本项目已经定位的瓶颈。首轮不同时开展三种训练。

**跨 LM 复用的边界：**连续状态 tokens 是投影器对当前状态的计算结果，训练的是投影器参数，不是为每个新状态重新训练一组 tokens。更换 LM 后，二值状态、固定 V、状态／报告数据可以继续使用；投影器通常需要重新对齐或迁移后验证。即使两个 LM 输入维度相同，其向量坐标与后续读取方式也未必相同。本轮整个 MLP 都通过 Qwen 的报告损失学习，不能仅把中间 256 维命名为“共享空间”就认定它与 LM 无关。

长期可以把状态表示与各 LM 的读取接口分开：共享状态模型输出 `h`，分别由 `P_Qwen(h)`、`P_Llama(h)` 转成对应模型的输入。共享部分的保留程度需要用冻结状态模型、仅适配新接口的迁移实验验证。当前积木已有独立于 LM 的二值状态，首轮无需为此额外增加一个学习模块。若要求不训练接口就能接入不同 LM，准确文字网格是现成基线，但读取效果与 token 成本仍需评测。

连续提示迁移有先例：[Su 等，NAACL 2022](https://aclanthology.org/2022.naacl-main.290/) 用跨模型投影器迁移提示；[PTfer，ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/file/05f0734db34deb367fc66f1482528044-Paper-Conference.pdf) 以共同词汇为锚，匹配相对几何关系，在目标模型上搜索提示向量，无需目标任务标签。这些结果不能直接证明本轮动态状态向量的迁移；PTfer 的零样本也不等于不做向量优化。跨 LM 比较留作后续，不加入当前训练矩阵。

## 3. 任务与数据

复用 [Sol 积木配置](../sol_dag_blocks/configs/sol_medium.json) 的棋盘、十种固定方向形状、合法动作定义和无重力／无库存规则。复用 `BlocksTask.apply`；它验证完整形状是否覆盖当前占据格子。旧 `prompt` 和最终 `judge` 要改造成逐动作、可非空目标的协议，不能直接照搬。

成功定义是到达目标网格，不要求最少动作，也不要求恢复生成时的原始分块。形状的零格是空洞，不约束对应板格。动作采用零起始的 `shape_id, row, col`；只能按规定方向放置。

**数据划分提案：**

| 用途 | 数量 | 生成方法与用途 |
| --- | --- | --- |
| 对齐训练 | 2,048 个状态—目标对 | 初始板由 4／6／8 块构造；当前板可取原板或随机保留构造块的子集；一半目标为空，另一半保留当前构造块的非空子集 |
| 开发集 | 256 对 | 与训练不同初始板家族；用于损失、读出和协议校准，不能用正式规划测试选模型 |
| 独立能力探针 | 128 个查询 | 当前报告 16、目标报告 16、关系报告 16、单步转移 32、合法性 24、目标判断 24 |
| 规划测试 | 128 个实例 | 4／6／8／12 块各 32；每档一半空目标，一半非空目标；初始板就是当前板 |

训练对一半保留完整初始板作为当前状态，另一半先均匀选择需保留的块数，再随机选择构造块子集，兼顾起点和执行中间状态。每对产生当前、目标、差分三类报告，合计 6,144 条监督样本。非空规划目标随机保留至少一块且至少需移除一块；见证分解仅用于保证有解，不进入 prompt、接口或损失。12 块作为规模外推，不称为跨任务泛化。

生成顺序先固定初始板家族的划分，再产生派生状态；同一初始板、其平移副本和派生样本不得跨训练／开发／测试家族。额外去除跨划分完全相同的当前—目标对。空目标、简单子形状仍可重复，不能把测试集每个目标都称作未见目标。探针与正式规划样本不按模型失败筛选。

生成器可枚举合法放置并保留隐藏解，裁判可事后分析死局；这些能力都不提供给 agent。非空目标被错误移除时，这是可能**物理合法但目标已不可恢复**的动作，应与非法动作分开。

训练关系为 `s_t - g`。可达训练对中是零／一；独立关系探针另外包含目标格已经缺失的样本，真值可为负一，单列为分布外测试，不能截成零。

## 4. 两个文字对照与三个状态接口条件

| 条件 | 当前与目标如何输入 | 训练 | 回答的问题 |
| --- | --- | --- | --- |
| T0：准确文字状态 | 相同规则下的二值网格文字 | 无 | 获得同样状态更新的基础模型能做到多少？ |
| T1：文字报告适配 | 与 T0 相同 | 普通固定 LoRA，仅同一批报告监督 | 改善能否仅由做过报告适配解释？ |
| S1／S2／S4：状态接口 | 每状态 1／2／4 个连续 tokens | 分块 MLP，仅同一批报告监督 | 状态接口是否带来收益，增加向量和分块是否有帮助？ |

五个条件使用同一原始 Qwen checkpoint、同一任务信息、固定转移更新、实例、生成参数和预算，均关闭 thinking。规则只给文字；三个 S 条件不再额外给一份准确网格文字，也不直接输入差分。差分是要让模型根据两个状态生成的训练目标。

T1 的 LoRA 是训练后固定的对照，**不是本轮选择了动态 LoRA 状态架构**。在各层 q/v 投影使用 rank 2，约 0.96M 参数，与三个 S 条件接近。训练数据和步数相同；可训练位置、输入长度和实际计算仍不同，因此不是完美的单变量因果控制。需要同时报告参数、训练时间、输入 token 和生成 token。T0、T1 各自运行一次条件矩阵，不为每个 S 重复训练或重复评测同一文字基线。

所有条件都能确定下一动作，但没有专家规划示例、合法动作表、候选打分器或分支转移查询。固定 V 只推进已经选定的一步，不比较多条候选后果。格式例子只说明字段，不提供一个完整任务解。

## 5. 报告对齐怎样训练

**对齐阶段使用“状态输入 → 报告答案”的监督，不构造专家思考。** 使用非 thinking 的 chat 模板，问题例如 `Report the CURRENT board in row order.`，用冻结 LLM 的原输出头预测准确的十行文本。其余两类任务分别指定目标和有符号差分。

仅答案文本计算自回归交叉熵；状态向量、问题和固定前缀不计算损失。梯度经过冻结 LLM 回到接口；不能对整段 LLM forward 使用 `no_grad()`。T1 在相同报告前缀、答案和损失上训练新增 LoRA。报告按类型等权，各样本按目标 token 数归一化。

报告训练与报告评测统一设 `enable_thinking=False`，固定 chat 模板前缀不计算损失，也不以空 thinking 标签作为训练目标。训练 loss 降低后，要测自由生成的报告；还需在开发集检查有旧状态和旧动作的连续序列中能否读取最新状态。报告对齐与连续规划仍有上下文差异，不能用 teacher forcing 准确率代替实际读出。

这项处理参考多模态投影器的对齐思路，而非已经存在的 Qwen 积木配方。简短规划理由只在评测时生成；若后续加入模型自生成解释或专家 CoT 监督，属于另一项训练条件，应单独比较。

首轮优化设置：AdamW，零 weight decay，cosine schedule，3% warmup，梯度裁剪 1.0，有效 batch 32，最多三轮。只比较两个学习率 `1e-3` 和 `1e-4`，T1、S1、S2、S4 各获得相同选择次数；每轮按开发集答案 NLL 保存候选，选择最小 NLL，平局取更早轮次。正式测试成功率不参与 checkpoint 或架构选择。

这是单个训练种子的工程试点，不把一次训练的差异当稳健结论。四个需要训练的条件各两个学习率，共八次短训练；每次最多 576 次参数更新。由十向量单一方案改为三个候选后，训练计划从四次增至八次，尚未启动。若要形成方法结论，需冻结配方后对全部条件补充多个训练／采样种子，无论第一轮结果正负。

默认 BF16，不引入量化变量；实现采用可访问 `inputs_embeds` 的 Transformers/PyTorch。先做一小批真实反传的显存／速度测量，再决定 microbatch 与梯度累积。冻结 8B 仍需要反向传播所需的激活，不能按“只有百万参数可训练”估算显存。软件版本、模型 revision 在实际实现时锁定，不能把未验证的版本号写成已验证环境。

## 6. 同序列逐动作推进与预算

初始 user 输入规则、目标与初始状态，使用 `enable_thinking=False` 打开 assistant 生成。每段输出一行 JSON，例如 `{"reason":"brief rationale","action":{"shape_id":0,"row":2,"col":3}}`，或 `{"reason":"brief rationale","done":true}`。理由提示为一至两句，各条件相同；其中提到的候选动作不执行，只有 action 字段确定下一步。生成在完整 JSON 行的边界暂停，不能等待整个 assistant 回合结束才插入状态。

对确定的动作作合法性验证，并用固定 V 更新当前规划状态。随后在同一 assistant 序列中追加明确的 step/state 标记及新状态：S1/S2/S4 分别追加 1/2/4 个连续向量，T0/T1 追加准确网格文字。目标保留在初始前缀中；首轮不重新发送 user 消息、不引入状态分支或回滚。新状态由程序注入，不能让模型生成占位文字冒充向量。

达到目标即记轨迹成功，并由规则裁判从初态重放选定动作验证。提前宣称 done 为失败；非法动作、破坏目标、未达目标的结束、格式错误和预算耗尽分别记录。目标判断能力另用独立探针测量。非法动作不修复，也不继续把不合法转移输入状态模块。

完整保存简短理由、动作和注入状态；它们留在当前序列中，不执行多轮模板的历史 CoT 清理。接口在评测时固定，序列只追加，因此可以复用已有前缀的 KV cache，但必须正确推进新向量的位置和 attention mask。最小实现需核对追加后的结果与同一完整前缀重算一致；尚无实现验证结果。历史消融会重新构造输入，此时需重建缓存。

采样采用 Qwen 官方非 thinking 建议：temperature 0.7、top_p 0.8、top_k 20、min_p 0；repetition_penalty 保持 1。**整局累计生成上限 16,384 tokens，包含所有段的理由和动作输出；不是每步重新发放 16k。** 每段可用上限为剩余整局预算和上下文空间中的较小者。简短理由是输出要求，不以隐藏的逐步 token 截断替代动作边界。

上下文首轮限制在原生 32,768 tokens 内，不开 YaRN；不自动截掉旧状态或目标。超出时单列 context-cap。能力探针每个独立查询同样最多 16k。16k 来自历史对照与首轮成本约束，并非论文证明充分；Qwen 官方通常建议更长输出。若开发集显示明显触顶，先给出所有条件共同增加预算的成本，再固定修订配置后测试，不能只给 S 追加预算或重采失败样本。

首轮每题一条轨迹，无 pass@8、无外部评分选解。thinking-on 仅留作后续匹配对照，不自动加入本轮训练或评测。未来多路径实验须让所有条件有同样的采样次数及评分信息，并区分“候选中存在正确解”和“最后选中正确解”。输入 token、prefill 和实际时间另报；相同生成上限不等于严格 FLOPs 匹配。

## 7. 读什么结果，下一步做什么

主指标是固定预算下的到达目标率，预先指定最简接口 S1−T0 为主比较；S2/S4−T0、各 S−T1，以及 S2/S4−S1 为补充比较。五个条件各在同一 128 个实例上运行，主测试共 640 个 episode；一个 episode 可包含多个模型调用。按实例配对，报告差值、配对 bootstrap 区间和各规模／目标分层结果。128 题只能筛查较大效应，不能承诺检测几个百分点的差异；小分组主要作描述。

完整报告三个向量数，不从测试集挑最好的一个后当作预先确定的单一结果。补充比较用于探索；后续如据此选定架构，应使用独立确认数据验证。若性能相近，优先较少向量，并结合实际成本与误差区间判断，不预设数量越多越好。

能力探针分别评估完整网格精确匹配及逐格准确率、单步转移、合法性和目标判断。稀疏网格的逐格准确率可能被全零答案抬高，必须同时给完整匹配和占据格错误。转移探针给定一个动作，不用环境向模型预先返回后果；合法性探针平衡合法／非法动作并包含空洞语义。goal 判断包括相等、仍需移除、目标格已缺失。

不要为了记录状态而要求所有主 rollout 每步再输出完整网格，这会改变规划负担。完整生成文本、确定动作与规划状态全部留档；额外强制状态报告放在独立探针。显式理由可供发现矛盾和设计后续干预，但不等同于完整内部思考或因果机制证据。

另做两项预先固定的小诊断：

1. **状态／目标干预**：使用 16 对合法、可解的小局面，八对改变当前状态，八对在同一当前状态下改变目标，正确动作应相应改变。五个条件各测两种输入，共 160 个单动作查询。动作改变本身不够，要检验改变后是否适合新状态和新目标。
2. **历史干扰**：预先从规划集均衡取 32 题，让 T0、S1、S2、S4 再运行“仅最新状态／目标、无历史状态及旧动作”的条件，共 128 个 episode。完整日志仍保留。它检验冗余历史是否妨碍当前状态使用，不单独宣称已定位某层 attention 的机制。

| 观察 | 可作出的判断与下一步 |
| --- | --- |
| 报告自由生成或连续序列读出不准 | 先处理对齐／格式／容量；当前方案尚未通过接口验证 |
| 报告很好，转移或合法性差 | 读出不等于理解动作规则；定位具体规则错误，再讨论是否加转移监督 |
| 状态、转移都好，但长程任务差 | “只训练报告即可迁移规划”的假设在此设置下受挫；不能仅靠换 memory 宣称解决 |
| S 优于 T0，但与 T1 相当 | 报告适配有效；专用状态接口的额外价值未确立 |
| S 优于 T0/T1，且干预响应正确 | 支持该任务／预算下的状态接口收益；再做种子重复和机制扩展 |
| 去历史明显改善，其他条件不变 | 优先研究历史呈现，再考虑独立 memory；不能默认 cross-attention 必然更好 |
| 准确文字状态对照已经很好 | 研究问题应转向效率、规模或有证据的困难子类；保留这个简单解释 |

不设置没有依据的“读出超过 95% 就算学懂”硬门槛。报告错误率及其对整段动作的影响直接呈现；没有正增益也完整保存。

## 8. 寻路如何衔接

首个 LLM 接口试点只做积木。抽象图先做独立地图诊断，避免把“地图没有方向性”和“LLM 不会读地图”混成一次失败。

起点采用 [GCML 官方抽象图代码](https://github.com/LH-cbicr/GCML/blob/ff76859b71a2bc2056b50f5e052475351c007f76/gcml_abstract_graph.ipynb) 的小图与完整 Q/V/W 更新规则，固定源码 revision。只训 Q/V 后直接按欧氏距离贪心是对原方法的简化，必须单列。记录探索覆盖：若每条有向边都是独立动作，未见边就涉及未训练动作参数，不能宣称那是普通的未见起终点测试。

地图训练数据不含最终评测的规划答案；同图起终点对可留作评测，但训练可以覆盖其节点和边。先比较随机合法邻居、嵌入距离贪心、原 W 选择器；BFS 只提供裁判距离和上界。使用相同可访问邻接信息和动作步数预算，记录合法到达、绕路、循环与最短距离相关的动作排序。低转移损失不能替代这些指标。

小图机制核对后再迁移到已有 path256 双向图，主要目标改为合法到达，最短性作效率指标。只有地图方向信息确有用，才讨论给 LLM 输入当前／目标／候选下一状态；文本对照应获同样候选信息。若贪心已经足够而 LLM 没有额外收益，应如实收缩 LLM 作用的主张。该阶段还没有获验证的容量和预算，不在本轮伪装成可直接运行的寻路合同。

## 9. 文献能支撑什么，不能支撑什么

| 设置 | 可参考的原始工作 | 本项目中的边界 |
| --- | --- | --- |
| 状态经 MLP 转连续输入向量，允许冻结 LLM | [PaLM-E](https://arxiv.org/html/2303.03378v1)，§3–5 | 其机器人规划训练含专家任务数据；不能作为本轮“仅报告监督就能规划”的证明 |

| “读懂状态后泛化到新任务”的动机 | [FLAN](https://arxiv.org/abs/2109.01652) | FLAN 训练了语言模型的多任务指令能力；不证明冻结模型只做状态报告对齐即可完成所有子任务 |

每状态 1/2/4 个向量是用户指定的首轮候选；对应分块方式、隐藏宽度、样本量、三轮上限和两个学习率候选属于**本项目工程选择**。处理无直接配方的方式是：给出机制理由和有限预算，只在开发集校准；冻结设计后看独立测试，失败时改变有证据的问题环节。没有查到直接验证本任务完整配方的工作，不等于已经证明文献中不存在。

## 10. 实施交付与成本边界

执行顺序：先实现非 thinking 的同序列动作／状态注入协议，运行 T0 开发集探针和预先固定的 16 个非平凡规划实例，确认该协议下还存在什么问题。再实现新增输入／训练模块，做极小数据的反传和自由生成读出检查，最后才进行配置中的报告训练和独立评测。如果准确文字状态对照已足够可靠，先解释这一结果，再决定状态接口是否仍有明确的效率或泛化问题可检验。最便宜的实现检查应覆盖：坐标／形状空洞语义、非空目标被破坏、理由中的候选不执行、LLM 权重冻结但接口有梯度、整局预算累计、状态向量追加与缓存位置一致。

这些是未来实现时针对明确风险的测试；本次没有编写占位 runner 或运行训练。候选扩展后的主测试、能力探针、两项诊断合计最多 1,568 份独立查询或 episode 槽位，其中 768 个是可能多段续写的 episode；实际计算量须由校准吞吐和每局动作数估计，不给未经测量的 GPU 小时承诺。数据集规模保持原提案，额外成本来自在同一数据上比较更多接口条件。

运行产物放忽略目录 `runs/`；保留模型与配置 revision、分割种子、准确输入、完整原始输出、token 使用、动作环境轨迹和失败类型。公开仓库只保存代码、紧凑配置和与结论有关的摘要。下一次实施应先把本设计配置接入具体 runner 并完成最小检查，再提出有硬件与时间依据的运行安排。
