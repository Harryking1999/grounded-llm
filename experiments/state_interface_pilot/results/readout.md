# 单 token 棋盘读出诊断

本页记录 previous approach 的历史实验结果。连续 token 读出训练已不再是当前路线；现行研究定义与 TODO 见[研究简述](../../../docs/RESEARCH_BRIEF.md)和[项目状态页](../../../docs/PROJECT_STATUS_AND_TODO.md)。

## 已确认结果

同一冻结 Qwen3-4B-Instruct-2507 接收 MLP 编码的一个连续 token。输入是完整 10×10 二值棋盘；
训练仅监督状态报告，没有动作标签。原合同见 [配置目录](../configs/)。

| 训练 | 自由生成完整棋盘 | 解释范围 |
| --- | ---: | --- |
| 固定八张，累计 1,000 步 | 训练原题 8/8 | 可拟合这些输入；不能说明泛化 |
| 多样 2,917 张，十轮 | 未见开发棋盘 0/356 | 尚未学会可靠的通用空间读出 |

小集每张累计呈现 1,000 次，多样训练每张呈现 10 次。训练次数与评测对象均不同，
不能由这两项准确率断言“多样性降低泛化”。小集轮换输入后原答案匹配 0/8、新输入答案匹配 8/8，
证明它确实响应输入，但仍可能仅记住有限映射。

## 多样训练学到了什么

十轮选中权重的开发集输出中，345/356 格式有效，194/356 全零；逐格匹配 27,865/35,600（78.27%），
占据格识别 5,263/9,926（召回 53.02%），预测占据格共 7,348（精确率 71.62%）。
无效输出的整板格子计错。正确占据格主要来自高覆盖率棋盘：覆盖率 76–99% 组识别 2,792/2,793 个占据格，
但预测了 3,194 个占据格；构造棋盘组则仅识别 53/1,081 个。

全零基线逐格准确率为 72.12%。更强的诊断参考是：**使用真实占据比例**，为每张棋盘在全零／全一中选准确率较高者，
可以达到 81.26%，而完全不识别空间位置。它不是可部署模型或公平预测基线；用途是说明总逐格准确率不足以证明位置读出。
当前结果与利用覆盖率的捷径相容，尚不足以确定内部机制，也不支持“一个 token 信息容量不足”的解释。

## 短程位置监督探索

从同一多样训练末次权重继续，比较完整报告与完整报告加指定行报告。两组共用保存的数据、初始权重、学习率，
匹配样本呈现数和更新数；优化器均重新初始化。行报告更短，监督 token 数与计算量不匹配。
adapter 不接收查询行号，始终编码完整棋盘。

开发集统一使用完整棋盘自由生成；另外读取训练子集，检查拟合与泛化差距。
单格翻转成对诊断要求原棋盘和翻转后棋盘的指定行都读对，以排除仅凭密度或固定答案得分。
行正确率或部分像素准确率不用于直接放行规划。

两组均已结束，选中权重完整开发棋盘均为 0/356；行探针分别正确 0/64、12/64，
要求单格翻转前后整行都正确时均为 0/32。该预算尚不足以确认收敛，不能据此比较两种方法的最终能力。
用户随后指定改成单格查询普通 CE 并重新训练；不再启动原完整报告的长程续训。
新配置 [blocks_cell.json](../configs/blocks_cell.json) 只预测 `p(bit | state token, row, col)`，
重新初始化 adapter，在全部开发棋盘全部坐标上统计结果。
`cell_smoke_84b4819/` 小批 16 次更新将 CE 从 10.455 降至 2.006，冻结梯度与状态槽标签检查通过。
2026-09-22 恢复访问后确认 `cell_84b4819/` 已训练至第 75 轮第 10 步，最后完整检查点在第 70 轮。
第 70 轮开发集 CE 0.42983，单格 28,338/35,600（79.60%），占据格 7,676/9,926、空格 20,662/25,674，
两类平均准确率 78.91%，逐格重建整板 0/356；无非 0/1 输出。
固定训练子集单格 2,574/3,200（80.44%），整板 0/32，训练 CE 与开发 CE 仍有改善，未确认收敛。
从第 70 轮检查点在 `cell_resume_84b4819/` 恢复同一训练；不重新初始化优化器，不切换监督目标。
