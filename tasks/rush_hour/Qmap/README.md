# Rush Hour Qmap

## 已确认范围与实施状态

同一个Qmap覆盖多种无墙6×6车辆布局，按整个布局／可达分量留出测试。**每题给出一张完整成功目标棋盘：A到右端，其他车辆也要到明确位置**；不同题可以使用不同目标。训练与评测均使用指定目标，不安排原出口目标的对照。一次滑动任意合法非零距离均成本1，不是逐格移动成本。

精确分量数据、状态对训练、冻结评测与任务reader入口已实现，见[正式实验](../../../experiments/new_tasks_qmap/README.md)；尚无通过验收的权重，[selection](selection.json)保持空值。现有[公开数据与精确求解](../data/README.md)、[文字和裁判](../prompts/README.md)可复用；Flash筛查不证明Qmap已能准确表示。

## 棋盘编码

编码器读取完整棋盘，必须分辨每辆车的身份及其占据格，不能把所有车辆合成一个占用通道。同一场景内每辆车的长度、方向、所在行／列固定，轴向位置随动作变化。只有空地、没有固定墙；环境仍禁止穿过其他车或出界。

按A至Z的固定通道存放6×6车辆占据图，未出现车辆通道全零；展开为936维后接共享两层隐藏MLP、128维Q。完整棋盘中的各车连通占据格已确定其存在性、长度、方向、行／列与当前位置，A所在行确定出口；无需场景ID或虚构车辆位置的目标条件。起点、目标、候选完全使用同一种物理状态编码。具体通道顺序在编码实现中固定，目前尚无该编码的已训练权重。

当前和每个合法后继各自编码。候选为所有车辆的所有合法滑动距离，数量可变，不能只取相邻一格或沿用寻路的固定候选上限。车辆可逆移动，不能旋转或横向侧移；动态位置不能从输入中省掉。

## 完整目标与距离真值

目标g保留与起点相同的车辆身份、长度、方向、行／列，每辆车的位置都已确定，A在最右端。共享编码器独立产生Q(s)、Q(g)、Q(s')，监督指定状态对的最少滑动次数。`goal_board`给出完整棋盘，提示与裁判已区分原完成规则和所有车逐项匹配；不把目标g拼入Q(s)，不聚合多个目标向量。

每个被接纳的分量完整枚举，对选定的完整成功目标分别单源BFS生成精确标签，起点与目标须在同一分量。每个场景采多个目标、不同成本起点和候选关系，并留出部分关系及目标检验；目标域暂限于A已到位的成功棋盘，不扩称所有合法中间状态目标。公开原题及分量计数先独立核对，上游参考与LLM答案不进入标签生成。

沿用[统一方法](../../QMAP_METHOD.md)的MLP、距离Huber与原权重soft-rank；可达分量内物理状态对距离对称，具体对称距离、尺度和预算在正式配置中确定。指定目标的精确成本独立标注，不能直接照搬上游到任意成功终局的标签。

## 布局留出与验收

同一静态车辆配置及其分量内所有起点整组划分；同一车辆配置的不同分量也不跨组，以便检验未见车辆布局。仅改起点、沿最短轨迹取中间状态或重命名非目标车不算新布局；去重需按车辆长度、方向、行／列及等价重命名核对。不能把改变出口方向的任意旋转视作仍满足本轮规则。

已有40个Flash起点只来自8个分量，共54,171个状态；这说明其中的精确图可处理，不等于跨布局训练池已经准备。已测试分量作为开发诊断保留；独立最终测试另留未曝光的布局。场景范围、采样和训练预算见[正式配置](../../../experiments/new_tasks_qmap/configs/rush_hour_pairs.json)，实际图规模及曝光随结果报告。

分别报告已见分量新起终点关系、目标留出、未见布局的距离误差、最优动作率、到指定目标完成率、最优完整计划、超额滑动次数和循环。先验收冻结Q贪心，再接公共MapBatch的当前、一个完整目标、全部合法真实后继；不增加多目标读取。A到位但其他车与指定目标不同仍未完成。若加入搜索、重试或环境工具须单列，不能归为地图本身能力。旧Flash结果只对应原出口目标规则，也不充当逐轮反馈条件下的匹配LLM对照。

已测8个分量分别有199、2649、29、468、827、244、45、164个物理成功终局，全部逐个送入cross-attention会改变单目标读取负担。本方案每题明确一个终局，不引入多目标接口。历史Flash原出口目标结果保留，不用作指定目标成绩。

正式验收遵循[统一合同](../../../experiments/new_tasks_qmap/configs/exact_pair_acceptance.json)：各必需组地图贪心至少80%，目标90%以上；未见端点／布局分开报告，不以易题合并分数替代。
